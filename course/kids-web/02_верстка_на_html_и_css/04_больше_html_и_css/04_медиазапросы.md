# Медиазапросы

![](https://code.s3.yandex.net/kids-web/Animated-GIF-Export_11.gif)

Если тебе {{отозвалась философия отзывчивого дизайна}}[web_04_02_отозвалась_философия_отзывчивого_дизайна] из предыдущего урока, то время поговорить о главном его инструменте — медиазапросах.

Вы с Аски уже поняли, что адаптивность помогает нам управлять HTML-блоками, подстраивая их размеры и расположение под устройства, с которых открывается сайт. Но что, если при этом, например, шрифт в элементе остаётся слишком громоздким для мобильных устройств, а на кудахтерах с очень большим монитором посетители смотрят сайт примерно так:

![](https://pictures.s3.yandex.net:443/resources/Untitled_Artwork_457_1696438140.png)

В таких случаях надо не только изменить структуру сайта, но и прописать дополнительные стили для устройств разного размера. Например, указать, что на экранах с шириной у́же, скажем, 768 пикселей (приблизительно такая у планшетов и мобильных устройств) не нужно отображать боковую панель и стоит уменьшить размер текста.

Даже нужно. Чтобы с этим работать, как раз и существуют **медиазапросы** в CSS. 

Медиазапросы — это способ задать условия, при которых определённые стили будут применяться к веб-странице в зависимости от характеристик устройства или размера экрана.

С радостью удовлетворим твой запрос на медиазапросы 🤡

Медиазапрос выглядит так:

```css
@media screen and (max-width: 768px) {
/* Новые правила */
}
```

Он состоит из трёх элементов:

**1) Тип устройства** 

Тут мы указываем, на каком устройстве отобразятся перезаданные CSS-правила: на стационарном компьютере, планшете, смартфоне, телевизоре, игровой консоли или даже электронных часах.

Доступны значения `all` (все устройства), `print` (предпросмотр печати и печать страницы), `screen` (экраны).

**2) Логический оператор**

Это просто английское слово, которое используют для комбинирования условий медиазапроса. Два основных: `and` (и), `not` (не).

**3) Условие**

Это часть правила медиазапроса, определяющая обстоятельства, в которых заданные стили должны быть применены к элементам веб-страницы: в нашем примере выше правила вступят в силу, если экран, с которого смотрят сайт, не шире `768px`

На этом этапе, возможно, не очень понятно, как в итоге работает медиазапрос, но давай мы тебе продемонстрируем это сразу после того, как расскажем, какие ещё бывают условия его работы и как с ними взаимодействуют операторы.

### Топ условий медиазапроса

[Полный список доступных условий](https://doka.guide/css/media/){target="_blank"} длинноват, поэтому приведём несколько ходовых:

- `width/max-width/min-width` 
Проверка по ширине окна (окна браузера, а не твоей квартиры, если что), в котором открыт сайт.
- `height/max-height/min-height` 
Проверка по высоте окна, в котором открыт сайт.
- `orientation` 
Проверка по соотношению сторон окна: 
`portrait` для ситуаций, когда высота окна больше ширины.
`landscape` для ситуаций, когда ширина окна больше высоты.
Этот медиазапрос может понадобиться для перезаписи стилей страницы на мобильных устройствах.
- `hover` 
Проверка устройства на возможность наведения курсора на элементы. Полезно, чтобы, например, определить устройство с сенсорным дисплеем. 
Доступные значения: `none` и `hover`
- `pointer`
Похоже на предыдущее условие, но определяет, есть ли у пользователя возможность нажимать на элементы. 
Доступные значения: `none`, `coarse` (нажатие не слишком точное, например на сенсорный экран), `fine` (нажатие точное — мышью или с помощью тачпада). Тоже может быть использовано для определения устройства с сенсорным дисплеем, например, для того, чтобы увеличить элементы, с которыми пользователь должен взаимодействовать.
- `resolution/max-resolution/min-resolution`
Проверка по плотности пикселей устройства, отображающего сайт. Значение условия нужно указывать в dpi, вот так: `min-resolution: 42dpi`
Не пугайся, dpi (то есть dots per inches*)* буквально переводится как «точки на дюйм».
- `prefers-color-scheme` 
Проверка, какая тема включена в браузере пользователя (тёмная  — `dark`, или светлая — `light`).

### Пару слов об операторах 📹

Теперь, когда ты в теме условий, посмотрим, как в коде медиазапроса работает логический оператор `and`

Он нужен для того, чтобы соблюдалось несколько условий сразу, поскольку `and` — это «**и**» (**и** такое условие, **и** такое, **и** такое).

Посмотрим ещё раз на наш медиазапрос:

```css
@media screen and (max-width: 768px) {
/* Новые правила */
}
```

В случае с нашим кодом правила применимы для экранов (`screen` — тип устройства по существу тоже условие), которые не шире 768 пикселей (`max-width: 768px` — условие 1). То есть соблюдаться должны оба этих обстоятельства.

С помощью оператора `and` создаются и более сложные медиазапросы. 

Например, можно:

- Задать промежуток, в котором должны работать перезаписанные в запросе стили👇🏻

```css
@media screen and (min-width: 450px) and (max-width: 768px) {
/* 
	Новые правила, которые будут действовать в случае, 
	если ширина окна больше 450 пикселей и меньше 768 пикселей
*/
}
```

- Объединять правила разного типа 👇🏻

```css
@media screen and (max-width: 768px) and (pointer: coarse) and (hover: none) {
/* 
	Новые правила, которые будут действовать в случае, 
	если ширина окна меньше 768 пикселей и устройство пользователя — устройство 
	с сенсорным экраном
*/
}
```

А вот оператор `not` полностью отрицает медиазапрос — прям все условия сразу. Лови пример:

```css
@media not screen and (max-width: 768px) and (pointer: coarse) and (hover: none) {
/* 
	Новые правила, которые будут действовать в случае, 
	если ширина окна не меньше 768 пикселей и устройство пользователя – 
	не устройство с сенсорным экраном
*/
}
```

### Что нужно писать в медиазапросах

В теле медиазапроса прописываются изменённые CSS-правила, которые отобразятся при соблюдении условий запроса. 

В них можно включать что угодно, но мы покажем пару популярных изменений, необходимых при адаптации сайта к отображению на смартфонах. 

Возьмём рандомную страницу:

![](https://pictures.s3.yandex.net:443/resources/Untitled_Artwork_461_1696438294.png)

```html
<!DOCTYPE html>
<html>
<head>
	<meta charset="utf-8">
	<meta name="viewport" content="width=device-width, initial-scale=1">
	<title>Медиазапросы</title>
	<style>
		.main {
			display: flex;
			flex-direction: column;
			min-height: 100vh;
			font-family: "Helvetica Neue", "Arial", sans-serif;
		}

		.main__title {
			font-size: 72px;
		}

		.cards {
			display: flex;
			flex-direction: row;
			width: 100%;
			gap: 12px;
		}

		.cards__nav {
			width: 100%;
			max-width: 240px;
			background: cornflowerblue;
			border-radius: 5px;
			list-style: circle;
			color: white;
			font-size: 24px;
		}

		.cards__content {
			display: flex;
			flex-direction: row;
			flex-wrap: wrap;
			gap: 12px;
			width: 100%;
		}

		.card {
			max-width: 382px;
			border-radius: 5px;
			background: lavender;
			width: 100%;
		}

		.card__text {
			margin: 12px;
			font-size: 24px;
		}
	</style>
</head>
<body>
	<main class="main">
		<h1 class="main__title">
			Классный сайт, вот бы он красиво отображался на всех устройствах!
		</h1>
		<section class="cards">
			<nav class="cards__nav">
				<ul class="cards__nav-list">
					<li class="cards__nav-item">Элемент 1</li>
					<li class="cards__nav-item">Элемент 2</li>
					<li class="cards__nav-item">Элемент 3</li>
				</ul>
			</nav>
			<div class="cards__content">
				<div class="card">
					<p class="card__text">Элемент 1</p>
				</div>
				<div class="card">
					<p class="card__text">Элемент 2</p>
				</div>
				<div class="card">
					<p class="card__text">Элемент 3</p>
				</div>
				<div class="card">
					<p class="card__text">Элемент 4</p>
				</div>
				<div class="card">
					<p class="card__text">Элемент 5</p>
				</div>
			</div>
		</section>
	</main>
</body>
</html>
```

Если мы посмотрим, как этот сайт выглядит на мобильных устройствах, то заметим несколько проблем. Хотя, честно сказать, текущий вид сайта на мобилке и есть одна большая проблема: текст не влезает в ширину экрана, шрифт слишком большой, да и блоки снизу смотрятся не очень.

![](https://pictures.s3.yandex.net:443/resources/Untitled_1696438369.png)

Вот тут-то мы и воспользуемся медиазапросами. 

Например, это CSS-правило определяет размер шрифта заголовка:

```css
.main__title {
	font-size: 72px;
}
```

Чтобы изменить это свойство в окне, ширина которого меньше 768 пикселей, добавляем в код следующее:

```css
@media screen and (max-width: 768px) {
	.main__title {
		font-size: 36px;
	}
}
```


![](https://pictures.s3.yandex.net:443/resources/Untitled_1696438401.png)

Так-то лучше!

Теперь предположим, что нам не нужен синий блок, когда сайт отображается на мобильных устройствах. Мы можем его скрыть. 

Допустим, этому блоку дан атрибут `class=”cards__nav”`

```css
.cards__nav {
	/* ...правила для боковой панели */
}
```

Если указать у него свойство `display: none;`, то он самовыпилится при выполнении условий медиазапроса.

```css
@media screen and (max-width: 768px) {
	.main__title {
		font-size: 36px;
	}

	.cards__nav {
		display: none;
	}
}
```


![](https://pictures.s3.yandex.net:443/resources/11Untitled_1696438471.png)

Вжух, и блок скрыт.

Согласны…

Тогда попробуем расположить его под списком элементов. Вот так:

```css
@media screen and (max-width: 768px) {
	.main__title {
		font-size: 36px;
	}

	.cards { 
		/* Класс контейнера, в котором хранятся синий блок и контейнер 
		с голубыми блоками  */
		flex-direction: column-reverse;
	}
}
```


![](https://pictures.s3.yandex.net:443/resources/Untitled_1696438565.png)

Стало лучше, но ещё есть куда стремиться: у синего блока стоит ограничение ширины. Его тоже можно снять с помощью медиазапросов.

```css
@media screen and (max-width: 768px) {
	.main__title {
		font-size: 36px;
	}

	.cards { 
		/* Класс контейнера, в котором хранятся синий блок и контейнер 
		с голубыми блоками  */
		flex-direction: column-reverse;
	}
	
	.cards__nav {
		/* 
			Значение unset снимает ограничение по ширине для этого блока. 
			Если unset используется в правилах, где свойство наследуется 
			(например, color), то оно срабатывает аналогично значению inherit. 
			Если наследования нет, то действует аналогично значению initial 
		*/
		max-width: unset;
	}
}
```


![](https://pictures.s3.yandex.net:443/resources/Untitled_1_1696438595.png)

Супер! Твои скиллы в веб-разработке подросли и теперь ты:

- Знаешь, что такое медиазапросы и из чего они состоят (тип устройства, оператор, условие).
- Разбираешься в самых ходовых условиях для медиазапросов и знаешь, какие за что отвечают (`max-width`, `min-width`, `pointer`, `hover` и так далее).
- Знаешь, как, используя операторы (`and`, `not`), объединять правила разного типа.
- Ориентируешься в размерах девайсов (мобильные, планшеты, ноутбуки, десктоп) и какими единицами они обычно измеряются (пикселями).
