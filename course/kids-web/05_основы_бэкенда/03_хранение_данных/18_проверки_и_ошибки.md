# Проверки и ошибки

![](https://pictures.s3.yandex.net:443/resources/Worn-Ass-Semi-Gloss_16_1714142391.jpg)

Давай посмотрим, что бывает, когда сервер безусловно доверяет данным клиента и отправляет их БД ровно в том виде, в каком он их получил.

Воспользуйся Postman и сделай `POST`-запрос в эндпоинт `/games` для того, чтобы создать игру со следующими данными 👇🏻

```javascript
{
  "title": "",
  "image": "https://code.s3.yandex.net/teens/pindie-games/gunner/cover.png",
  "link": "https://code.s3.yandex.net/teens/pindie-games/gunner/game/index.html",
  "description": "Продержись как можно дольше, отбиваясь от врагов, которых будет становиться всё больше.",
  "developer": "CoolDeveloper",
  "categories": "661409e16f295459a0872d85"
}
```

Обрати внимание на поле `title`: оно содержит пустую строку, то есть некорректные данные 👇🏻

{video:https://code.s3.yandex.net/kids-web/vids/M4/M4T3/11.mp4|controls:true|autoplay:0|pip:false|controlsList:nodownload}

На скринкасте видно, что в базе данных уже есть одна игра, в которой поле `title` заполнено значением `G.U.N.N.E.R.`, а карточка для неё отображается в браузере**.** При добавлении новой игры через Postman c пустым полем `title` в браузере отобразится её карточка, в которой отсутствует название.

## Проверка данных на сервере

Чтобы такого не происходило, тебе необходимо валидировать все данные на сервере, которые к нему приходят в запросах от браузера, прежде чем внести их в БД. Но для начала давай определимся, что именно ты хочешь проверить. 

1. Для `POST`-запросов к `/games` для записи данных об игре возможны:

    a. Проверка пустых значений в теле запроса.
    
    b. Проверка, существует ли уже такая игра в БД. Если ответ положительный, не нужно создавать документ в MongoDB повторно.
    
    c. Проверка, существует ли категория, к которой будет относиться игра. При создании игры мы указываем идентификатор категории, поэтому необходимо проверять, что категория с таким идентификатором есть в базе данных.
    
2. Для `PUT`-запросов к `/games` для обновления данных об игре возможны:

    a. Проверка пустых значений в теле запроса.
    
    b. Проверка количества проголосовавших за игру пользователей.
    
    c. Проверка, существует ли категория, к которой будет относиться игра.
    
3. Для `POST`-запросов к `/categories`, чтобы создать документ о категории, возможны:

    a. Проверка на пустое значение в поле имени категории.
    
    b. Проверка, существует ли уже в БД такая категория.
    
4. Для `PUT`-запросов к `/categories` для изменения данных о категории возможна:

    a. Проверка на пустое значение в поле имени категории.
    
5. Для `POST`-запросов к `/users`, чтобы создать документ о пользователе, возможны:

    a. Проверка на пустое значение в поле имени и почтового ящика пользователя.
    
    b. Проверка, существует ли в БД такой пользователь.
    
6. Для `PUT`-запросов к `/users` для изменения данных о пользователе возможна:

    a. Проверка на пустое значение в поле имени и почтового ящика пользователя.

## Проверка при создании новой игры

Итак, проверки удобнее всего делать в виде отдельных функций и подключать их следует, как и миддлвары. Для начала напиши функцию `checkEmptyFields`, в которой будешь проверять наличие всех полей в теле запроса к `/games` для создания документа о новой игре 👇🏻

```javascript
const checkEmptyFields = async (req, res, next) => {
  if (
    !req.body.title ||
    !req.body.description ||
    !req.body.image ||
    !req.body.link ||
    !req.body.developer
  ) {
    // Если какое-то из полей отсутствует, то не будем обрабатывать запрос дальше,
    // а ответим кодом 400 — данные неверны.
    res.setHeader("Content-Type", "application/json");
		res.status(400).send(JSON.stringify({ message: "Заполни все поля" }));
  } else {
    // Если всё в порядке, то передадим управление следующим миддлварам
    next();
  }
};
```

Теперь её нужно положить в `middlewares/games.js` и не забыть внести в список экспортируемых из файла функций.

Чтобы подключить `checkEmptyFields` как миддлвар, функцию нужно импортировать в `routes/games.js` и добавить в обработчик `POST`-запросов 👇🏻

```javascript
gamesRouter.post(
  "/games",
  findAllGames,
  checkEmptyFields,
  createGame,
  sendGameCreated
);
```

Это говорит о том, что в результате запроса сервер не создал новый документ в MongoDB — введённые данные были некорректны.

## Проверка при обновлении игры

Для обновления данных об игре при голосовании пользователей сервер должен слушать `PUT`-запросы по эндпоинту `"/games/:id"`

Важно учитывать, что каждая игра принадлежит к определённому жанру, поэтому должен быть выбран хотя бы один из них.

Для проверки жанров создай миддлвар-функцию `checkIfCategoriesAvaliable`, чтобы прочитать массив с категориями, приходящий в запросе `req.body.categories`. Если он отсутствует или его длина равна `0`, значит, для игры не выбран ни один жанр. В таком случае верни статус ошибки `400` с сообщением 👇🏻

```javascript
// Файл middlewares/games.js

const checkIfCategoriesAvaliable = async (req, res, next) => {
	// Проверяем наличие жанра у игры
  if (!req.body.categories || req.body.categories.length === 0) {
    res.setHeader("Content-Type", "application/json");
		res.status(400).send(JSON.stringify({ message: "Выбери хотя бы одну категорию" }));
  } else {
    next();
  }
};
```

Обработай эти два случая, используя ещё одну миддлвар-функцию `checkIfUsersAreSafe`. Достаточно сделать пару условных конструкций и посмотреть количество пользователей в теле запроса 👇🏻

```javascript
// Файл middlewares/games.js

const checkIfUsersAreSafe = async (req, res, next) => {
	// Проверим, есть ли users в теле запроса
  if (!req.body.users) {
    next();
    return;
  }
  // Cверим, на сколько изменился массив пользователей в запросе
  // с актуальным значением пользователей в объекте game
  // Если больше чем на единицу, вернём статус ошибки 400 с сообщением
  if (req.body.users.length - 1 === req.game.users.length) {
    next();
    return;
  } else {
    res.setHeader("Content-Type", "application/json");
		res.status(400).send(JSON.stringify({ message: "Нельзя удалять пользователей или добавлять больше одного пользователя" }));
  }
};
```

Таким образом, роут для обновления игры — `gamesRouter` — можно записать в виде кода 👇🏻

```javascript
// Файл routes/games.js

gamesRouter.put(
  "/games/:id", // Слушаем запросы по эндпоинту
  // Шаг 1. Находим игру по id из запроса
	findGameById,
	// Шаг 2. Выполняем проверки для корректного обновления
	checkIfUsersAreSafe,
	checkIfCategoriesAvaliable,
  checkEmptyFields,
	// Шаг 3. Обновляем запись с игрой
	updateGame,
	// Шаг 4. Возвращаем на клиент ответ с результатом обновления
	sendGameUpdated
);
```

Теперь добавь проверку при работе с категориями. В файле `middlewares/categories.js` создай функцию `checkIsCategoryExists`. Её задача — проверять при каждой попытке записать в базу новый документ с данными о категории, существует ли уже одноимённая категория. Не забудь экспортировать функцию `checkIsCategoryExists` 👇🏻

```javascript
const findAllCategories = async (req, res, next) => {
  console.log("GET /categories");
  req.categoriesArray = await categories.find({});
  next();
};

const checkIsCategoryExists = async (req, res, next) => {
  // Среди существующих в базе категорий пытаемся найти категорию с тем же именем,
  // с которым хотим создать новую категорию
  const isInArray = req.categoriesArray.find((category) => {
    return req.body.name === category.name;
  });
  // Если нашли совпадение, то отвечаем кодом 400 и сообщением
  if (isInArray) {
    res.setHeader("Content-Type", "application/json");
		res.status(400).send(JSON.stringify({ message: "Категория с таким названием уже существует" }));
  } else {
  // Если категория, которую хотим создать, действительно новая, то передаём управление дальше
    next();
  }
};
```

Миддлвар `findAllCategories` тебе уже знаком, внутри него происходит получение всех категорий из базы и сохранение их в `req.categoriesArray`, который дальше используется в `checkIsCategoryExists`

Подключи в файле `routes/categories.js` 👇🏻

```javascript
categoriesRouter.post(
  "/categories",
  findAllCategories,
  checkIsCategoryExists,
  createCategory,
  sendCategoryCreated
);
```

## Проверка данных на фронтенде

Мы рассмотрели способ проверки данных на сервере. На фронтенде можно изначально предотвратить отправку запроса на сервер, проверив, какие именно данные собираются отправить. 

{quiz-task}
    background: |
        #f1f1ef
    content: |
        ❗ Такая стратегия называется валидацией пользовательского ввода, она позволяет сильно снизить нагрузку на сервер, отсекая часть заведомо неуспешных запросов, например запросы с пустыми данными об игре.
{/quiz-task}

При этом есть ошибки от сервера, которые невозможно предугадать в браузере, — например, повторное создание одной и той же игры. Фронтенд не должен проверять, существует уже такая игра в базе на сервере или нет, этим должен заниматься сервер. Тем не менее фронтенд должен правильно реагировать на ошибки, которые может вернуть сервер в ответе, и показывать соответствующее сообщение, чтобы пользователь понимал, что не так.

{video:https://code.s3.yandex.net/kids-web/vids/M4/M4T3/33.mp4|controls:true|autoplay:0|pip:false|controlsList:nodownload}

В скринкасте мы попробовали создать игру с пустым названием и игру, данные о которой уже существуют в базе данных. Как видишь, в обоих случаях пользователю отражается корректное сообщение об ошибке.

## Самостоятельная работа 📝

Выше, в разделе «Проверка данных на сервере», для каждого эндпоинта мы привели список проверок, которые необходимо сделать, прежде чем выполнять какие-либо действия с базой данных. Также в качестве примера реализовали несколько миддлваров:  `checkEmptyFields`, `checkIfUsersAreSafe`, `checkIfCategoriesAvaliable` и `checkIsCategoryExists`

По аналогии с ними реализуй в виде миддлваров все остальные проверки:

- При создании новой игры необходима проверка, существует ли уже такая игра в БД (`checkIsGameExists`)
- При создании и обновлении категории нужно проверить наличие поля name (`checkEmptyName`)
- При создании пользователей нужно проверить, что имя пользователя, email и пароль не пустые (`checkEmptyNameAndEmailAndPassword`)
- При обновлении пользователя из админки нужна проверка только на наличие имени пользователя и email (`checkEmptyNameAndEmail`)

Не забывай экспортировать эти проверки, импортировать их и подключать к роутам. А если вдруг не получается, переходи в следующий урок, там найдёшь готовый код.
