Чтение документов

{quiz-task} background: | #f1f1ef content: | ❗ Обрати внимание, метод Read не новинка в проекте, ведь мы использовали его при демонстрации. В твоём игровом миддлваре уже есть функция `findAllGames`, которая ищет и считывает все игры в БД из коллекции `games` {/quiz-task}

Рассмотрим упомянутую функцию `findAllGames` 👇🏻

const findAllGames = async (req, res, next) => {
  req.gamesArray = await games.find({})
  next();
};

В качестве аргументов миддлвар принимает объект запроса `req`, объект ответа `res`, а также метод `next`, чтобы передать запрос следующему миддлвару.

Миддлвар обращается к объекту запроса и создаёт в нём новое поле `gamesArray`. Самому же полю присваивается результат работы функции, которая обращается к коллекции `games` через библиотеку Mongoose. Используя метод `find`, функция ищет и читает все документы этой коллекции. Сам процесс обращения к базе данных происходит асинхронно, поэтому в миддлваре используются ключевые слова `async` и `await`. После вызывается метод `next()`, который передаёт управление следующему миддлвару.

В результате в поле `gamesArray` записывается массив с данными игр в формате JSON, с которым можно удобно работать.

Способы чтения

- Метод `find`, который мы уже юзали раньше, позволяет найти и прочитать **все** документы из нужной коллекции 👇🏻

    games.find({}) // Вернёт массив документов

Обрати внимание на фигурные скобки внутри вызова — именно они указывают на необходимость поиска **всех** документов коллекции.

Также можно передать **определённое условие** внутри скобок, тогда метод вернёт все документы, которые **соответствуют критерию отбора** 👇🏻

    games.find({условие})

К примеру, в качестве условия можно указать значение определённого поля 👇🏻

    games.find({developer: "niclan"}) // Вернёт все игры этого разработчика

- Метод `findById` позволяет найти определённый документ по его уникальному идентификатору 👇🏻

    games.findById(идентификатор) // Вернёт один документ или «null», если его нет

- Метод `findOne` позволяет найти первый документ, удовлетворяющий заданному условию. Работает так же, как и обычный `find` с условием, но в ответ отдаёт не список, а только первый документ 👇🏻

    games.findOne({условие})

Лови пример 👇🏻

    games.findOne({developer: "niclan"}) // Вернёт первую игру этого разработчика

Считываем игру по `id`

Для начала давай создадим функцию поиска игры по её идентификатору.

Для этого перейди в файл игрового миддлвара, расположенного по пути `middlewares/games.js`, и добавь новую функцию `findGameById` 👇🏻

const findGameById = async (req, res, next) => {};

Она принимает уже знакомые тебе аргументы и является асинхронной, так как внутри себя ей необходимо отправить запрос к базе данных.

Напомним, метод `findById` может вернуть `null`, если документа с таким идентификатором в коллекции не существует, поэтому воспользуйся конструкцией `try…catch` для обработки ошибок 👇🏻

const findGameById = async (req, res, next) => {
	try {
	} catch (error) {
	  res.setHeader("Content-Type", "application/json");
		res.status(404).send(JSON.stringify({ message: "Игра не найдена" }));
	}
};

В блоке `catch` в случае возникновения ошибки обратись к объекту ответа `res` и установи статус `404`. Также в самом ответе отправь сообщение с явным указанием ошибки `Game not found` — игра не найдена.

В блоке `try` создай новое поле `game` в объекте запроса `req` и присвой ему результат работы функции, как это было в миддлваре `findAllGames` 👇🏻

const findGameById = async (req, res, next) => {
	try {
		req.game = await games.findById(req.params.id);
    next();
	} catch (error) {
		res.setHeader("Content-Type", "application/json");
		res.status(404).send(JSON.stringify({ message: "Игра не найдена" }));
	}
};

В самой функции обратись к коллекции `games` и вызови метод `findById`, записав в качестве аргумента идентификатор — он будет передаваться клиентом в объекте параметров запроса в поле `id`. И последний шаг: вызови метод `next()`, чтобы передать управление запросом следующему миддлвару.

Заполняем пробелы

Вместо того чтобы копировать всю информацию о категориях в документ игры, сохрани только идентификатор в поле `categories`. Это позволит тебе создавать связь между игрой и её категориями, используя ссылки на документы категорий 👇🏻

{
	// ...другие поля документа игры
	categories: [
		{
			"$oid": "661acbf240533bf11b84fdc7" // Ссылка на категорию 1
		},
		{
			"$oid": "661acbf240533bf11b84fbc6" // Ссылка на категорию 2
		}
	]
}

Используя метод `find` для поиска и чтения документов из коллекции, мы получаем данные **поверхностно**, то есть категории так и остаются ссылками на документы категорий.

Используя метод `populate`, выполни запрос на получение документа игры — её категории будут содержать полную информацию 👇🏻

{
	// ...другие поля документа игры
	categories: [
		{
			"_id": {
		    "$oid": "661acbf240533bf11b84fdc7"
		  },
			"name": "shooter",
		},
		{
			"_id": {
		    "$oid": "661acbf240533bf11b84fbc6"
		  },
			"name": "new",
		}
	]
}

Заметь, что `populate` уже использовался в игровом миддлваре в функции `findAllGames` 👇🏻

const findAllGames = async (req, res, next) => {
  console.log("GET /games");
  req.gamesArray = await games
    .find({})
    .populate("categories")
    .populate("users");
  next();
};

{quiz-task} background: | #f1f1ef content: | ❗ Метод `populate` принимает в качестве аргумента название поля, в котором содержатся ссылки на другие документы. Благодаря этому база данных обращается к соответствующим документам и подтягивает все необходимые данные в документы игр. {/quiz-task}

К примеру, в поле `categories` хранятся ссылки на категории игр и мы используем метод `populate` для того, чтобы получить полную информацию о каждой категории. Аналогично в поле `users` собираются идентификаторы пользователей, проголосовавших за игру, и мы снова используем метод `populate`, чтобы получить данные о каждом пользователе. Это позволяет нам создать полное представление о каждой игре, включая её категорию и голоса пользователей.

Но и этого можно избежать. Просто более детально пропиши параметры в методе `populate`. Попробуй на примере функции `findAllGames` 👇🏻

const findAllGames = async (req, res, next) => {
  console.log("GET /games");
  req.gamesArray = await games
    .find({})
    .populate("categories")
    .populate({
		  path: "users",
		  select: "-password"
		});
  next();
};

В метод `populate` передай аргумент в виде объекта с параметрами. В `path` укажи поле, которое необходимо заполнить данными из других документов, — в твоём случае это `users`. Затем в `select` укажи опцию, которая скажет методу, какие поля пользователя нужно исключить из заполнения. Здесь `-password` означает, что мы хотим исключить поле `password` из данных пользователя.

Самостоятельная работа 📝

Теперь попробуй самостоятельно добавить метод `populate` в функцию получения игры по её идентификатору. Для этого в `findGameById` после метода `findById` дважды вызови метод `populate` 👇🏻

- В первом вызове передай аргументом строку с названием поля, где хранятся идентификаторы категорий. - Во втором вызове передай аргументом объект с названием поля, где хранятся идентификаторы пользователей, а также укажи, что поле с паролем заполнять в запросе не нужно.

Улучшаем проект

Для начала поработай с игровым контроллером и создай функцию `sendGameById`, которая будет отправлять на клиент игру по её идентификатору. Для этого в файле `games.js` в папке `controllers` добавь функцию и передай аргументами объект запроса и объект ответа 👇🏻

const sendGameById = (req, res) => {};

Внутри функции установи заголовок с типом контента, а затем заверши запрос, отправив в ответе данные игры, преобразованные в строку формата JSON 👇🏻

const sendGameById = (req, res) => {
  res.setHeader("Content-Type", "application/json");
  res.end(JSON.stringify(req.game));
};

Здесь ты передаёшь на клиент данные из поля `game`. Мы создали его в игровом миддлваре в функции `findGameById`, выполняя запрос к базе данных.

Переходим к игровом роуту `games.js` в папке `routes`. Здесь создай новый маршрут, по которому можно будет получить игру, указав определённый идентификатор 👇🏻

gamesRouter.get("/games/:id");

После того как прописали путь, следующими аргументами должны быть функции, которые обработают твой запрос. Укажи вторым аргументом новую функцию `findGameById` из игрового миддлвара, а затем и функцию `sendGameById` из игрового контроллера 👇🏻

gamesRouter.get("/games/:id", findGameById, sendGameById);

Суммируя: сервер, получая запрос по адресу `/games/:id`, где `:id` — это уникальный идентификатор игры, передаст запрос функции `findGameById`. Она в свою очередь обратится к базе данных, найдёт и прочитает нужную игру, а затем передаст функции `sendGameById`, которая отправит её данные обратно на клиент.
