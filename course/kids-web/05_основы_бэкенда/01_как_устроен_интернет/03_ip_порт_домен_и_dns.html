IP-адрес

Сервер легко можно сравнить с квартирой — такая коробка с кучей модулей типа кухни, спальни и кабинета. У сервера, как и у квартиры, есть уникальный адрес, с помощью которого его можно найти на просторах интернета, — **IP-адрес.** Его предоставляют провайдеры, когда подключают компьютер к интернету.

IP-адреса работают по протоколу **IPv4** (Internet Protocol version 4), который устанавливает правила, как адрес для сервера должен выглядеть. Согласно этому протоколу адрес может состоять из 4 {{байт}}[web_teens_theme1_lesson_3_байт]. Обычно он записывается в виде четырёх чисел, каждое из которых может принимать значения от 0 до 255, разделённых точками, например `77.88.55.242`

Чтобы современный интернет продолжал работать, придумали хитрость: на одном IP-адресе может лежать несколько сайтов, которые различаются по именам, поэтому найти нужный сайт не составляет труда.

Правда, эта хитрость не решает основную проблему, а иногда даже добавляет новые. Например, при блокировке определённых ресурсов часто используется блокировка по IP-адресу, поэтому в результате под блокировку может попасть множество других сайтов, которым не повезло делить один адрес с неугодным ресурсом.

Таким образом, твой сервер может быть найден в интернете, вычислен по IP, но попасть на него не так уж просто.

Чтобы другие пользователи интернета могли быстро и удобно находить нужные им страницы и сервера, были придуманы доменные имена. Это просто набор слов, который легко запоминается и читается человеком, например `practicum.yandex.ru`

Таким образом, IP-адрес сервера больше не является сложной и громоздкой комбинацией цифр, которую нужно запоминать.

![](https://pictures.s3.yandex.net:443/resources/Frame_1597_1_1710946235.png)

Доменные имена работают по принципу телефонной книги. Когда нужно кому-то позвонить, нет необходимости запоминать номер телефона, достаточно один раз внести его в список контактов и присвоить имя.

![](https://pictures.s3.yandex.net:443/resources/Frame_1612_1710946283.png)

{quiz-task} background: | #f1f1ef content: | ❗ В настоящее время происходит постепенный переход на **протокол IPv6,** имеющий одно из главных преимуществ — длину адреса, которая состоит не из четырёх байт, а из 16. Адрес выглядит следующим образом: `2001:0db8:85a3:0000:0000:8a2e:0370:7334`. Это позволяет обеспечить каждому ресурсу уникальный IP-адрес и предоставить достаточный запас уникальных адресов на долгие годы вперёд. {/quiz-task}

**Порт**

Разные пользователи интернета, зная твой уникальный IP-адрес, могут прийти к твоему серверу с запросом.

Да! Существует несколько разновидностей запросов, и каждый описывается определёнными правилами — протоколами. По этим правилам можно заранее понять, как нужно реагировать на запросы.

В твой сервер могут постучаться с запросами, используя протокол **HTTP** — это небезопасный способ взаимодействия, таким запросам доверять нельзя, будет достаточно отдать простой ответ (простую вёрстку) или вовсе отказать в доступе. Запросы по протоколу **HTTPS** подразумевают взаимодействие «запрос — ответ», ты в сервере самостоятельно решаешь, что отвечать на такие запросы👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1600_1710946355.png)

Есть ещё протокол **SSH** — набор правил для запросов с взаимодействием. По таким запросам мы можем пустить гостя в свой сервер и даже позволить чувствовать себя как дома — двигать мебель, читать книги и устроить бардак в шкафу.

**Порт** — это номер, который используется для определения конкретного приложения или службы, прослушивающих входящие сетевые запросы. Каждый порт связан с определённым протоколом и службой. Например, порт 80 используется для HTTP, порт 443 — для HTTPS, а порт 22 — для SSH.

Для 443-го порта (HTTPS) будем обмениваться данными `GET`/`POST`/`PUT`/`DELETE`, а если придёт запрос на порт 22 (SSH), сервер будет знать, что нужно дать доступ к файловой системе.

Залог правильной коммуникации — заранее настроить процесс и утвердить все правила.

**Домен (Domain) и** DNS

С IP-адресом и портом более или менее понятно, теперь ты точно можешь найти нужный сервер на просторах интернета и обратиться к нему с определённой задачей. Все запросы в сети происходят по протоколам и IP-адресам.

Для простоты взаимодействия людей с сетевой инфраструктурой были придуманы **доменные имена.** Пользователи могут ввести доменное имя `https://practicum.yandex.ru` вместо `87.250.250.5:443` и получить доступ к сайту Яндекс Практикума. Как мы говорили ранее, доменное имя — удобное название для адреса сайта. И эта связка имени и настоящего адреса сайта работает по принципу телефонного справочника.

Много лет назад всё началось с обычного файла, где хранился список сайтов: их доменные имена и адреса. Но этот список быстро разрастался, возникали конфликты имён, и пользоваться таким списком становилось проблематично. В 1983 году придумали систему доменных имён, или **Domain Name System** (DNS).

Доменное имя всегда состоит из нескольких частей. Разберём на примере Яндекс Практикума: `practicum.yandex.ru` 👇🏻

- `ru` — домен верхнего (первого) уровня, или **зона.** Владелец такой зоны может выдавать новые доменные имена и продавать их, например, для `pindie.ru` - `yandex` — домен второго уровня. Владелец этого домена может выпускать новые доменные имена третьего уровня: `market.yandex.ru`, `music.yandex.ru` и другие. - `practicum` — домен третьего уровня.

Адресов в сети очень много, хранить их в одной базе нецелесообразно, поэтому придумали распределённую систему.

![](https://pictures.s3.yandex.net:443/resources/Frame_1599_1710946463.png)

Корневая зона хранит данные обо всех доменах верхнего уровня — `ru`, `com`, `net` и так далее. Зона `ru` содержит данные о доменах второго уровня, а, например, домен `yandex` содержит адреса поддоменов.

Получается, чтобы найти нужный сервис `practicum.yandex.ru`, необходимо было бы опросить различные сервера по всей иерархии доменных имён для поиска конечного сервера Практикума. Но вместо этого браузер просто стучится к серверу, который располагается ближе всего — обычно это сервер провайдера (кто оказывает услуги доступа в интернет). Такой сервер называют локальным DNS-сервером. Он делает всю работу по поиску нужного сервера, а затем сохраняет на определённое время результат, на случай повторного запроса.

![](https://pictures.s3.yandex.net:443/resources/Frame_1601_1710946508.png)

Короче, DNS — это не только список доменов, но и адреса серверов. В нём скрыто множество дополнительных настроек и расширений. Можно улучшить скорость доступа к своему сайту или ограничить его, настроить доступ только с определённых IP-адресов или перенаправлять на другие ресурсы и сервера. Также один IP-адрес может использоваться для сайтов по HTTP-протоколу и для клиентов почты по протоколу для работы с имейлом.
