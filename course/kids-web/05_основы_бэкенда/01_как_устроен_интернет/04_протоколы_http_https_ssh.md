# Протоколы: http, https, ssh

![](https://pictures.s3.yandex.net:443/resources/IMG_4853_1710946767.jpg)

С протоколами `http` и `https` мы уже сталкивались: они используются для обмена данными между сервером и браузером. Запрос отправляется серверу, он его обрабатывает и возвращает ответ.

Ок! 

Возьмём **{{http}}[web_teens_theme1_lesson_4_http]** — это основной протокол для передачи данных в интернете. Когда клиент отправляет запрос, открывается **{{соединение}}[web_teens_theme1_lesson_4_tcp]** с сервером, через которое проходят все запросы и ответы клиента и сервера. Когда соединение клиента и сервера открыто, HTTP-запрос отправляется от клиента на сервер. Сервер его обрабатывает, возвращает ответ и… всё. Соединение клиента и сервера разрывается. Этих действий хватает для большинства сайтов. 

Например, каждый раз, когда ты заходишь на сайт, браузер отправляет несколько HTTP-запросов (они состоят из адреса, заголовков, метода и, возможно, тела запроса), а в ответ получает запрошенные данные (HTML/CSS/JS-файлы, шрифты и так далее). 

Напоминаем, что посмотреть на запросы, которые отправляет браузер, можно во вкладке Network инструментов разработчика.

{video:https://code.s3.yandex.net/kids-web/vids/Untitled_Artwork_28.mp4}

Мы уже внедряли HTTP-запросы к серверу в проектах этого курса (правда, там было о HTTP-запросах с точки зрения фронтенда — смотри урок «Как писать запросы серверу»). Например, в Pindie мы писали запросы к серверу по адресу [https://api-code-2.practicum-team.ru](https://api-code-2.practicum-team.ru){target="_blank"}. На этом сервере была программа, которая получала твой запрос, обрабатывала его и возвращала ответ.

На сервере хранится объект `{message: "Привет!", sender: "Аски"}`. Если попробовать обновить значение `message` через `PUT`-запрос `{message: "Ну здравствуй!"}`, то значение `sender` исчезнет. В случае с `PATCH`-запросом этого не произойдёт и получится объект `{message: "Ну здравствуй!", sender: "Аски"}`

Перейдём к следующему протоколу. Протокол `https` (сокращение от **HTTP Secure** — защищённый HTTP) работает по такому же принципу, как `http`. По сути, это тот же HTTP-протокол, но передаваемые между сервером и клиентом данные шифруются. Таким образом, злоумышленники не смогут их перехватить и прочитать. Чтобы расшифровать данные, браузер проверяет **сертификат безопасности**, в котором содержатся сведения о владельце сайта. Браузеры обычно предупреждают, если сайт использует незащищённый протокол `http`. Например, вот так это выглядит в Яндексе 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1622_1710947484.png)

Если у сайта всё в порядке с сертификатами безопасности, то таких предупреждений не возникает 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1623_1710947498.png)

Настройка `https` связана с доменом сайта, и для неё нужно выпускать сертификаты безопасности — мы расскажем, как это сделать, но чуть позже.

Протокол `ssh` (**Secure Shell** — «безопасная оболочка») используется для шифруемого удалённого подключения к другому компьютеру (серверу). Подключившись к серверу с помощью `ssh`, ты сможешь управлять им через команды в терминале.

Вот так выглядит интерфейс терминала при подключении к серверу 👇🏻

{video:https://code.s3.yandex.net/kids-web/vids/example-terminal.mp4|controls:true|autoplay:0|pip:false|controlsList:nodownload}

В этом видео показаны примеры, как можно посмотреть содержимое папки (команда `ls`), создать новую папку (`mkdir <путь к папке>`), перейти в другую папку (`cd <путь к папке>`), создать и открыть текстовый файл (`nano <название файла>`). Об этих командах мы уже рассказывали тебе, а если нужно освежить в памяти, залетай на урок «Командная строка (урок со звёздочкой)».  

HTTP/HTTPS и SSH — не единственные существующие виды протоколов: бывают протоколы для самых разных целей. Например, протокол для отправки и получения электронной почты (SMTP), для обмена данными через постоянное соединение клиента и сервера (WebSocket) и прочие. Для создания веб-сервиса нам понадобятся протоколы `http`/`https` и `ssh`
