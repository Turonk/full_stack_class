# Доступ к серверу по SSH

![](https://pictures.s3.yandex.net/resources/Worn-Ass-Semi-Gloss_30_1715276188.jpg)

Мы уже рассказывали, что SSH — это способ пустить на удалённый компьютер юзера и дать ему возможность делать там что угодно: создавать файлы и папки, устанавливать программы, запускать код.

Чтобы компьютеры узнавали друг друга при подключении, используют специальные ключи. Тебе действительно уже знакома эта технология, когда для работы с репозиториями GitHub с компьютера на компе создавался ключ, а на сайте гитхаба мы его сохраняли в специальной форме. Так гитхаб узнавал, что это именно твой комп хочет что-то скачать или отправить. 

Вот с сервером в облаке то же самое: на компе нужен ключ, и на сервере нужен ключ, а если они совпадают, сервер допустит твой комп к управлению.

![](https://pictures.s3.yandex.net/resources/1_3_1715276253.jpg)

Ниже, под тогглом, собрали инструкцию о том, как раньше проводилась настройка твоего локального компьютера и GitHub по протоколу `ssh` (подробнее можешь глянуть в уроке **«Git через терминал»**) 👀

Для начала генерировали ключи — действия отличались в зависимости от операционной системы. Лови инструкции 👇🏻

Введи команду, заменив `email@example.ru` на свой email, используемый в GitHub 👇🏻

```bash
ssh-keygen -t ed25519 -C "email@example.ru"
```

Система спросит, где сохранить ключ, нажми `Enter`, чтобы использовать предложенное по умолчанию расположение. Также при создании ключа система предложит ввести парольную фразу — этот вопрос можно пропустить, нажав `Enter`

После этого необходимо добавить ключ в спецслужбу `ssh-agent`. Запусти её следующей командой 👇🏻

```bash
eval "$(ssh-agent -s)"
```

Добавь свой SSH-ключ в службу `ssh-agent` командой 👇🏻

```bash
ssh-add ~/.ssh/id_ed25519
```

```bash
ssh-keygen -t rsa
```

После добавления необходимо было скопировать содержимое ключа в буфер обмена 👇🏻

```bash
clip < ~/.ssh/id_ed25519.pub
```

```bash
pbcopy < ~/.ssh/id_rsa.pub
```

Потом переходили в собственный профиль на GitHub и в правом боковом меню выбирали раздел `Settings`. В самом разделе — пункт `SSH and GPG keys`. Затем нажимали зелёную кнопку `New SSH key` 👇🏻

![](https://pictures.s3.yandex.net/resources/Frame_1695_1715276508.png)

В появившейся форме добавления ключа в поле `Title` вводили название устройства, с которого добавляли ключ, к примеру `My Laptop`. В поле `Key` вставляли содержимое ключа, которое автоматически скопировалось после команды выше. Должно было получиться вот так 👇🏻

![](https://pictures.s3.yandex.net/resources/Frame_1696_1715276684.png)

Наконец, нажимали кнопку `Add SSH key`, после которой можно было увидеть новый ключ в списке.

        ❗ От наставника своей группы ты получишь личный ключ от сервера и адрес сервера для подключения.

Приватный ключ сохраняется на стороне пользователя, то есть у тебя на компьютере, и не должен быть доступен кому-то ещё. Его утечка позволит злоумышленнику войти на сервер и выполнить действия от имени владельца ключа, поэтому не отправляй такие ключи кому попало.

Приватный ключ выглядит так 👇🏻

```bash
----BEGIN OPENSSH PRIVATE KEY-----
xxxx
-----END OPENSSH PRIVATE KEY-----
```

Он состоит из разделителей, которые помечают начало и конец ключа, и ключа шифрования между ними. Опробуем его в деле:

- Подключимся к серверу с собственным ключом.
- Добавим туда ключ наставника, чтобы он смог прийти на помощь.
- Свяжем твой аккаунт на GitHub с удалённым сервером.

## Подключаемся к серверу за четыре шага

### Шаг 1

Положи ключ от сервера в папку `.ssh` к себе на компьютер. Она изначально скрыта и находится в папке пользователя.

        на Windows — смотри [инструкцию](https://hi-tech.mail.ru/news/47521-kak-pokazat-skrytye-papki/){target="_blank"}

Должно получиться вот так 👇🏻

![](https://pictures.s3.yandex.net/resources/2_2_1715276784.jpg)

Теперь открой её и скопируй в неё файл с ключом. Файл назови таким образом, чтобы было понятно, чей ключ и для чего: например, `student_key`. Дальше нам понадобится обращаться к файлу с ключом командами через терминал.

### Шаг 2

Открой терминал на macOS или GitBash на Windows 👇🏻

![](https://pictures.s3.yandex.net/resources/3_1_1715276831.jpg)

Введи команду `cd ~/.ssh`. Она позволит попасть в скрытую папку для хранения ключей 👇🏻

![](https://pictures.s3.yandex.net/resources/4_1715276845.jpg)

### Шаг 3

Настрой права доступа для файла с ключом. Для этого введи команду `chmod 0600 ./student_key` 👇🏻

![](https://pictures.s3.yandex.net/resources/5_1715276900.jpg)

Благодаря ей теперь только владелец файла имеет полный доступ к нему для чтения и записи.

### Шаг 4

Подключись по протоколу SSH к удалённому серверу. Для этого укажи адрес сервера — `158.160.137.249` (подставь свой адрес из цифр — IP-адрес виртуальной машины) и ключ для доступа.

Введи команду `ssh student@158.160.137.249 -i ./student_key`

При первом подключении появится вопрос с дополнительным подтверждением подключения 👇🏻

Достаточно ввести `yes` и нажать кнопку `Enter`

## Настраиваем работу сервера с GitHub за четыре шага

На первом этапе мы настраивали работу твоего персонального компьютера и GitHub для работы по протоколу `ssh`. Так как сервер — это другая машина, нам нужно таким же образом подружить сервер с гитхабом. Все команды, написанные ниже, тебе нужно выполнять уже на удалённой машине, подключившись к ней по SSH.

### Шаг 1. Генерация SSH-ключа

Для начала нужно сгенерировать для сервера пару ключей командой 👇🏻

```bash
ssh-keygen -t rsa
```

В процессе создания ключей будет несколько вопросов:

1. `Enter file in which to save the key` — куда сохранять сгенерированные ключи. Достаточно нажать `Enter`, чтобы они сохранились в папке по умолчанию по адресу `/home/student/.ssh/id_rsa`
2. `Enter passphrase` — введи пароль (секретную фразу). 
Этот шаг можно пропустить, нажав кнопку `Enter`
3. `Enter same passphrase again` — введи пароль (секретную фразу) повторно. 
Также пропускаем этот шаг, нажав `Enter`

Далее ты увидишь сообщение об успешном создании и сохранении ключей по адресу `/home/student/.ssh/...` 👇🏻

![](https://pictures.s3.yandex.net/resources/8_1715277049.jpg)

Выведи теперь в терминал созданный публичный ключ командой 👇🏻

```javascript
cat ~/.ssh/id_rsa.pub
```

Теперь скопируй ключ, чтобы добавить к себе в GitHub-аккаунт 👇🏻

![](https://pictures.s3.yandex.net/resources/9_1715277068.jpg)

### Шаг 2. Добавление SSH-переключения в аккаунт GitHub

Перейди в свой профиль на гитхабе и в правом боковом меню выбери раздел `Settings`. В самом разделе выбери пункт `SSH and GPG keys`. Затем нажми зелёную кнопку `New SSH key` 👇🏻

![](https://pictures.s3.yandex.net/resources/10_1715277099.jpg)

В появившейся форме добавления ключа в поле `Title` введи название устройства, с которого ты добавляешь ключ, к примеру `server`. В поле `Key` вставь содержимое ключа, который копировали из терминала. Должно получиться вот так 👇🏻

![](https://pictures.s3.yandex.net/resources/11_1715277115.jpg)

Наконец, нажми кнопку `Add SSH key`, после которой ты увидишь новый ключ в списке.

### Шаг 3. Настройка SSH-агента

Для упрощения процесса аутентификации можно настроить SSH-агента, который будет хранить твои SSH-ключи и автоматически предоставлять их при необходимости.

Для этого введи команды 👇🏻

```
eval "$(ssh-agent -s)"
ssh-add
```

Получится вот так 👇🏻

![](https://pictures.s3.yandex.net/resources/12_1715277152.jpg)

Команда `eval` выполняет вывод команды `ssh-agent -s`, которая создаёт экземпляр SSH-агента. Затем `ssh-add` добавит приватный ключ (`id_rsa`) в список ключей команды, управляемой агентом. Эти шаги обеспечат автоматическую аутентификацию по SSH без необходимости вводить пароль каждый раз.

### Шаг 4. Подключение к GitHub

После настройки SSH-агента можешь подключиться к своему репозиторию на GitHub без ввода пароля. Лови пример команды для подключения к GitHub 👇🏻

```
ssh -T <имя твоего аккаунта>@github.com
```
