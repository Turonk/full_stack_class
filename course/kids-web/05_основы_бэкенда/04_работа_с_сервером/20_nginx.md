# Nginx

Можно попробовать исправить проблему, изменив порт в коде приложения 👇🏻

```javascript
app.listen(80);
```

Если сделать это и запустить приложение на сервере в облаке, получишь ошибку 👇🏻

```bash
Error: listen EACCES 0.0.0.0:80
```

Дело в том, что Node.js по умолчанию не может взаимодействовать с портами ниже `1024`. И это даже не столько ограничение ноды, сколько ограничение операционной системы Ubuntu, установленной на виртуальной машине, которое не разрешает процессу, запущенному без прав суперпользователя, взаимодействовать с такими портами. 

То есть ошибку можно исправить, только если запустить приложение с правами суперпользователя. Для этого, как помнишь, нужно добавить команду `sudo` 👇🏻

```bash
sudo node app.js
```

А если Node.js-приложение будет работать под обычным пользователем и злоумышленник как-то запустит в нём свой код, у него будет много системных ограничений. Он уже не сможет делать с машиной всё что пожелает.

## Что это такое

**Nginx** — это HTTP-сервер. Он умеет раздавать статические файлы, перенаправлять запросы, кешировать результат — и делает всё это очень быстро.

Поэтому они и работают в связке 👇🏻

- Если нужно отдать статический файл или перенаправить запрос куда-то, лучше поручить это Nginx.
- Если нужно исполнить какую-то логику, это сделает Node.js.

Да, например, когда на сервер приходит запрос на получение картинки, Nginx ищет её на сервере и, когда находит, отправляет клиенту. А когда приходит запрос, который должно обработать Node.js-приложение, Nginx перенаправляет этот запрос на порт, где запущено это приложение.

## Установка и запуск

Для начала зайди на удалённый сервер, затем установи Nginx двумя командами 👇🏻

```bash
sudo apt update # Обновляем список пакетов (программ), доступных для установки
sudo apt install -y nginx # Устанавливаем Nginx
```

После установки нужно настроить **файрвол** — прослойку между сервером и внешним миром, которая решает, какие запросы пускать дальше, а какие отклонять.

В операционной системе Ubuntu по умолчанию установлен файрвол — `ufw`

Сконфигурируй его, разрешив некоторые виды трафика. Для этого используй команды 👇🏻

```bash
sudo ufw allow 'Nginx Full'
sudo ufw allow OpenSSH
```

Здесь `sudo ufw allow 'Nginx Full'` открывает на текущей машине два порта: `80` и `443`, на них приходят `http`- и {{`https`}}[web_teens_theme4_lesson_8_«`https`»]-запросы к серверу. `OpenSSH` открывает порт `22` — соединение по `ssh`, чтобы можно было подключаться к серверу через консоль и при работающем файрволе.

После включи файрвол 👇🏻

```bash
sudo ufw enable
```

Система здесь может задать тебе дополнительный вопрос. На него нужно ответить текстом `yes` и нажать кнопку `Enter`

Осталось запустить Nginx и добавить его в автозапуск. Это можно сделать за один шаг 👇🏻

```bash
sudo systemctl enable --now nginx
```

Далее открой в браузере адрес своего сервера. Теперь, если ты не укажешь порт, увидишь похожий экран 👇🏻

## Изменение конфигурации

Мы будем использовать **два файла** для конфигурации Nginx. Конфигурация **фронтенда** будет в конфигурационном файле по умолчанию `/etc/nginx/sites-available/default` — ты вернёшься к нему чуть позже. А для того, чтобы настроить **бэкенд**, создай новый файл конфигурации `/etc/nginx/sites-available/backend`

Введи команду `touch` 👇🏻

```bash
# Команда touch создаёт пустые файлы
sudo touch /etc/nginx/sites-available/backend
```

Дело в том, что в Nginx есть две директории для хранения конфигураций: `sites-available` (доступные сайты) и `sites-enabled` (запущенные сайты). В первой хранятся конфигурации всех сайтов, а во второй — ссылки только на активные. 

Перед редактированием конфигурации нужно создать символическую ссылку между `sites-available` и `sites-enabled`. Только не забудь заменить `<имя_конфига>` на `backend`, когда будешь вводить команду 👇🏻

```bash
sudo ln -s /etc/nginx/sites-available/<имя_конфига> /etc/nginx/sites-enabled/<имя_конфига>
```

Теперь переходим к редактированию файла конфигурации. В командной строке введи 👇🏻

```bash
sudo nano /etc/nginx/sites-available/backend

# sudo значит — запустить команду как суперпользователь
# nano — это текстовый редактор
# /etc/nginx/sites-available/default — путь к конфигурационному файлу nginx
```

Вставь в этот файл следующую конфигурацию, указав созданный в уроке «Выпуск доменов» соответствующий домен 👇🏻

```bash
server {
      listen 80;

      server_name <твой_домен>;

      location / {
                proxy_pass http://localhost:3001;
                proxy_http_version 1.1;
                proxy_set_header Upgrade $http_upgrade;
                proxy_set_header Connection 'upgrade';
                proxy_set_header Host $host;
                proxy_cache_bypass $http_upgrade;
      }
}
```

Конфигурация говорит, что слушать запросы необходимо на `80`-м порте и перенаправлять их на `http://localhost:3001`, то есть на `3001`-й порт внутренней сети. Обрати внимание, кроме перенаправления запроса конфигурация выставляет некоторые дополнительные заголовки. 

Ещё в конфигурационном файле есть блок `server_name`. В нём пропиши доменное имя, зарегистрированное в предыдущем уроке. Тогда такая конфигурация будет перенаправлять все запросы с твоего домена Node.js-приложению на `3001`-й порт.

После того как всё сделаешь, жми комбинацию `Ctrl + X`. Nano спросит, хочешь ли ты сохранить изменения, — нажимай `Y` и кнопку `Enter`

Но если в конфигурации окажутся ошибки, то в лучшем случае работа приложения будет остановлена. Nginx позволяет изменять и тестировать конфигурацию, что называется, на лету. Для этого до перезапуска Nginx введите команду 👇🏻

```bash
sudo nginx -t
```

Она позволит проверить конфигурацию на наличие ошибок в синтаксисе команд. Если всё прошло успешно, получишь такой ответ 👇🏻

```bash
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful
```

Уже после этого можно перезагрузить конфигурацию Nginx и не бояться, что приложение слетит 👇🏻

```bash
sudo nginx -s reload
```
