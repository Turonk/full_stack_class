## Авторизация

**Аутентификация,** или **авторизация,** в веб-приложениях — это процесс проверки подлинности пользователя и предоставления ему доступа к определённым ресурсам или функциям приложения. 

С точки зрения бэкенда это выглядит примерно так:

- Сервер получает `POST`-запрос с логином и паролем.
- Проверяет, есть ли такой пользователь в БД.

Рассмотрим подробнее, как организовать работу такого кода.

## Создаём контроллер аутентификации

Создай в папке `controllers` файл `auth.js` и импортируй в него модель пользователя 👇🏻

```javascript
// controllers/auth.js

const users = require("../models/user.js");
```

Чтобы войти в систему, пользователь отправляет на сервер почту и пароль. Это удобно делать в теле запроса. С этой целью опиши функцию `login` для обработки входящих значений после аутентификации 👇🏻

```javascript
// controllers/auth.js

const login = (req, res) => {
  const { email, password } = req.body;

  // ...
};
```

Если почта и пароль совпадают с теми, что есть в базе, пользователь сможет войти на сайт. Иначе — получит сообщение об ошибке. 

Проверить корректность данных можно по-разному:

- Проверить наличие пользователя с полученной почтой в базе. 
Если пользователь нашёлся, высчитать хеш пароля и сравнить его с хешем в базе.
- Посчитать хеш пароля и проверить, есть ли в базе пользователь с полученной почтой и хешем пароля.

### Ищем пользователя

Проверь, есть ли пользователь в базе 👇🏻

```javascript
// controllers/auth.js

const login = (req, res) => {
  const { email, password } = req.body;

  users.findOne({ email })
    .then(user => {
      if (!user) {
        // Пользователь с такой почтой не найден
    }
    
    // Пользователь найден
    });
};
```

Если пользователь не найден, перейди в блок `catch` и верни ответ с ошибкой 👇🏻

```javascript
// controllers/auth.js

const login = (req, res) => {
  const { email, password } = req.body;

  users
    .findOne({ email }).then(user => {
	    if (!user) {
	      // Пользователь не найден — отклоняем промис
	      // с ошибкой и переходим в блок catch
	      return Promise.reject(new Error("Неправильные почта или пароль"));
	    }
	   })
     // Пользователь найден
    .catch(error => {
      // Возвращаем ошибку аутентификации
      res.status(401).send({ message: error.message });
    });
};
```

### Проверяем пароль

Если пользователь найден, проверь пароль: захешируй его и сравни с хешем в базе — вторым аргументом. Для реализации используй метод `bcrypt.compare`, принимающий на входе пароль и его хеш👇🏻

```javascript
// controllers/auth.js
const bcrypt = require('bcryptjs')

const login = (req, res) => {
  const { email, password } = req.body;

  users
    .findOne({ email }).then(user => {
    if (!user) {
      return Promise.reject(new Error("Неправильные почта или пароль"));
    }
    // Сравниваем переданный пароль и хеш из базы
    return bcrypt.compare(password, user.password)
    .catch(error => {
      res.status(401).send({ message: error.message });
    });
};
```

Метод `bcrypt.compare` работает асинхронно, поэтому результат нужно вернуть и обработать в следующем `then`. Если хеши совпали, в следующий `then` придёт `true`, иначе — `false` 👇🏻

```javascript
// controllers/auth.js

const login = (req, res) => {
  const { email, password } = req.body;

  users
    .findOne({ email }).then(user => {
	    if (!user) {
	      return Promise.reject(new Error("Неправильные почта или пароль"));
	    }
	
	    return bcrypt.compare(password, user.password).then(matched => {
	      if (!matched) {
	        // Хеши не совпали — отклоняем промис
	        return Promise.reject(new Error("Неправильные почта или пароль"));
	      }
	      // Аутентификация успешна
	      return user; // Теперь user доступен
	    });
	  })
    .then((user) => {
      res
        .status(200)
        .send({ _id: user._id, username: user.username, email: user.email });
    })
    .catch(error => {
      res.status(401).send({ message: error.message });
    });
};

// Не забываем экспортирвать функцию 
module.exports = { login };
```

Также обрати внимание, что в результате успешной аутентификации с сервера возвращается объект с данными о пользователе — `{ _id: user._id, username: user.username, email: user.email }`, который используется клиентом для отображения информации о юзере на сайте. Таким образом происходит синхронизация актуальных данных между клиентом и сервером. В будущем здесь также будет передаваться `JWT`-токен, который обеспечит дополнительную защиту и удобство использования сайта для пользователя.

## Создаём роутер для аутентификации

Добавь в папке `routes` в файле `auth.js` роутер для авторизации `authRouter`. Импортируй в него функцию `login` из контроллера аутентификации, где будешь отслеживать `POST`-запросы по эндпоинту `"/api/auth/login"` 👇🏻

```javascript
// routes/auth.js

const authRouter = require("express").Router();
const { login } = require("../controllers/auth.js");

authRouter.post("/auth/login", login);

module.exports = authRouter;

```

Останется только использовать новый роутер в файле `routes/api.js`, где собираются все роутеры для API сервера 👇🏻

```javascript
// routes/api.js

const authRouter = require("./auth");
const categoriesRouter = require("./categories");
const gamesRouter = require("./games");
const usersRouter = require("./users");

const apiRouter = require("express").Router();

apiRouter.use("/api", usersRouter);
apiRouter.use("/api", gamesRouter);
apiRouter.use("/api", categoriesRouter);
apiRouter.use("/api", authRouter); // Добавляем роутер для аутентификации

module.exports = apiRouter;
```
