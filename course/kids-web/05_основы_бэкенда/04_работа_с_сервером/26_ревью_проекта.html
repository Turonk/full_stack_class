Ревью проекта

Как отправить работу на ревью

Лови парочку шагов для подготовки фронтенда 👇🏻

1. Зайди в проект со своим Next.js-приложением и найди в нём файл `README.md` 2. Удали всё, что там написано. 3. Напиши туда вместо удалённого текста `Мой бэкенд:`, а после двоеточия укажи адрес сайта, где лежит твой бэкенд. Cохрани файл. 4. Создай новую ветку Git командой `git checkout -b last-review` 5. Отправь изменения в эту ветку 👇🏻

git add .
git commit -m 'Финальное ревью'
git push origin last-review

6. Зайди на GitHub и создай в репозитории с фронтендом Pull-Request-запрос. Если не помнишь как, ищи подсказки в уроке **«Git через терминал»** (подтема «Создание Pull Request»).

Гуд, теперь насчёт бэкенда 👇🏻

1. Зайди в проект со своим Express-приложением. 2. Создай новую ветку Git командой `git checkout -b last-review` 3. Добавь в корне проекта файл `README.md` 4. Напиши в нём следующую информацию и сохрани файл 👇🏻

Ссылка на репозиторий с фронтендом: <сюда вставь ссылку на репозиторий фронтенда>

Ссылка на домен фронтенда: <сюда вставь ссылку, по которой лежит Pindie>

IP-адрес: <ip-адрес твоего сервера>

5. Затем отправь изменения в GitHub 👇🏻

git add .
git commit -m 'Финальное ревью'
git push origin last-review

6. Создай на гитхабе в репозитории с бэкендом Pull-Request-запрос. 7. Скопируй ссылку на него из адресной строки браузера и отправь в форму ниже.

Чек-лист 📝

1. Оба твоих сайта открываются по `https` на указанных адресах.

2. Фронтенд Pindie работает корректно, а именно 👇🏻

a. Все данные отображаются.

b. Можно авторизоваться.

c. Перезагрузка сохраняет состояние авторизации.

d. Можно проголосовать за игру.

3. Админка бэкенда позволяет выполнить все операции 👇🏻

a. Можно авторизоваться пользователем `[aski@example.com] (mailto:aski@example.com)` с паролем `ilovehtml`

b. Без авторизации страница `dashboard` недоступна.

c. После авторизации пользователь перенаправляется на `dashboard` автоматически.

d. При перезагрузке страницы авторизация сохраняется.

e. Можно добавить, удалить, изменить игру.

f. Нельзя создать игру с неуникальным именем или изменить, не добавив хоть одну категорию. Также нельзя добавить игру с пустыми полями.

g. Можно добавить, удалить категорию и изменить её имя.

h. Невозможно создать категорию с неуникальным именем или изменить её с пустым именем.

i. Можно добавить, удалить пользователя и изменить данные о нём (имя или email).

j. Невозможно создать пользователя с неуникальным email или без логина, почты или пароля, а ещё изменить данные о юзере на пустые логин или email.

4. В коде бэкенда 👇🏻

a. Корректно описаны роуты.

b. Корректно разбиение проекта на контроллеры и миддлвары.

c. Корректны CORS и настройки JWT.

d. Корректны настройки работы с Cookie.

e. Корректно разделение роутинга на `/api` и `/admin`

5. В коде фронтенда корректно настроена связь с бэкендом.
