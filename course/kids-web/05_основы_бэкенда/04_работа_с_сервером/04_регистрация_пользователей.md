# Регистрация пользователей

Но чтобы создать полноценный бэкенд для Pindie, нужно не только сохранять пользователей в базе, но и правильно обрабатывать {{регистрацию}}[web_teens_theme4_lesson_4_«регистрацию»] и {{аутентификацию}}[web_teens_theme4_lesson_4_«аутентификацию»] на сайте.

## Добавление пользователя в базу данных

Сначала создай, а затем запиши пользователя в БД. 
Для этого проверь ключевые моменты:

1. Модель юзера должна содержать обязательные поля для регистрации и поиска в базе 👇🏻

    ```javascript
    // models/user.js
    
    const mongoose = require('mongoose');
    
    const userSchema = new mongoose.Schema({
      username: {
        type: String,
        required: true
      },
      email: {
        type: String,
        required: true,
        unique: true
      },
      password: {
        type: String,
        required: true
      }
    });
    
    module.exports = mongoose.model("user", userSchema);
    ```

    `email` должен быть уникальным, поскольку пользователь проходит аутентификацию по электронной почте. Для этого добавь свойство `unique` со значением `true`. Так в базе не окажется нескольких пользователей с одинаковой почтой.

2. Запись пользователя в БД происходит при помощи метода `create` у модели `user`. Ранее мы создавали специальную миддлвар-функцию `createUser`, которая получает данные из тела запроса, проверяет их и записывает в базу данных 👇🏻

    ```javascript
    // middlewares/users.js
    
    const users = require("../models/user");
    
    const createUser = async (req, res, next) => {
      try {
        req.user = await users.create(req.body);
        next();
      } catch (error) {
        res.status(400).send("Ошибка при создании пользователя");
      }
    };
    ```

## Шифрование пароля

Пароль в базе следует хранить в зашифрованном виде. Иначе пользователи окажутся в уязвимом положении: если у злоумышленника появится доступ к базе, он получит доступ и к аккаунтам.

Хеш берёт любой произвольный текст на входе и совершает с ним некоторые математические действия, в результате которых получается новая зашифрованная строка. Хитрость в том, что вне зависимости от длины входящего текста строка получается всегда одной и той же длины, а восстановить исходный текст из этой строки невозможно.

![](https://pictures.s3.yandex.net:443/resources/1_1714651316.jpg)

Нет, это не так. Хакеры бывают умными, а пользователи — ленивыми.

Итак, хакер знает, что повторяющиеся хеши — это зашифрованные популярные пароли. Что хакер сделает следующим шагом? Захеширует самостоятельно самые распространённые пароли, которые могут использовать люди на этом сайте: `123456`, `qwerty123`, `password`, `111111`. А потом сравнит хеш этих паролей и хеш для каждого пользователя в БД, к которой он получил доступ.

Взломать всех пользователей он не сможет, но аккаунты с самыми слабыми паролями окажутся в его полном распоряжении.

Теперь процесс шифрования становится сложнее: 

- Генерируется случайная соль для каждого пользователя, например `V7s2#Lg8`
- Пользователь вводит пароль `password`
- К паролю добавляется соль, получаем `passwordV7s2#Lg8`
- Полученная строка хешируется.
- Полученный хеш сохраняется в базе данных вместе со случайной солью.

![](https://pictures.s3.yandex.net:443/resources/1-1_1_1714652738.jpg)

У каждого пользователя своя соль, поэтому даже если пароль у кого-то одинаковый и очень простой, то хеш будет разным. Теперь хакеру надо либо перебирать для каждого пароля все комбинации с солью из БД, либо уйти ни с чем 👇🏻

![](https://pictures.s3.yandex.net:443/resources/2_1_1714652803.jpg)

Таким образом, хеширование паролей является важным элементом обеспечения безопасности в современных приложениях и веб-сервисах. Теперь ты знаешь принцип шифрования твоих паролей на сайтах, которыми пользуешься каждый день. Пора самостоятельно написать это в коде.

## Пишем код

Для хеширования пароля понадобится модуль `bcryptjs`. Его нужно установить через терминал, как мы делали это с другими модулями и библиотеками, командой `npm i bcryptjs`, а затем импортировать в файл 👇🏻

```javascript
// middlewares/users.js

const users = require("../models/user");
const bcrypt = require("bcryptjs"); // Импортируем bcrypt
```

Добавь вспомогательную функцию `hashPassword`, преобразовывающую пароль. Таким образом ты сможешь защитить данные пользователя, если вызовешь её для хеширования перед созданием записи в базе данных. 

За преобразование пароля отвечает метод `hash`, который принимает на вход два параметра — пароль и длину соли 👇🏻

```javascript
// middlewares/users.js

const hashPassword = async (req, res, next) => {
  try {
    // Создаём случайную строку длиной в десять символов
    const salt = await bcrypt.genSalt(10);
    // Хешируем пароль
    const hash = await bcrypt.hash(req.body.password, salt);
    // Полученный в запросе пароль подменяем на хеш
    req.body.password = hash;
    next();
  } catch (error) {
    res.status(400).send({ message: "Ошибка хеширования пароля" });
  }
};
```

## Актуальный `usersRouter` для регистрации

Теперь, чтобы зарегистрировать пользователя, тебе нужно 👇🏻

- Слушать `POST`-запрос по эндпоинту `"/api/users"`
- Найти пользователей в базе данных — `findAllUsers`
- Выполнить необходимые проверки и захешировать пароль — `hashPassword`
- Создать запись в БД о новом пользователе, сохранив хеш в качестве пароля пользователя — `createUser`
- Вернуть ответ об успешной регистрации с данными о добавленном пользователе — `sendUserCreated`

Чекай, как это выглядит 👇🏻

```javascript
// routes/users.js

usersRouter.post(
  "/users",
  findAllUsers,
  checkIsUserExists,
  checkEmptyNameAndEmailAndPassword,
  hashPassword,
  createUser,
  sendUserCreated
);
```

Когда ты создаёшь нового пользователя, в базе данных будет сохраняться хеш вместо оригинального пароля — это обезопасит данные юзера. Джаст воч 👇🏻
