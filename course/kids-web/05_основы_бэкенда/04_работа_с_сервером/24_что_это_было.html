Что это было?

В основе всего лежит база данных MongoDB, в ней ты хранишь данные об играх, которые связаны с пользователями и категориями. У каждой игры может быть много категорий и много проголосовавших за эту игру пользователей.

![](https://pictures.s3.yandex.net/resources/1_1715872124.jpg)

Для удобной работы с этой БД на своём компьютере тебе потребовалось установить на него MongoDB и Compass. Compass позволил управлять базой данных через приятный графический интерфейс.

![](https://pictures.s3.yandex.net/resources/2_1715872164.jpg)

Для более продвинутых операций над данными в базе и описания сложной логики работы с ними мы создали рядом приложение на Express, которое связывается с БД через специальную библиотеку Mongoose.

![](https://pictures.s3.yandex.net/resources/3_1715872279.jpg)

В приложении на Express у тебя есть два вида функциональности 👇🏻

- REST API, которое создано, чтобы другие приложения могли общаться с базой данных через HTTP-запросы. - Статическая админка на HTML, CSS, JS, чтобы администраторы данных могли работать с БД без Compass, а сразу через браузер.

![](https://pictures.s3.yandex.net/resources/4_1715872323.jpg)

На основе реализованного REST API создали приложение Pindie на Next.js. Это фронтенд, который отправляет запросы в приложение на Express и получает от него ответы. Некоторые запросы доступны без авторизации, а некоторые требуют авторизации и отправки специального набора символов — `JWT`-токена.

![](https://pictures.s3.yandex.net/resources/5_1715872366.jpg)

Чтобы приложения на Express и Next работали, на твоём компьютере установлена Node.js.

![](https://pictures.s3.yandex.net/resources/6_1715872409.jpg)

Так это всё работает сейчас на твоём компьютере, но нужно, чтобы заработало в облаке, на удалённом сервере, доступ к которому мы тебе выдали.

![](https://pictures.s3.yandex.net/resources/7_1715872464.jpg)

На удалённом сервере пришлось вручную установить MongoDB и импортировать все данные, которые хранились на компьютере. Для установки мы повозились с терминалом через `ssh`. Для экспорта коллекций использовался Compass, а для импорта — команды на удалённом сервере.

![](https://pictures.s3.yandex.net/resources/8_1715872512.jpg)

Чтобы перенести в облако код приложений, пользовались Git. Его тоже установили на удалённый сервер.

![](https://pictures.s3.yandex.net/resources/9_1715872553.jpg)

Для хранения, ревью и {{версионирования кода}}[web_teens_theme4_lesson_12_«версионирования кода»] создали два репозитория на GitHub: один для фронтенда, другой для бэкенда. Git на компе отправляет код в эти репозитории командой `git push`, а Git в облаке скачивает командой `git pull`

![](https://pictures.s3.yandex.net/resources/10_1715872598.jpg)

Чтобы код приложений на Express и Next заработал на удалённом сервере, на него пришлось установить Node.js, как и на твой компьютер. Именно Node.js запускает и выполняет код приложений.

![](https://pictures.s3.yandex.net/resources/11_1715872696.jpg)

После этого наконец-то удалось запустить приложение на удалённом сервере! Бэкенд был запрограммирован открываться на порте `3001`, а фронтенд — на `3000`. Поэтому из интернета твои приложения стали видны по адресам `http://твой-ip-адрес:3001` и `[http://твой-ip-адрес:300](http://твой-ip-адрес:3001)0`

![](https://pictures.s3.yandex.net/resources/12_1715872739.jpg)

А ещё возникла проблема: когда отключались от сервера, приложения переставали работать. Причина в том, что приложения запускались через Node.js вручную, как мы раньше делали это на компе. Как только выходили с сервера, приложения выключались. Поэтому на сервер пришлось установить специальную программу PM2, которая умеет запускать приложения на Node.js в фоновом режиме, независимо от присутствия человека на сервере.

![](https://pictures.s3.yandex.net/resources/13_1715872795.jpg)

После этого приложения стали доступными по адресам `http://твой-ip-адрес:3001` и `[http://твой-ip-адрес:300](http://твой-ip-адрес:3001)0`, даже когда ты не на сервере.

Потом нам очень захотелось, чтобы вместо некрасивых IP-адресов и адресов портов приложения начали работать на красивых доменах типа [http://mywebsitename.ru](http://mywebsitename.ru){target="_blank"}. Для этого пришлось зарегистрировать домены во внешнем сервисе и направить их на нужные IP-адреса A-записью. Сервис по регистрации и направлению доменов мы предоставили тебе на период обучения.

![](https://pictures.s3.yandex.net/resources/14_1715872866.jpg)

Чтобы приложения с портов `3000` и `3001` начали открываться при вводе доменных имён, нужно было связать эти имена и адреса портов на сервере. Для этого установили Nginx, который за счёт механизма под названием «реверс-прокси» выполнил эту задачу.

![](https://pictures.s3.yandex.net/resources/15_1715872910.jpg)

Ну и в конце нужно было выпустить сертификаты, чтобы приложения открывались не через `http`, а зашифрованный и безопасный `https`. Мы с тобой установили специальный пакет программ от Let’s Encrypt, который создан именно для этих целей. После чего проги выпустили и зарегистрировали все нужные сертификаты и перенастроили Nginx так, чтобы сайты работали по `https`

![](https://pictures.s3.yandex.net/resources/16_1715872963.jpg)
