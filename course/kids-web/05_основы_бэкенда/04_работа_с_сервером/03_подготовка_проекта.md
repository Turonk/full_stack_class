## Единый интерфейс в роутах

Ты уже знаешь, что серверное приложение может обрабатывать и возвращать разные данные: игры, категории, пользователей. Но для работы с каждым из этих разделов, будь это создание игры или получение категории по идентификатору, нужно иметь единую точку входа.

Сейчас для взаимодействия с данными в приложении у тебя уже описаны соответствующие роуты. К примеру, для получения всех игр 👇🏻

```javascript
http://localhost:3000/games
```

Здесь `http://` — это протокол подключения, `localhost:3000` — адрес нашего сервера, а `/games` — роут для получения информации обо всех играх.

Такого же типа маршруты можно наблюдать и для получения данных всех категорий, и для пользователей 👇🏻

```javascript
http://localhost:3000/categories // Получаем все категории
http://localhost:3000/users // Получаем всех пользователей
```

Для всех этих маршрутов существует единый интерфейс, другими словами — точка входа, то есть адрес сайта.

Чтобы не происходило таких конфликтов, предлагаем создать единый роут для серверного приложения, явно указав, что мы обращаемся к API. 

Для этого добавь файл `apiRouter.js` в папку `routes`. Затем внутри него создай сам роут, как мы раньше делали это со всеми остальными 👇🏻

```javascript
const apiRouter = require("express").Router();
```

После обратись к созданному `apiRouter` и используй метод `use`, указав первым аргументом главный путь, а вторым — роут, который будешь использовать по этому пути. Лови пример игрового роута `gamesRouter`, только не забудь его импортировать перед компиляцией 👇🏻

```javascript
const gamesRouter = require("./games");

const apiRouter = require("express").Router();
apiRouter.use("/api", gamesRouter);
```

Таким образом, для всех маршрутов, которые работают с данными пользователя, изменится точка входа. Конечный маршрут для всех роутов внутри `gamesRouter` будет `localhost:3000/api/games` 

Теперь добавь самостоятельно `usersRouter`, `categoriesRouter`, `authRouter`, указав тот же путь `/api`. Должно получиться вот так 👇🏻

```javascript
// Импорты и инициализация главного роута
apiRouter.use("/api", gamesRouter);
apiRouter.use("/api", usersRouter);
apiRouter.use("/api", categoriesRouter);
apiRouter.use("/api", authRouter);
```

Не забывай экспортировать наш единый роут 👇🏻

```javascript
// Код роута
module.exports = apiRouter;
```

Осталось только указать приложению, чтобы оно использовал его вместе с остальными инструментами. При этом все одиночные роуты для пользователей, игр и категорий нужно исключить, как и их импорты 👇🏻

```javascript
// app.js
// Импорты и инициализация приложения

app.use(
  cors,
  bodyParser.json(),
  apiRouter // Добавляем
  express.static(path.join(__dirname, "public")),
  usersRouter, // Удаляем
  gamesRouter, // Удаляем
  categoriesRouter, // Удаляем
);

// Запуск приложения
```

## Защищаем пароли

При работе с библиотекой Mongoose мы уже знакомили тебя с методом `populate`, собирающим полный документ из ссылок на другие документы. Например, при запросе всех файлов из коллекции `games`, чтобы подгрузить полные данные категорий 👇🏻

```javascript
const findAllGames = async (req, res, next) => {
  req.gamesArray = await games
	  .find({})
	  .populate("categories")
  // Остальной код
};
```

Метод `populate` заполняет данными массив `users`, который хранит всю информацию о пользователях, проголосовавших за игру.

Поэтому при втором вызове `populate` следует детально настроить его и указать, что поле `password` нужно исключить из данных запроса 👇🏻

```javascript
const findAllGames = async (req, res, next) => {
  req.gamesArray = await games
	  .find({})
	  .populate("categories")
	  .populate({path: "users", select: "-password"});
	// Остальной код
};
```

Решить эту проблему можно двумя разными способами: используя возможности Mongoose или создав собственную функцию исключения пароля из данных каждого пользователя. Рассмотрим оба, а ты выбери тот, что тебе по вкусу.

Как ты знаешь, документы представляют собой объекты. Создай новую функцию в миддлваре для работы с пользователями, которая будет пересобирать объект каждого юзера при запросе его данных, исключая оттуда поле с паролем.

Для этого перейди в файл `users.js` в папке `middlewares` и добавь функцию `filterPassword` 👇🏻

```javascript
const filterPassword = (req, res, next) => {};
```

Она будет служить миддлваром как для запросов на получение всех пользователей, так и для запросов на получение одного конкретного юзера по его идентификатору. Для того чтобы можно было обработать и одиночный объект пользователя, и массив с объектами пользователей, внутри функции `filterPassword` создай универсальную функцию `filterUser` 👇🏻

```javascript
const filterPassword = (req, res, next) => {
  const filterUser = (user) => {
    const { password, ...userWithoutPassword } = user.toObject();
    return userWithoutPassword;
  };
};
```

Она будет принимать объект пользователя и пересобирать его, используя метод `toObject` из библиотеки Mongoose.

При запросе данных всех пользователей — в объекте ответа мы создаём поле `usersArray`, а при запросе данных одного пользователя — поле `user`. Поэтому нужно проверить наличие каждого из полей и запустить функцию `filterUser` для каждого из них по-своему. 

Первым делом проверь поле `user` 👇🏻

```javascript
const filterPassword = (req, res, next) => {
	// Код функции фильтрации
  if (req.user) {
    req.user = filterUser(req.user);
  }
};
```

Здесь всё очень просто: если в объекте запроса содержится поле `user` — перезапиши объект внутри него, применив функцию фильтрации.

Добавь вторую проверку на случай, если в объекте запроса будет поле `usersArray`. В этом случае проделай те же действия, но для каждого из пользователей. Используя метод `map`, отфильтруй каждый объект юзера в массиве 👇🏻

```javascript
const filterPassword = (req, res, next) => {
	// Код функции фильтрации
  if (req.user) {
    req.user = filterUser(req.user);
  }
  if (req.usersArray) {
    req.usersArray = req.usersArray.map((user) => filterUser(user));
  }
};
```

Осталось добавить вызов метода `next()` после всех действий и проверок, чтобы передать запрос следующему миддлвару 👇🏻

```javascript
const filterPassword = (req, res, next) => {
	// Остальной код
	next();
};
```

Теперь нужно применить новый миддлвар для двух запросов: получения данных всех пользователей и получения данных одного пользователя. Перейди в роут, который работает с юзерами, и добавь функцию `filterPassword` между миддлваром для поиска и контроллером, который возвращает ответ 👇🏻

```javascript
usersRouter.get("/users", findAllUsers, filterPassword, sendAllUsers);
usersRouter.get("/users/:id", findUserById, filterPassword, sendUserById);
```

Чтобы приложение работало без ошибок, не забудь экспортировать новую функцию из миддлвара и импортировать её в роут `users.js` в папке `routes`

Метод `find` библиотеки Mongoose умеет не только принимать параметры, по которым будет проходить поиск документов в коллекции, но и использовать опцию проекции, благодаря которой можно указать, какие поля включать или исключать из запроса.

Чтобы применить опцию в запросе, будем использовать немного непривычный для тебя синтаксис. Добавь проекцию в функцию получения данных всех пользователей `findAllUsers` 👇🏻

```javascript
const findAllUsers = async (req, res, next) => {
  console.log("GET /api/users");
  req.usersArray = await users.find({}, { password: 0 });
  next();
};
```

Здесь вторым аргументом метода `find` ты передаёшь объект с полем `password`, у которого установлено значение `0`. Это и называется **проекцией.**

Кстати, метод `findById` тоже поддерживает проекцию. Попробуй самостоятельно добавить эту опцию в запрос в функции `findUserById`

```javascript
const findUserById = async (req, res, next) => {
  console.log("GET /api/users/:id");
  try {
    req.user = await users.findById(req.params.id, { password: 0 });
    next();
  } catch (error) {
    res.status(404).send("User not found");
  }
};
```
