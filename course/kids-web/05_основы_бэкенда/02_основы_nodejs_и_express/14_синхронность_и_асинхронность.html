Синхронность и асинхронность

![](https://pictures.s3.yandex.net:443/resources/IMG_4963_1712130522.jpg)

Что такое синхронные и асинхронные операции

Представим, что к Аски сегодня в гости должны прийти друзья-рыцари, а к Цэ-эс-эсочке подружки — аниме-тянки. Наши герои идут в магазин прикупить к чаю торт и мороженое, но действуют по-разному.

Аски посещает прилавок с тортами и, сделав заказ, ждёт, пока ему всё упакуют. Только получив его, он пойдёт к прилавку с мороженым, сделает заказ и снова станет ждать свою порцию.

Цэ-эс-эсочка время впустую тратить не любит и поступает резвее: заказывает торт, а затем сразу оформляет покупку в магазине мороженого. В итоге её запросы на торт и мороженое собираются одновременно — и ждёт она всего один раз вместо двух.

В этом примере Аски выполняет все действия синхронным образом, а Цэ-эс-эсочка наоборот — асинхронно.

Держи несколько формальных определений.

**Синхронная операция** — операция, которая блокирует дальнейшее выполнение программы до тех пор, пока не будет полностью выполнена.

Например, рассмотрим простой код 👇🏻

function logCakes() {
  const cakes = [
    'Чизкейк',
    'Тирамису',
    'Шарлотка',
    'Прага',
    'Наполеон'
  ];
  for (let cake of cakes) {
    console.log(cake);
  }
}

console.log('В наличии есть торты:')
logCakes();
console.log('Все очень вкусные!')

Компьютер последовательно выполнит ряд синхронных операций:

1. Проинициализирует функцию `logCakes` 2. Выведет в консоль `В наличии есть торты:` 3. Начнет выполнять функцию `logCakes`, в которой в цикле выведет в консоль название каждого торта. 4. Выведет в консоль `Все очень вкусные!`

То есть код проги исполняется строчка за строчкой, пока не дойдёт до самого конца. После выполнения последней программа считается завершённой. В примере выше компьютер каждый момент времени занят выполнением синхронной операции.

Перейдём к **асинхронным операциям** — это такие операции, которые не блокируют дальнейшую работу программы. Часто случается ситуация, когда неизвестно время завершения выполнения всех команд кода.

Например 👇🏻

- Чтение файла с помощью `readFile` — файл может быть любого размера, но чем он больше, тем дольше его читать. Операция чтения не блокирует выполнение программы. - Запросы по сети — неизвестно, когда выполнится запрос. - Ожидание таймеров.

Перепиши пример выше и добавь асинхронную операцию — таймер с помощью `setTimeout`. Это простая функция, которая принимает другую функцию и выполняет её через заданное время 👇🏻

function logCakes() {
  const cakes = [
    'Чизкейк',
    'Тирамису',
    'Шарлотка',
    'Прага',
    'Наполеон'
  ];
  for (let cake of cakes) {
    console.log(cake);
  }
}

console.log('Подожди пару секунд, мы проверим, что осталось в наличии...')
setTimeout(() => {
  console.log('В наличии остались такие торты: ');
  logCakes();
  console.log('Все очень вкусные!')
}, 5000);

console.log('Пока ждёшь, расскажи, какой торт твой любимый, мой — Наполеон');

Рекомендуем ещё глянуть скринкаст и обратить внимание на то, в каком порядке будут выполнены все операции в данном коде 👇🏻

{video:https://code.s3.yandex.net/kids-web/vids/M4/2.mp4|controls:true|autoplay:0|pip:false|controlsList:nodownload}

Теперь компьютер пройдёт следующие шаги в таком порядке:

1. Проинициализирует функцию `logCakes` 2. Выведет в консоль `Подожди пару секунд, мы проверим, что осталось в наличии...` 3. Выполнит асинхронную функцию `setTimeout`, то есть запустит таймер на 5 секунд 4. Выведет `'Пока ждёшь, расскажи, какой торт твой любимый, мой — Наполеон'` 5. Через пять секунд выполнит функцию, которую мы передали в `setTimeout`

Но судя по выводу в консоли, четвёртый шаг выполнился сразу после второго. В этом и заключается суть асинхронных операций. Запустив таймер через `setTimeout`, компьютер не стал дожидаться окончания таймера — можно сказать, что он отложил его в сторону и продолжил дальнейшее выполнение программы.

Колбэки и `callback hell`

{quiz-task} background: | #f1f1ef content: | ❗ Исторически первым способом обработки асинхронных операций является функция обратного вызова — `callback`, которую мы уже упоминали в курсе. {/quiz-task}

В этой теме мы рассмотрели две асинхронные функции: `readFile` — для чтения содержимого файла, и `setTimeout` — для запуска таймера. В каждую из них передаётся функция, которая вызывается после того, как файл будет полностью прочитан или истечёт таймер, эта функция и есть `callback`

При написании реальных приложений часто возникает задача, когда по завершении одной асинхронной операции нужно вызвать ещё одну, тоже асинхронную, а по её завершении нужно вызвать третью и так далее. Вот пример такого кода 👇🏻

setTimeout(() => {
  fs.readFile('data.json', (err, data) => {
    // ...
    anotherAsyncOperation(() => {
      // ...
      oneMoreAsyncOperation(() => {
        // ...
        lastAsyncOperation(() =>{
          // ...
        })
      })
    })
  })
}, 5000)
