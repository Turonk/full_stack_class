# Запрос, ответ, ошибка

![](https://pictures.s3.yandex.net:443/resources/IMG_4940_1711716982.jpg)

Давай разберём метод `http.createServer()`, в функции-колбэке которого аргументами передаются два объекта — запрос `req` и ответ `res`. В них может находиться много полезной информации для взаимодействия клиента и сервера.

## Адрес запроса `req.url`

В прошлом модуле мы уже познакомились с запросами: они нам нужны для взаимодействия с API веб-сервиса, когда происходит обращение к различным эндпоинтам. 

Например, в Pindie мы уже активно юзали 👇🏻

- `'https://api-code-2.practicum-team.ru/games'` — для получения игр.
- `'https://api-code-2.practicum-team.ru/auth/local'` — для авторизации пользователей.
- `'https://api-code-2.practicum-team.ru/users/me'` — для проверки авторизации.

Как видишь, основной URL-адрес API один, но его конечная часть, которая отвечает за маршруты запроса (они же эндпоинты), может варьироваться в зависимости от действий.

Давай вспомним JavaScript и работу с условиями. В колбэк-функции метода `http.createServer()` получи значение `url` из объекта `req`, для этого опиши действия для разных запросов 👇🏻

```javascript
const server = http.createServer((req, res) => {
  const url = req.url;
  if (url === "/") {
	  console.log("запрос по url = '/'")
  } 
  if (url === "/game") {
	  console.log("запрос по url = '/game'")
  } 
  if (url === "/vote") {
	  console.log("запрос по url = '/vote'")
  } 
  if (url !== "/" && url !== "/game" && url !== "/vote") {
	  console.log("необрабатываемый запрос")
  }
});
```

Начать предлагаем с конструкции `switch…case`

Ранее делать ветвления в коде тебе помогали условия `if…else`, логические и тернарные операторы, а теперь давай познакомимся с управляющей конструкцией `switch`

Выглядит она так:

```javascript
switch (имя_переменной_значение_которой_сравниваем) {
  case значение:
    // код
    break
}
```

Это похоже на `if…else`, но оператор `if` используется для определения блока кода, который будет выполняться, если заданное условие соблюдается (возвращает `true`).

Оператор `switch` определяет несколько альтернативных блоков кода. 

Огромную цепочку из условий с использованием конструкции `if…else` легко заменяет аккуратный `switch`. Его можно расширять блоками с кодом и оператором `case`. Принцип работы `switch` похож на реальную жизнь. Например, тебе пришло уведомление о пропущенном сообщении, и у тебя есть масса вариантов действий в зависимости от обстоятельств: 

- Ты не можешь ответить — следует вернуться к сообщению позже.
- Тебе пришло сообщение с рекламным спамом — следует игнорировать его или заблокировать контакт.
- Важное сообщение от родителей — нужно ответить как можно скорее.

Такие цепочки можно продолжать бесконечно. В программировании подобное разнообразие действий в зависимости от условия или переменной удобно описывать с помощью оператора `switch`. Его принцип работы следующий:

- Сначала вычисляется выражение в операторе `switch`
- Затем его значение сравнивается со значениями каждого оператора `case`
- Если найдено совпадение, то выполняется соответствующий блок кода.

Например, попросим пользователя ввести значение и выполним соответствующий ему блок кода:

```javascript
// Запиши цифру между 0 и 3 вместо null в переменную number
const number = null;

switch (number) {
  case 0:
    console.log('Введён 0');
    break;

  case 1:
    console.log('Введена 1');
    break;

  case 2:
    console.log('Введена 2');
    break;
    
  case 3:
    console.log('Введена 3');
    break;
}
```

Этот код можно запустить в консоли браузера и проверить его работу.

В этом примере мы просим пользователя записать число от 0 до 3 в переменную `number`. Затем, выполнив код, получим сообщение в консоли с введённым значением. Логика работы проста: при помощи оператора `switch` определим значение в переменной `number` и поочерёдно сравним его с каждым значением после оператора `case`; если значения совпадут, выполнится код из блока `case`. 

И самое важное в этой схеме ключевое слово — `break`! Оператор `break` завершает выполнение кода. Если не поставить `break`, то будут выполнены все команды, начиная со сработавшего `case` и до тех пор, пока либо не встретится `break`, либо не закончится весь `switch`.

И ещё один нюанс. Запустив код из примера выше, ты можешь попробовать ввести некорректное значение. Что произойдёт в таком случае? Ничего, потому что у нас нет подходящего блока `case`. Чтобы не столкнуться с проблемами в работе приложения и различными багами, хорошей практикой считается предусмотреть блок с оператором `default` — он является необязательным, но помогает обрабатывать случаи, если ни одно значение оператора `case` не подошло. Доработаем код из примера, добавим блок с оператором `default` 👇🏻

```javascript
// Запиши цифру между 0 и 3 вместо null в переменную number
const number = null;

switch (number) {
  case 0:
    console.log('Введён 0');
    break;

  case 1:
    console.log('Введена 1');
    break;

  case 2:
    console.log('Введена 2');
    break;
    
  case 3:
    console.log('Введена 3');
    break;
    
  default:
    console.log('Некорректный ввод 😔');
    break;
}
```

Теперь код сможет обработать любой ввод пользователя.

Примени `switch` для обработки маршрутов во входящих запросах 👇🏻

```javascript
const server = http.createServer((req, res) => {
  const url = req.url;
  switch (url) {
    case "/":
	    console.log("запрос по url = '/'")
      break;
    case "/game":
      console.log("запрос по url = '/game'")
      break;
    case "/vote":
      console.log("запрос по url = '/vote'")
      break;
    default:
      console.log("необрабатываемый запрос")
  }
});
```

Вуаля! Код стал выглядеть проще, теперь его легко расширять и поддерживать.

## Метод запроса `req.method`

Ещё одна распространённая ситуация: когда нужно добавить комментарий в соцсети или изменить количество лайков. В этом случае пользователь хочет внести изменения в уже существующие данные. Чтобы объяснить серверу, что от него требуется, используют различные методы: `POST`, `PUT`, `DELETE` и другие. Такие запросы могут обрабатывать по тому же `url`, что и запросы на получение данных. Например по `"/comments"` 👇🏻

- Методом `GET` можно получить данные о комментариях.
- Методом `POST` — добавить новые комментарии.

Для определения метода запроса тебе также понадобится объект `req`. Свойство `req.method` поможет выяснить, с каким намерением клиент стучится на сервер.

С играми для `url` `"/game"` мы можем обрабатывать только определённые методы — например, позволить получать данные об игре запросом с `GET`. А если пользователь по `url` `"/game"` придёт с другой целью — методом `DELETE` удалить или методом `POST` добавить игру, то дай ему понять, что у него недостаточно прав, вернув сообщение со статусом ответа 👇🏻

```javascript
const server = http.createServer((req, res) => {
  const url = req.url;
  switch (url) {
    case "/":
	    console.log("запрос по url = '/'")
      break;
    case "/game":
	    // Если метод отличается от GET, возвращаем сообщение с ошибкой
      if (req.method !== "GET") { 
        res.statusCode = 405;
        res.end("запрещённый метод запроса, по данному url доступен только GET");
      }
      console.log("отдаём информацию об игре")
      break;
    default:
      console.log("необрабатываемый запрос")
  }
});
```

Таким образом, ты обработаешь приходящий запрос, поймёшь, по какому маршруту постучались, и даже проверишь, правильный ли метод используют при обращении. А так как он нарушает внутренние правила сервера (по маршруту `"/game"` доступны только `GET`-запросы), то в ответ вернётся сообщение об ошибке с соответствующим статус-кодом.

Разрабатывая серверную логику, мы можем описать требования для запросов: какие URL-маршруты использовать, с какими методами обращаться и многое другое. Останется только тщательно проверять объект запроса и возвращать подходящие ответы. Если правила сервера будут нарушены, хорошей практикой считается вернуть подробный ответ с соответствующей [ошибкой](https://developer.mozilla.org/ru/docs/Web/HTTP/Status){target="_blank"}.

## Заголовки запроса `req.headers`

Заголовки HTTP позволяют клиенту и серверу передавать допсведения. Они могут содержать описание данных и информацию (например, о домене, сжатии, шифровании и формате данных, кодировке и др.), необходимую для взаимодействия между клиентом и сервером.

HTML-сервер, отдавая вёрстку в ответе, добавляет заголовок `res.setHeader('Content-Type': 'text/html; charset=utf-8');`, чтобы браузер клиента, определив кодировку `utf-8`, мог корректно отобразить HTML. 

В прошлых проектах мы часто обменивались данными между клиентом и сервером, для этого мы преобразовывали их в специальный формат JSON, а при отправке добавляли 👇🏻

```javascript
// Запрос от клиента

const response = await fetch(url, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' }, // Заголовок о формате данных
  body: JSON.stringify(data),
})
```

Для корректной обработки запросов и ответов важно определять, что в них хранится, ведь они могут содержать важную информацию для доступа к контенту сайта 👇🏻

```
// Запрос от клиента

const response = await fetch(url, {
  method: 'GET',
  headers: { Authorization: `Bearer ${jwt}` }, // Токен пользователя для авторизации
})
```

Всё необходимое о заголовках можно найти также в объектах запроса `req.headers` и ответа `res.headers`

## Тело запроса `req.body`

Ранее при отправке данных на сервер и обратно в формате JSON мы говорили, что получение ответа от сервера не означает получения данных. Так уж устроен протокол передачи: информация разбивается на небольшие пакеты, которые собираются воедино на стороне клиента.

Мы вызывали метод `JSON` асинхронно: нужно дождаться события загрузки данных, а затем превратить ответ в объект JSON. Для браузера получалось следующее 👇🏻

```javascript
const getData = async (url) => {
  try {
    // Отправка запроса на сервер и получение ответа
    const response = await fetch(url) 
    if (response.status !== 200) {
      throw new Error('Ошибка получения данных')
    }
    // Получение данных
    const data = await response.json()
    return data
  } catch (error) {
    return error
  }
}
```

Сначала обрабатываем приходящий ответ сервера, а потом — данные. Отсюда и асинхронный код.

### Как обрабатываются данные запроса

Нам неизвестно заранее, сколько данных отправит пользователь. При этом информация не приходит на сервер просто так — с ней нужно что-то сделать, например записать в файл.

### Как собрать данные запроса

Для работы с телом запроса есть специальная структура — поток (с англ. stream). Чтобы полностью получить тело запроса, нужно принять все блоки и склеить их.

### Что обрабатывать, когда приходит блок

Приход каждого блока — отдельное событие. Чтобы его обработать, пользуйся методом `on` объекта запроса 👇🏻

```javascript
const http = require('http');

const server = http.createServer((req, res) => {
  req.on('data', (chunk) => {
    console.log(chunk);// <Buffer 66 69 65 6c 64 3d 76 61 6c 75 65>
  });
});

server.listen(3000);
```

Событие `data`, которое мы обрабатываем, происходит при получении очередного пакета данных. Когда на сервер придёт запрос, у которого есть тело, в консоли окажутся вот такие сообщения: `<Buffer 66 69 65 6c 64 3d 76 61 6c 75 65>`. Количество сообщений зависит от размера запроса: больше данных — больше сообщений 👇🏻

{video:https://code.s3.yandex.net/kids-web/vids/M4/get_req_data.mp4|controls:true|autoplay:0|pip:false|controlsList:nodownload}

Данные из сети приходят в бинарном виде. Получить их в JavaScript мы можем благодаря спецобъекту `Buffer`

Каждый поступивший блок нужно добавлять в одну переменную. После того как придёт последний пакет, ты целиком получишь тело ответа 👇🏻

```javascript
const http = require('http');

const server = http.createServer((req, res) => {
  let data = '';

  req.on('data', (chunk) => {
    data += chunk.toString();
  });
});

server.listen(3000);
```

За последним пакетом следует событие `end`. Его и нужно обработать, чтобы превратить запрос в JSON-объект 👇🏻

```javascript
const http = require('http');

const server = http.createServer((req, res) => {
  let data = '';

  req.on('data', (chunk) => {
    data += chunk.toString();
  });

  req.on('end', () => {
    console.log(JSON.parse(data));
  });
});

server.listen(3000);
```

## Проектная работа

Теперь давай научим наш сервер для расчёта рейтинга игр обрабатывать запросы и ответы. Сделай так, чтобы на запросы из таблицы приходили соответствующие ответы. Подробный алгоритм выполнения задания есть ниже.

| Запрос | Ответ |
| --- | --- |
| `GET`: `http://localhost:3000/` | `200`, `"Спасибо за запрос, скоро придумаю, что тебе ответить"` |
| `GET`: `http://localhost:3000/game`  | `200`, `"Спасибо за запрос, скоро придумаю, что тебе ответить"` |
| `GET`: `http://localhost:3000/vote`  | `404`, `"Not Found"` |
| `POST`: `http://localhost:3000/vote с телом запроса req.body` | `200`, `"Спасибо за запрос, скоро придумаю, что тебе ответить"` |

```javascript
// Заголовок Headers

```

### Алгоритм

- В корне проекта создай файл `app.js`,  внутри которого импортируй модуль `http` и добавь сервер методом `createServer`
- В `createServer` в функции-колбэке получи значение адреса запроса из `req.url`
- Конструкцией `switch…case` обработай адреса: `"/"`, `"/game"`, `"/vote"`. Для каждого запроса методами `res.statusCode` и `res.end` сформируй ответы со статус-кодом `200` и сообщением `"Спасибо за запрос, скоро придумаю, что тебе ответить"`. Также в операторе `switch` нужно обработать вариант `default`, в котором рекомендуем отвечать статус-кодом `404` и сообщением `"Not Found"`
- В операторе `switch` для `case` с адресом `"/vote"` сделай проверку на метод запроса:

    1. Если метод отличается от `POST`, сформируй ответ со {{статус-кодом `405`}}[web_teens_theme2_lesson_5_«статус-кодом `405`»] и сообщением `"Запрещённый метод запроса"`

    2. Если запрос с методом `POST`, прочитай данные из запроса `req.body` и выведи в консоль. 

- Программой Postman протестируй сервер проекта.
