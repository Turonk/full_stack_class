Как сдать работу на проверку через GitHub Desktop

![](https://pictures.s3.yandex.net:443/resources/IMG_4988_1712565722.jpg)

{quiz-task} background: | #f1f1ef content: | ❗ Папка на твоём компьютере, в которой хранится код приложения и отслеживаются версии с помощью Git, называется **локальным** репозиторием. А место в интернете, куда отправляешь код и данные об изменениях, — **удалённый** репозиторий. {/quiz-task}

Теперь для того, чтобы код, который ты редактируешь локально, отправлялся в удалённый репозиторий, где наставник сможет его проверить, ты будешь сдавать все проектные работы через GitHub.

Шаг 1. Авторизируйся

Для начала тебе нужно связать аккаунт на GitHub с Практикумом.

На платформе Практикума в уроке «Отправляем проект на проверку» ты наткнёшься на такой интерфейс: 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1669_1712565752.png)

Нажми на кнопку `Привязать аккаунт GitHub`. Появится окно авторизации 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1670_1712565764.png)

Шаг 2. Подготовься к работе

После успешной авторизации Практикум отправит в твой аккаунт на GitHub заготовку для проектной работы. Найти её можно так:

1. В правом верхнем углу нажми на иконку своего профиля, чтобы вызвать меню 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1672_1712565789.png)

2. Перейди на страницу **Your repositories** 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1673_1712565803.png)

3. Нажми на ссылку репозитория с заготовкой работы и приступай!

Шаг 3. Сделай репозиторий публичным

Чтобы работа была видна проверяющему, необходимо сделать репозиторий публичным:

1. Открой созданный репозиторий проектной работы. По умолчанию он расположен последним в списке созданных репозиториев. 2. Перейди на вкладку **Settings** 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1674_1712565870.png)

3. Опустись в низ страницы до блока Danger Zone и нажми кнопку `Change repository visibility` 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1665_1_1712565883.png)

4. В открывшемся модальном окне выбери `Make public` и согласись со всем, что спрашивает GitHub при изменении видимости репозитория 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1675_1712565899.png)

5. После этого тебя перенаправит на главную страницу настроек репозитория. Убедись, что тип репозитория `Public`. Он указан рядом с названием на начальной странице репозитория 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1676_1712565912.png)

Если это не так, повтори все шаги.

Шаг 4. Клонируй репозиторий

Теперь открой GitHub Desktop и авторизуйся в нём, если понадобится. Для работы с проектом нужно клонировать созданный репозиторий — нажми на кнопку `Clone a Repository from the Internet` на начальном экране либо на соответствующую кнопку в меню приложения. Вот так это выглядит в меню на macOS 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1677_1712565936.png)

![](https://pictures.s3.yandex.net:443/resources/Frame_1678_1712565947.png)

Нужный репозиторий появится в списке твоих репозиториев. Смело копируй его на комп 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1679_1712565959.png)

Если всё прошло успешно, у тебя откроется окно, в котором будут отображаться все изменения в файлах 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1680_1712565972.png)

![](https://pictures.s3.yandex.net:443/resources/Frame_1681_1712565985.png)

Шаг 5. Создай ветку

Теперь нужно создать ветку `review`

{quiz-task} background: | #f1f1ef content: | ❗ Ветка (с англ. branch) — способ разделить потоки создания кода. {/quiz-task}

Основной код лежит в ветке `main`, но для промежуточной работы и проверки ревьюером нужно создать отдельную. В ней ты будешь писать свой код и проходить ревью, а когда закончишь — перенесёшь все наработки в основную ветку.

Вот как создать ветку в GitHub Desktop:

1. Нажми на кнопку `Current Branch` — откроется список веток. Пока что в ней есть только основная — `main` 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1682_1712566013.png)

2. Нажми на кнопку `New Branch` (с англ. «новая ветка»). Введи в появившемся окне название — в нашем случае подойдёт `review` 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1683_1712566025.png)

3. Чтобы отправить изменения в GitHub (отправление изменений называют «**закоммитить»**), тебе нужно будет дать заголовок этим изменениям в поле **Summary (required)**. Как придумаешь, жми на `Commit to <название ветки>` 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1684_1712566040.png)

4. Отправь изменения в GitHub, нажав на кнопку `Publish branch` справа вверху 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1685_1712566054.png)

Шаг 6. Отправь на проверку

Вот как это сделать:

1. Открой репозиторий в веб-интерфейсе GitHub. Ты увидишь предложение создать **Pull Request** на начальной странице репозитория 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1686_1712566081.png)

Не переживай: если этого баннера не будет — нажми на **Pull requests** и на открывшейся странице выбери `New pull request` 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1687_1712566094.png)

Чекай 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1688_1712566107.png)

2. В интерфейсе будет показано, какие файлы изменились в сравнении с веткой `main`. Нажми на `Create pull request` и дополни информацию о **Pull Request,** если необходимо 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1689_1712566131.png)

![](https://pictures.s3.yandex.net:443/resources/Frame_1690_1712566148.png)

3. Поздравляем! Твой пулл реквест открыт! Скопируй адрес этой страницы и вставь его в уроке 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1691_1712566161.png)

![](https://pictures.s3.yandex.net:443/resources/Frame_1692_1712566172.png)
