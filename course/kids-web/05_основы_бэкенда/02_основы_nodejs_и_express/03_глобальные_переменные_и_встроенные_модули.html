Глобальные переменные и встроенные модули

Согласны! За всё время обучения мы привыкли к тесному взаимодействию с браузером при разработке интерфейса, то есть фронтенда веб-приложений. Но, когда дело касается разработки серверных приложений, бэкенда, возникает вопрос: где же теперь браузер?

Результат работы Node.js нельзя просто так посмотреть в браузере. Тем не менее Node.js обладает множеством возможностей {{«из коробки»}}[web_teens_theme2_lesson_3_«из коробки»], которые делают процесс разработки удобным и эффективным.

В этом уроке мы разберёмся:

- какие переменные будут доступны во всём приложении, а какие — только в файлах модулей; - как создавать собственные модули и работать с ними; - как работать со встроенными модулями.

![](https://pictures.s3.yandex.net:443/resources/IMG_4912_1711449399.jpg)

Комплектация

**Глобальные переменные**

Node.js оснащён множеством полезных возможностей, одна из которых — **глобальные переменные.** Они доступны в любой части приложения и предназначены для различных целей. Список глобальных переменных можно посмотреть в терминале, выполнив команду 👇🏻

console.log(global)

Здесь `global` — это объект, внутри которого находятся все глобальные переменные.

![](https://pictures.s3.yandex.net:443/resources/Frame_1642_1_1711449471.png)

Среди них можно встретить уже знакомые `console` или `setTimeout`. Чтобы использовать глобальные переменные, Node.js предлагает несколько вариантов:

1. Обращаться к переменной через объект `global` 2. Использовать переменную напрямую

В мире Node.js, когда мы переходим из клиентской разработки в серверную, мы заменяем объект `window` на `global`. В интерфейсе браузера `window` играет важную роль, предоставляя доступ к различным инструментам, таким как `console` (для вывода в окне браузера), `alert` (всплывающее окно) и прочим. При разработке серверных приложений мы не можем взаимодействовать с браузером и вместо этого используем объект `global`, предоставляющий не только базовые инструменты, но и множество других возможностей, таких как управление производительностью и работа с событиями.

Рассмотрим на примере работы глобальной переменной `console` 👇🏻

console.log("Hello World!")
global.console.log("Hello Global World!")
// Оба варианта будут работать

В рамках курса мы не будем использовать все-все переменные из этого списка, но в свободное время ты всегда можешь изучить их и применить в своих будущих проектах.

Модульные переменные

Кроме глобальных переменных, Node.js также предоставляет возможность работать с **модульными переменными**. В отличие от глобальных переменных, модульные ограничены областью видимости текущего модуля — файла.

![](https://pictures.s3.yandex.net:443/resources/Frame_1643_1711449587.png)

{quiz-task} background: | #f1f1ef content: | ❗ Когда мы создаём модуль в Node.js (файл с расширением `.js`), использовать можно только те модульные переменные, которые доступны внутри этого модуля, что помогает избежать конфликтов в именах переменных между разными модулями. {/quiz-task}

Чтобы лучше понять различие между модульными и глобальными переменными, используем переменную `__filename` для разных модулей. Если в нашем проекте есть два модуля — `games.js` и `app.js`, то результат работы `__filename` будет разным для каждого из них 👇🏻

// В games.js
console.log(__filename) // Выведет C:/Projects/my-app/games.js

// В app.js
console.log(__filename) // Выведет C:/Projects/my-app/app.js

В отличие от глобальных переменных, модульные переменные мы будем использовать на всём пути обучения. Особенно важно научиться работать с переменной `module`. Она позволяет структурировать код и разделять его на отдельные модули, которые могут общаться между собой и делиться своими данными и функциональностью.

Работа с модулями

Разделение кода на модули обладает рядом преимуществ, включая возможность повторного использования кода, его изоляцию от других модулей, а также удобную организацию и структурирование.

Да! При экспорте мы явно указывали, что модуль предоставляет другим 👇🏻

export const Component = () => {
	// Разметка компонента	
}

При импорте — то, что модуль использует из других модулей 👇🏻

import {Component} from './components/Component'

Такой способ организации модулей называется **ES Modules** (ECMAScript Modules), сокращённо ESM, и представляет собой самый современный подход к модульной структуре кода.

В ходе развития модульности в JavaScript разработчики вносили свой вклад, создавая различные инструменты для работы с модулями. Ещё до появления ES Modules был популярен стандарт **CommonJS.** Он предназначен для использования в серверных приложениях, и почти весь Node.js построен на его основе.

Хотя ESM считается самым современным стандартом, некоторые библиотеки всё ещё ориентированы на стандарт CommonJS. В новых версиях Node.js активно внедряют поддержку ES Modules, но не все технологии успевают за этим обновлением.

CommonJS

Пришло время знакомиться со стандартом CommonJS! Важно понимать, что и ESM, и CommonJS работают похожим образом. Основное различие между ними заключается в синтаксисе и ключевых словах, которые мы используем.

Игра в монетку

Создай папку для проекта и назови её `NodeGames`. Внутри этой папки понадобится ещё одна с названием `modules` , в которой и будет находиться модуль с кодом игры.

Затем внутри папки `modules` создай файл `drop-coin.js` и помести в него код 👇🏻

// modules/drop-coin.js
function dropCoin() {
  const randomIndex = Math.floor(Math.random() * 2);

  if (randomIndex === 0) {
    return console.log("Орёл");
  } else {
    return console.log("Решка");
  }
}

Игра в монетку довольно простая и состоит из одной функции, которая генерирует случайное число от 0 до 1, а затем округляет его. После выполняется проверка, в результате которой числу 0 соответствует «орёл», а числу 1 соответствует «решка».

Чтобы функция `dropCoin` была доступна другим, а сам `drop-coin.js` стал полноценным модулем, экспортируй функцию по стандарту CommonJS. Для этого добавь настройки экспорта в самом конце файла, после функции.

Чекай 👇🏻

// modules/drop-coin.js
function dropCoin() {
  const randomIndex = Math.floor(Math.random() * 2);

  if (randomIndex === 0) {
    return "Орёл";
  } else {
    return "Решка";
  }
}

module.exports = dropCoin;

Здесь ты используешь сразу две модульные переменные — `module` и `exports`, чтобы приложение понимало, что из этого модуля нужно экспортировать функцию `dropCoin`

Теперь можно переходить к созданию главного исполняемого файла — `script.js`. Так как это основной файл всего приложения, он не должен находиться в папке `modules`, создавать его лучше в корневой папке всего проекта, внутри `NodeGames`

Чтобы импортировать модуль игры в основной файл `script.js`, воспользуйся модульной переменной `require()` 👇🏻

// script.js
const dropCoin = require('./modules/drop-coin.js');

Здесь для хранения функции игры создай переменную `dropCoin`. И сообщи приложению поместить в эту переменную функцию `dropCoin` из файла `drop-coin.js`

Наконец, можно вывести результат работы функции в консоль 👇🏻

// script.js
const dropCoin = require('./modules/drop-coin.js')

console.log(dropCoin());

Отлично! Пришло время запустить твою игру, используя команду `node script.js`. Важно помнить, что на Node.js мы создаём серверные приложения, а значит, результат функции `dropCoin` будет отображаться в консоли VS Code, а не в консоли браузера. Вот смотри 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1645_1711449782.png)

Тонкости CommonJS

Как в ESM, так и в CommonJS существует несколько способов экспорта и импорта. В предыдущем примере мы использовали подход, который позволяет экспортировать из модуля `drop-coin.js` одну-единственную функцию `dropCoin`. Но, если в модуле будет несколько функций или переменных, стоит использовать другой подход.

Для экспорта нескольких элементов следует поместить их в объект, а для импорта провести {{деструктуризацию}}[web_teens_theme2_lesson_3_деструктуризацию] этого объекта, чтобы получить доступ ко всем необходимым переменным и функциям. Визуализируем 👇🏻

Точки входа

Для поддержания качественной структуры твоих проектов, создание отдельной папки `modules` — хорошая практика. В примере выше мы создали эту папку и поместили в неё модуль с игрой в монетку, но с появлением новых модулей с другими играми мы можем столкнуться с потенциальной проблемой.

{quiz-task} background: | #f1f1ef content: | ❗ Папка `modules` не резиновая, поэтому добавление огромного количества модулей может привести к путанице. Важно подходить к структуре проекта с умом, чтобы избежать **модульной каши** и не запутаться в проекте. {/quiz-task}

Для решения этой проблемы хорошо бы научиться группировать модули по смыслу внутри единой папки `modules`. Представим, что кроме игры в монетку у нас появился ещё один модуль с игрой в кубик — `roll-dice.js` 👇🏻

// modules/roll-dice.js
function rollDice() {
  const result = Math.floor(Math.random() * 6) + 1;
  return result;
}

Игра в кубик даже проще, чем игра в монетку, и состоит из одной функции, которая генерирует случайную цифру от нуля до шести. Затем функция возвращает цифру как результат своей работы.

Обе эти игры объединяют рандомные вычисления, которые они проводят:

- Игра в монетку выбирает одну из сторон монеты. - Игра в кубик выбирает одну из шести сторон кубика.

Можно объединить эти модули по смыслу, создав папку `randomizers` внутри папки `modules`, а затем переместить в неё оба модуля.

![](https://pictures.s3.yandex.net:443/resources/Frame_1646_1711449865.png)

Гуд! Структура преобразилась, но, чтобы импортировать обе игры из папки `randomizers` в `script.js`, потребуется два импорта 👇🏻

// script.js
const dropCoin = require('./modules/randomizers/drop-coin.js')
const rollDice = require('./modules/randomizers/roll-dice.js')

Чтобы решить проблему большого количества импортов, можно создать **точку входа** для директории `randomizers`. Этим файлом станет `index.js`, который будет содержать в себе все модули папки `randomizers` и делать их доступными для других модулей в виде объекта. Индексные файлы служат оглавлением для всех модулей в определённой директории.

Для директории `randomizers` файл `index.js` будет выглядеть так 👇🏻

// modules/randomizers/index.js
const dropCoin = require('./drop-coin.js')
const rollDice = require('./roll-dice.js')

module.exports = {
	dropCoin,
	rollDice
}

Структура проекта вновь преобразилась.

![](https://pictures.s3.yandex.net:443/resources/Frame_1647_1711449939.png)

Теперь в файле `script.js` импортировать все игры из директории `randomizers` можно одной строкой 👇🏻

const { dropCoin, rollDice } = require("./modules/randomizers");

Обрати внимание, что в конце пути мы не указываем конкретный файл `index.js`, а просто останавливаемся на указании директории `randomizers`. Здесь важно понимать принцип работы индексных файлов.

Встроенный модуль `readline`

Создание собственных модулей — это важно, но Node.js уже поставляется со множеством встроенных модулей, готовых к использованию. Умение работать с модулями «из коробки» позволяет писать код, используя готовые инструменты, а не создавать их самостоятельно. Изучая Node.js, мы познакомимся со множеством модулей, но начать это путешествие стоит с простого и полезного инструмента — модуля `readline`

В процессе разработки интерфейса мы привыкли к различным методам взаимодействия с пользователем в браузере. Например, на клиентской стороне пользователь может вводить информацию через теги `<input>` в формах или использовать всплывающее окно, созданное инструментом `prompt` в JavaScript.

{quiz-task} background: | #f1f1ef content: | ❗ В мире серверных приложений вариантов взаимодействия с пользователем гораздо меньше. Один из основных способов — это ввод информации в терминал, который доступен благодаря модулю `readline` {/quiz-task}

Прежде всего, нужно подключить модуль, используя переменную `require()`👇🏻

const readline = require('readline');

Подключая встроенные модули Node.js, не обязательно указывать конкретный путь, ведь Node.js уже знает, где искать свои встроенные модули. Вместо этого достаточно указать название нужного модуля.

Чтобы `readline` мог взаимодействовать с вводом и выводом, нужно использовать интерфейс. Это своего рода посредник между нашим кодом и тем, что вводит пользователь и что должно ему выводиться в ответ. Для этого используем метод `createInterface` 👇🏻

const readline = require('readline');

const myInterface = readline.createInterface();

Модуль `readline` — очень гибкий инструмент, который можно настроить под самые разные задачи. Для этого передадим в метод `createInterface` объект с нужными опциями 👇🏻

const readline = require('readline');

const myInterface = readline.createInterface({
  input: process.stdin,
  output: process.stdout,
  terminal: false,
  prompt: "",
});

Рассмотрим каждую из опций подробнее:

- `input: process.stdin` — обязательный параметр, который указывает, что вводить информацию пользователь будет стандартным способом, через свой терминал. - `output: process.stdout` — обязательный параметр, который указывает, что ответ на ввод пользователя будет выводиться также в его терминал. - `terminal: false` — необязательный параметр, который предотвращает дублирование символов в случае использования нескольких экземпляров `readline` - `prompt: ""` — необязательный параметр, который устанавливает символ, отображаемый перед вводом пользователя. В данном случае мы установили пустую строку, но обычно используется символ `>`, чтобы визуально обозначить, что пользователь уже может вводить данные.

Теперь интерфейс модуля настроен и готов к использованию. Обработай ответ пользователя, используя метод `question` 👇🏻

myInterface.question("Как тебя зовут?", (name) => {
  console.log(`Привет, ${name}!`);
});

Здесь метод принимает в себя вопрос в виде строки и функцию, которая должна выполниться после этого вопроса. Так, после вопроса «Как тебя зовут?» пользователь введёт своё имя, а затем выполнится функция, которая выведет сообщение с именем пользователя. Проверяй 👇🏻
