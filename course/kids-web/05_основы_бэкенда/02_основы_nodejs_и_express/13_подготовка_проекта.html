Обработка файлов

Первым шагом создай папку `appModules` в корне проекта — она послужит фундаментом для всех будущих модулей приложения. Мы собираемся обрабатывать HTTP-запросы, поэтому логично добавить ещё папку с названием `http-utils` в основной `appModules`

Перед тем как наполнять модуль `http-utils` крутыми и важными элементами кода, узнаем подробнее, как должна работать функция обработки статических файлов:

1. Функция принимает в себя путь до нужного файла, его расширение и объект ответа `res` 2. Затем устанавливается заголовок `Content-Type` в объекте ответа, чтобы таким образом сообщить браузеру, какой тип файла ему будет отправлен. 3. После этого асинхронно считывается файл по указанному пути. 4. Если в процессе чтения файла возникает ошибка (к примеру, файл не найден), функция устанавливает статус (код ответа `404`) и отправляет сообщение `Not Found`. Это говорит браузеру, что требуемый файл не был найден на сервере. 5. Если же файл успешно прочитан, его содержимое отправляется в теле ответа браузеру, завершая обработку запроса.

Верно! В папку `http-utils` добавь файл `mime-types.js` и размести внутри него следующий код 👇🏻

const mimeTypes = {
  ".html": "text/html",
  ".css": "text/css",
  ".js": "text/javascript",
  ".json": "application/json",
  ".png": "image/png",
  ".jpg": "image/jpg",
  ".gif": "image/gif",
  ".svg": "image/svg+xml",
  ".wav": "audio/wav",
  ".mp4": "video/mp4",
  ".woff": "application/font-woff",
  ".ttf": "application/font-ttf",
  ".eot": "application/vnd.ms-fontobject",
  ".otf": "application/font-otf",
  ".wasm": "application/wasm",
  ".ico": "image/x-icon",
  ".xlsx": "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
};

module.exports = mimeTypes;

Сам по себе MIME-тип — это стандарт, который указывает тип данных, содержащихся в файле, чтобы браузеры могли правильно его обработать. Каждый ключ в этом объекте — это расширение файла (например, `.html` или `.css`), а значение — соответствующий MIME-тип (например, `text/html` или `text/css`). Они используются в функции обработки статических файлов для того, чтобы приложение могло автоматически указывать тип контента при отправке файла клиенту.

Теперь создай файл `static-file.js` в папке `http-utils`. В нём и будет содержаться функция для обработки статических файлов. Для начала импортируй модули: `fs` — для чтения файлов, `mimeTypes` — для установки типа контента 👇🏻

const fs = require("fs");
const mimeTypes = require("./mime-types");

Ниже создай одноимённую функцию, код которой выглядит так 👇🏻

function staticFile(res, filePath, ext) {
  res.setHeader("Content-Type", mimeTypes[ext]);
  fs.readFile("./public" + filePath, (err, data) => {
    if (err) {
      res.statusCode = 404;
      res.end("Not Found");
    }
    res.end(data);
  });
}

module.exports = staticFile;

Здесь, обращаясь к объекту ответа `res`, мы устанавливаем заголовок `Content-Type`. Чтобы установить правильный тип контента, нужно соотнести расширение файла, переданное через аргумент `ext`, с полями объекта `mimeTypes`

Затем, обращаясь к модулю `fs`, считываем содержимое файла, указывая в качестве пути основную папку со статическим контентом `public` и добавляя к ней путь до самого файла, переданный через аргумент `filePath`

Отображение интерфейса

Супер! Теперь, когда функция для работы с файлами на месте, пора её проверить. Заметь, что в `app.js` мы уже используем `switch` для управления разными маршрутами — подробности об этом ты найдёшь в уроке «Запрос, ответ, ошибка».

Итак, перейди в файл `app.js`, импортируй созданную функцию `staticFile` и примени её для обработки запросов к главному маршруту `/` 👇🏻

// ...импорты и настройки

const server = http.createServer((req, res) => {
  const url = req.url;
  switch (url) {

Перед вызовом функции важно обратиться к объекту `res` и установить статус-код `200`

Да, в качестве параметров функции `staticFile` мы передаём объект `res`, путь до главной страницы интерфейса `"/index.html"`, ну и, конечно же, расширение этого файла `".html"`

Обработка исключений

Если сейчас запустить приложение и перейти на `localhost:3005`, страница будет грузиться бесконечно, а интерфейс так и не отобразится. Это происходит потому, что, хотя наше приложение и может отдать файл `index.html`, сама HTML-страница пытается загрузить стили и скрипты через теги `link` и `script`. Когда сервер получает подобные запросы, он не понимает, как их распознавать.

Чтобы решить эту проблему, нужно добавить обработку подобных запросов в `default`-секцию конструкции `switch`. В ней используем модуль `path` для определения расширения запрашиваемого файла. Затем проверим, соответствует ли это расширение известным MIME-типам, и, если да, отправим нужный файл обратно в браузер.

Самостоятельно импортируй модуль `path` и объект `mimeTypes` в файл `app.js`. Для этого обратись к секции `default` и напиши код функции 👇🏻

const server = http.createServer((req, res) => {
  const url = req.url;
  switch (url) {
		// ...другие маршруты
		default:
			const extname = String(path.extname(url)).toLowerCase();
		  if (extname in mimeTypes) {
		    staticFile(res, url, extname);
		  } else {
		    res.statusCode = 404;
		    res.end("Not Found");
		  }
  }
});

Сначала мы используем модуль `path` из Node.js, чтобы получить расширение файла из URL-запроса. К примеру, если запрошен URL `/style.css`, `path.extname(url)` вернёт `.css`. Полученное расширение файла приводим к строке и делаем все буквы строчными (маленькими), чтобы избежать проблем с регистром.

Затем проверяем, есть ли расширение файла в объекте `mimeTypes`, который содержит соответствия расширений файлов и их MIME-типов. Это нужно, чтобы убедиться, что мы можем обработать запрошенный тип файла.

Если расширение файла найдено в `mimeTypes`, вызываем функцию `staticFile`, которая отправит запрошенный файл обратно в браузер. Если же расширение файла не найдено в `mimeTypes`, устанавливаем в ответе статус-код `404` и отправляем сообщение `Not Found`, сообщая браузеру, что запрошенный ресурс не может быть найден.

Распределение обязанностей

По мере роста приложения объём кода также увеличивается. Когда конструкция `switch` становится всё больше и больше, читать код внутри неё гораздо труднее.

Всё верно! Так можно оставить настройку доступных маршрутов конструкции `switch`, а обрабатывать запросы к этим маршрутам будут специальные функции, которые назвали **контроллерами**.

Из названия уже понятно: именно они **контролируют** реакцию приложения на различные запросы. В следующих темах мы лучше познакомимся с контроллерами и их возможностями. А пока давай создадим такие функции для обработки запросов к основному маршруту `/` и обработки исключений — для тех случаев, когда запрос не соответствует ни одному из определённых маршрутов.

Создай папку `controllers` в корне проекта. Первый контроллер будет как раз для основного маршрута. В новую папку добавь пока ещё пустой файл `main.js` и импортируй в него функцию `staticFile`, которая понадобится для его работы 👇🏻

const staticFile = require("../appModules/http-utils/static-file");

Далее создай саму функцию-контроллер, передав ей три знакомых аргумента 👇🏻

function mainRouteController(res, publicUrl, extname) {}

В тело функции перенеси код, который уже написали в конструкции `switch`. В конце не забудь экспортировать модуль, чтобы можно было использовать его в файле `app.js` 👇🏻

async function mainRouteController(res, publicUrl, extname) {
  res.statusCode = 200;
  staticFile(res, publicUrl, extname);
}
module.exports = mainRouteController;

Перейди в файл `app.js`, импортируй контроллер и вместо кода внутри секции `case “/”` просто вызови его ещё раз, передав нужные аргументы 👇🏻

// ...импорты и настройки

const server = http.createServer((req, res) => {
  const url = req.url;
  switch (url) {
    case "/":
			mainRouteController(res, "/index.html", ".html");
      break;
    // ...другие маршруты
  }
});

Советуем поместить его в папку `controllers`, предварительно назвав файл `default.js`, а саму функцию сделать асинхронной — `defaultRouteController`

const path = require("path");
const staticFile = require("../appModules/http-utils/static-file");
const mimeTypes = require("../appModules/http-utils/mime-types");

async function defaultRouteController(res, url) {
  const extname = String(path.extname(url)).toLowerCase();
  if (extname in mimeTypes) {
    staticFile(res, url, extname);
  } else {
    res.statusCode = 404;
    res.end("Not Found");
  }
}

module.exports = defaultRouteController;

В файле `app.js` 👇🏻

const server = http.createServer((req, res) => {
  const url = req.url;
  switch (url) {
		// ...другие маршруты
		default:
			defaultRouteController(res, url);
  }
});

Пора это исправить!

Игры в нашем приложении нужно где-то хранить. С базами данных мы познакомимся в следующих темах, а пока создадим своё локальное хранилище. В корне проекта создай папку `dataset`, а внутри неё файл `rating.json`, в который помести небольшую заготовку 👇🏻

[
  {
    "id": 5,

Когда интерфейс загружается, он отправляет запрос к нашему серверу по адресу `/game`, чтобы получить данные об игре и показать их на странице. Наша задача — настроить обработку таких запросов, реализовав следующую логику:

- После получения запроса функция асинхронно прочитает содержимое файла `rating.json`, который находится в папке `dataset` - Если при чтении файла произойдёт ошибка, в ответ браузеру функция отправит статус-код `500` с сообщением `Internal Server Error`. Для браузера это будет означать, что запрос не может быть обработан из-за проблем на стороне серверного приложения. - Если чтение файла пройдёт успешно, его содержимое, которое представляет собой строку в формате JSON, преобразуется в JavaScript-код для удобной работы с данными. - Далее функция выберет первую игру из массива преобразованных данных (в нашем случае это единственная игра). - Прежде чем отправить данные об игре, функция установит заголовок с типом контента, сообщив браузеру, что в теле ответа он получит данные в формате JSON. - После этого информация о первой игре конвертируется обратно в строку JSON и отправляется браузеру. В свою очередь браузер, получив ответ, считает данные игры и отобразит их в интерфейсе.

Как мы уже выяснили, логику обработки запросов лучше писать в отдельных функциях-контроллерах. В папке `controllers` создай файл для нового контроллера — `game.js`

Для асинхронного чтения файла импортируй встроенный модуль `fs` 👇🏻

const fs = require("fs");

Затем пропиши логику работы 👇🏻

async function gameRouteController(res) {
  fs.readFile("./dataset/rating.json", (err, ratingFile) => {
    if (err) {
      res.statusCode = 500;
      res.end("Internal Server Error");
    }
    const data = JSON.parse(ratingFile);
    const game = data[0];
    res.setHeader("Content-Type", "application/json");
    res.end(JSON.stringify(game));
  });
}

В этом контроллере мы обрабатываем запрос без тела, поэтому используем только объект ответа `res`. Используя метод `readFile` из модуля `fs`, мы асинхронно читаем файл и получаем его содержимое в переменную `ratingFile`. Это содержимое передаётся в функцию обратного вызова (колбэк).

Внутри колбэка первым делом проверяем наличие ошибок при чтении файла. Если чтение прошло успешно, используем `JSON.parse` для преобразования данных. Из полученного массива данных выбираем {{первый элемент}}[web_teens_theme2_lesson_7_первый элемент], который содержит информацию об игре, и сохраняем его в переменную `game`

Затем устанавливаем заголовок `Content-Type` в `application/json`, чтобы указать, что отправляемые данные будут в формате JSON. В конце конвертируем объект `game` обратно в строку JSON, используя `JSON.stringify`, и отправляем его браузеру в ответе.

Наконец, экспортируй модуль, чтобы использовать его по нужному маршруту в `app.js` 👇🏻

module.exports = gameRouteController;

В конструкции `switch` для секции обработки маршрута `/game` вызови контроллер, передав ему объект ответа `res` 👇🏻

const server = http.createServer((req, res) => {
  const url = req.url;
  switch (url) {
    // ...другие маршруты

Обработка критериев рейтинга

Сейчас наш интерфейс показывает только одну игру, но пользователи уже могут оценить её, выставляя баллы по трём критериям: геймплей, дизайн и оригинальность идеи. Оценки по этим критериям — это цифры от 1 до 5. Когда пользователь заполняет оценки и нажимает на кнопку `Проголосовать`, из браузера отправляется `POST`-запрос обратно к серверу по маршруту `/vote`. Наш сервер должен уметь принимать эти данные и корректно обрабатывать их, чтобы формировать итоговый рейтинг.

Как мы выяснили в уроке «Запрос, ответ, ошибка», передача данных от клиента к серверу — это процесс, в ходе которого данные приходят постепенно, частями. Чтобы собрать все части вместе, у нас уже есть небольшая логика в конструкции `switch`

В папке `http-utils` создай файл `parse-body.js`, внутри которого объяви функцию `parseBody`. Собирая пакеты, она будет передавать их в колбэк — функцию, которая выполнится после завершения операции чтения 👇🏻

function parseBody(req, callback) {
  let body = "";
  req.on("data", (chunk) => {
    body += chunk.toString();
  });
  req.on("end", () => {
    callback(null, body);
  });
}

Функция принимает объект запроса `req`, а также следующую функцию — `callback`. Переменная `body` накапливает в себе части данных при каждом событии `data` во время запроса. Когда процесс обработки завершается, вызывается колбэк, в который передаётся тело запроса без ошибок. Добавим логику для события `error`, чтобы функция могла отловить возникшую ошибку и передать её в колбэк, не передавая при этом тело запроса.

В конце не забудь экспортировать функцию 👇🏻

function parseBody(req, callback) {
	// Код функции
  req.on("error", (error) => {
    callback(error, null);
  });
}

module.exports = parseBody;

Чтобы прочитать критерии рейтинга, которые интерфейс отправляет по маршруту `/vote`, создай новый контроллер специально для этого маршрута. В папку `controllers` добавь файл `vote.js` и импортируй в него функцию `parseBody` 👇🏻

const parseBody = require("../appModules/http-utils/parse-body");

Функция-контроллер будет считать тело запроса асинхронно, поэтому используй ключевое слово `async` перед объявлением функции. В качестве аргументов принимаются объект запроса `req` и объект ответа `res`, чтобы ответить браузеру, как прошёл запрос 👇🏻

async function voteRouteController(req, res) {}

Сначала нужно убедиться, что запрос к серверу был сделан правильным способом, а именно через `POST`-запрос. Это важно, поскольку именно таким методом должны отправляться данные на сервер. Для этой проверки обратись к свойству `method` в объекте запроса `req`. Если метод запроса не соответствует `POST`, установи статус-код `404` с сообщением `Not Found`, указывая браузеру, что такой запрос не может быть обработан 👇🏻

async function voteRouteController(req, res) {
  if (req.method !== "POST") {
    res.statusCode = 404;
    res.end("Not Found");
  }
}

Если метод запроса нам удовлетворяет, вызовем функцию `parseBody`. Этой функции передай два аргумента: объект запроса `req` и колбэк-функцию. Самой колбэк-функции нужно сообщить два параметра: `err` для обработки возможных ошибок и `body` для работы с телом запроса. Функция `parseBody` асинхронно обработает тело запроса и выполнит колбэк после завершения 👇🏻

async function voteRouteController(req, res) {
  // Код функции
  parseBody(req, (err, body) => {
	  
  });
}

Внутри этого колбэка мы сначала проверим наличие ошибок. Если в процессе чтения тела запроса возникла ошибка, установи статус-код ответа `500` с сообщением `Internal Server Error`, сигнализируя о внутренней ошибке сервера.

В случае если ошибок нет, просто выведи содержимое тела запроса в консоль для демонстрации и отправь браузеру обратно статус-код ответа `200` с подтверждением операции сообщением `Success!` 👇🏻

async function voteRouteController(req, res) {
  // Код функции
  parseBody(req, (err, body) => {
    if (err) {
      res.statusCode = 500;
      res.end("Internal Server Error");
    }
    console.log(body);
    res.statusCode = 200;
    res.end("Success!");
  });
}

Самостоятельно экспортируй модуль и импортируй его в файл `app.js`. Внутри конструкции `switch` вызови новый контроллер для обработки запросов к маршруту `/vote`, передав нужные аргументы 👇🏻

// ...импорты и настройки

const server = http.createServer((req, res) => {
  const url = req.url;
  switch (url) {
    // ...другие маршруты
    case "/vote":
			voteRouteController(req, res);
      break;
    // ...другие маршруты
  }
});
