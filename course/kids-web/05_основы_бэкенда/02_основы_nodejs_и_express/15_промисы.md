## Немного о промисах

Давай вспомним, как `promise` помогает работать с асинхронными операциями на примере хорошо знакомой тебе функции `fetch`, которая доступна и в Node.js тоже. 

**Сетевой запрос** — это яркий пример асинхронной операции. Программа выполняет запрос и ждёт, пока адресат что-нибудь ответит. В зависимости от скорости соединения время ожидания может быть разным. Именно поэтому функция `fetch` возвращает не непосредственный результат запроса, которым ответил адресат, а объект `promise`, то есть обещание, что рано или поздно ответ прилетит.

Смотри, как это выглядит в коде 👇🏻

```javascript
/**
 * Команда fetch делает сетевой запрос — асинхронную операцию
 * Результат вызова fetch — объект Promise, то есть обещание, что на запрос рано или поздно будет получен ответ
 * promiseFromFetch — переменная, в которую мы сохранили это обещание
 */
const promiseFromFetch = fetch('https://api-code-2.practicum-team.ru/games')
```

Как только обещание было создано, оно находится в состоянии `pending` — ожидание, когда же выполнится асинхронная операция, для которой это обещание было создано.

Аски шутит! JavaScript всегда выполняет промисы, и тебе уже известны два способа, как можно обработать результат их работы. Если подзабылось, можешь освежить в своей памяти, открыв тогглы с кодом 👀

```javascript
/**
 * Команда fetch делает сетевой запрос — асинхронную операцию
 * Результат вызова fetch — объект Promise, то есть обещание, что на запрос рано или поздно будет получен ответ
 * promiseFromFetch — переменная, в которую мы сохранили это обещание
 */
const promiseFromFetch = fetch('https://api-code-2.practicum-team.ru/games')

/**
 * В then передаётся обработчик результата выполнения обещания 
 * В catch передаётся обработчик ошибки при выполнении обещания
 */
promiseFromFetch
    .then((result) => {
        console.log(result)
    })
    .catch((error) => {
        console.log(error)
    })
```

Когда обещание выполнено, оно переходит в состояние `fulfilled` и вызывается обработчик `then`, если после обещания успешно был получен результат, или обработчик `catch`, если в процессе выполнения обещания была получена ошибка.

Кроме `then` и `catch` существует ещё один способ обрабатывать результат обещания — это синтаксис `async await`. Модифицируя пример выше, получим следующее 👇🏻

```javascript
// Командой async говорим, что getData — асинхронная функция
async function getData() {
    try {
        // Командой await дожидаемся результата выполнения асинхронной функции fetch
        const response = await fetch('https://api-code-2.practicum-team.ru/games');
    } catch (error) {
        console.log(error);
    }
}
```

Стоит помнить, что любая функция, в названии которой указано `async`, возвращает объект Promise. Конструкцию `try`/`catch` мы используем для обработки ошибок. Если в коде в блоке `try` возникнет ошибка, то выполнение программы перейдёт в блок `catch`

## Добавляем работу с файлами на сервере

Давай сделаем так, чтобы можно было не просто логировать список игр, который загрузили с помощью `getData`, но и записывать его в файл.

В прошлом уроке «Синхронность и асинхронность» мы рассказывали про такой способ обработки асинхронных операций, как `callback`, а также про `callback hell` (ад из колбэков 🥵), который они могут создавать. Решение этой проблемы — использовать промисы вместо колбэков. 

Мы уже несколько раз встречались c асинхронными функциями `readFile` и `writeFile` из модуля `fs` для чтения из файла и записи в файл. Существует версия модуля `fs`, где функции `readFile` и `writeFile` возвращают промис, который можно обрабатывать с помощью `then`/`catch` или `await`. Разбираться проще на примере 👇🏻

```javascript
// Импортируем модуль fs, в котором функции возвращают промис
const fs = require('fs').promises;

// Читаем файл асинхронной функции readFile
fs.readFile('data.json', { encoding: 'utf8' })
	// Когда промис разрешится успешно, сработает обработчик в then, в который будут переданы прочитанные данные
  .then((data) => {
    console.log(data);
  })
  // Если промис разрешится с ошибкой, сработает обработчик в catch, куда будет передана ошибка
  .catch(err => {
    console.log(err);
  });
```

Итак, вернёмся к проекту с сервером для составления интересного рейтинга игр. В данный момент в контроллере `mainRouteController` мы просто логируем список игр, который загрузили с помощью `getData`. Также у нас есть файл `dataset/rating.json`. Мы могли бы записывать полученный список игр в этот файл командой модуля `fs`, функции которого возвращают промис. 

Для это нам понадобится сделать ещё один модуль `appModules/rating` и в нём файл `rating-file.js`, где будет лежать функция `makeRatingFile`. Её задача — принимать на вход путь к файлу, в который надо записать сам список игр.

```javascript
const fs = require("fs").promises;

/**
 * path — путь к файлу
 * array — список игр
 */
async function makeRatingFile(path, array) {
  // Читаем содержимое файла по пути path. ratingFile — строка со всем содержимым файла
  const ratingFile = await fs.readFile(path, "utf8");
  // Так как ratingFile — строка, то преобразуем её в json
  const ratingArray = JSON.parse(ratingFile);

  // Код далее повторяем для каждой игры из списка игр
  array.forEach((item) => {
    // Если в ratingArray ещё нет игры с таким id,
    if (!ratingArray.find((el) => el.id === item.id)) {
      let obj = {
        id: item.id,
        title: item.title,
        image: item.image,
        link: item.link,
        description: item.description,
        rating: 0,
      };
      // добавляем её к уже существующему списку игр
      ratingArray.push(obj);
    }
  });

  // Обновим список игр в файле по пути path, записав туда обновлённый массив ratingArray
  await fs.writeFile(path, JSON.stringify(ratingArray));
}

module.exports = makeRatingFile;
```

В модуле `appModules/rating` нужно создать файл `config.js`, откуда ты будешь экспортировать строку — путь к файлу `rating.json`. Чекай 👇🏻

Не у всех функций в JavaScript есть версии, которые возвращают `promise`. Например, функция `parseBody`, которую мы используем в проекте для обработки результата запроса. Пока что она принимает `сallback`, сейчас же ты промисифицируешь её, то есть сделаешь так, чтобы она возвращала `promise`, который разрешится, когда будут обработаны все данные запроса.

```javascript
function parseBody(req) {
  // Фукнция parseBody возвращает Promise, созданный с помощью конструктора
  return new Promise((resolve, reject) => {
    let body = "";
    req.on("data", (chunk) => {
      body += chunk.toString();
    });
    req.on("end", () => {
      // Как только обработали все данные, успешно разрешаем Promise
      resolve(body)
    });
    req.on("error", (error) => {
      // Если в процессе возникла ошибка, то разрешаем Promise с ошибкой
      reject(error)
    });
  })
}
```
