Node.js, версии, запуск скриптов

Давай ещё раз закрепим. Несмотря на всю кажущуюся сложность, которая скрывается за словом **сервер,** он всего лишь компьютер с операционной системой. Любой ноутбук или стационарный ПК может быть сервером, в том числе тот, на котором ты сейчас читаешь этот урок.

Конечно! Для этого сначала мы научимся писать программы на JavaScript и запускать их на компьютере, а не в браузере (как в прошлых модулях). У тебя может возникнуть вопрос: зачем всё усложнять, почему бы не запускать любой JS-код в браузере, ведь работает же? Так вот, сервер — это не просто комп, а **комп, на котором нет браузера.**

JavaScript для сервера

Предположим, что у нас на компьютере есть файл `script.js` с очень простым JS-кодом `console.log(2+2)`. Чтобы компьютер мог прочитать и выполнить код из этого файла, ему необходим специальный инструмент — Node.js.

Отличия JS в браузере и на сервере

Несмотря на то что и в браузере, и на сервере выполняется код, написанный на одном и том же языке, есть различия в том, какими элементами языка мы можем пользоваться, когда кодим для браузера, и какими — для сервера.

Поговорим об объекте `window`, доступном исключительно в браузере, содержащем множество инструментов, необходимых для работы с ним.

Чекай скринкаст 👇🏻

{video:https://code.s3.yandex.net/kids-web/vids/M4/Screen_Recording_2024-02-29_at_09.24.34.mp4|controls:true|autoplay:0|pip:false|controlsList:nodownload}

Давай пройдёмся по основным моментам. Сначала мы залогировали объект `window` в консоли. Дальше с помощью `window.location` воспользовались функцией `href` и получили адрес страницы, на которой находимся. Адресная строка браузера — вещь, существующая только в браузере, объект `window` позволяет получить к ней доступ из JS.

Да, само по себе хранилище `localStorage` — это инструмент для хранения данных в браузере. Для работы с ним через JS существует `window.localStorage`

Теперь перейдём к серверу. На сервере нет браузера, а значит, нет адресной строки, хранилищ типа `localStorage` и вообще всего, что встроено в браузер, — соответственно, нет никакого объекта `window`. Глянь 👇🏻

{video:https://code.s3.yandex.net/kids-web/vids/M4/Screen_Recording_2024-02-29_at_09.39.25.mp4|controls:true|autoplay:0|pip:false|controlsList:nodownload}

В остальном на сервере тот же самый JS, что и в браузере. К тому же на сервере есть свои задачи, которые необходимо решать с помощью JS-кода, например чтение и запись файлов, которые лежат в файловой системе компьютера.

Пара слов о Node.js

Всё так! И для того, чтобы Node.js мог выполнять самый современный JS, у него существуют версии, в которых разработчики добавляют поддержку последних стандартов языка. Полный список версий Node.js с датами выхода можно увидеть [тут](https://nodejs.org/en/about/previous-releases){target="_blank"}.

Какую версию Node.js использовать — вопрос, за которым в процессе разработки постоянно приходится следить. Существуют сторонние библиотеки и целые программы, которые могут работать только с какой-то определённой версией Node.js. Для того чтобы каждый раз не заниматься переустановкой, есть специальные инструменты, например `nvm`, позволяющий одной командой изменить версию Node.js на ту, которая нужна тебе в проге.
