Подготовка к отправке

Для отправки потребуется создать новый репозиторий в GitHub.

Войди в свою учётную запись, в правом боковом меню перейди на вкладку `Your repositories`, а затем нажми на зелёную кнопку с надписью `New` 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Untitled_2_1712747170.png)

При создании репозитория придумай понятное название, описывающее проект. Базовые настройки менять не нужно, стоит только убедиться в том, что созданный репозиторий будет типа `Public`, то есть открытым для просмотра другим пользователям. Чуть ниже настроек нажми кнопку `Create repository` 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Untitled_3_1712747187.png)

После того как репозиторий отобразится, добавь одноимённую папку для проекта, но не торопись переносить в неё все файлы приложения. Пока просто открой новую папку в VS Code, чтобы с ней можно было работать.

Вводить команды и работать с Git удобнее прямо в терминале VS Code, поэтому создай экземпляр терминала Git Bash, как показано на видео 👇🏻

{video:https://code.s3.yandex.net/kids-web/vids/term.mp4|controls:true|autoplay:0|pip:false|controlsList:nodownload}

Взаимодействовать с гитхабом мы будем новым безопасным способом — через `ssh`. Об этом протоколе мы уже говорили в уроке «Протоколы: `http`, `https`, `ssh`», если что, загляни и освежи в памяти материал.

Для начала нужно сгенерировать ключи — действия отличаются в зависимости от операционной системы. Лови инструкции 👇🏻

Введи команду, заменив `email@example.ru` на свой email, используемый в GitHub 👇🏻

ssh-keygen -t ed25519 -C "email@example.ru"

Система спросит, где сохранить ключ, нажми `Enter`, чтобы использовать предложенное по умолчанию расположение. Также при создании ключа система предложит ввести парольную фразу — этот вопрос можно пропустить, нажав `Enter`

После этого необходимо добавить ключ в спецслужбу `ssh-agent`. Запусти её следующей командой 👇🏻

eval "$(ssh-agent -s)"

Добавь свой SSH-ключ в службу `ssh-agent` командой 👇🏻

ssh-add ~/.ssh/id_ed25519
ssh-keygen -t rsa

После добавления необходимо скопировать содержимое ключа в буфер обмена 👇🏻

clip < ~/.ssh/id_ed25519.pub
pbcopy < ~/.ssh/id_rsa.pub

Перейди в свой профиль на гитхабе и в правом боковом меню выбери раздел `Settings`. В самом разделе выбери пункт `SSH and GPG keys`. Затем нажми зелёную кнопку `New SSH key` 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1695_1712934777.png)

В появившейся форме добавления ключа в поле `Title` введи название устройства, с которого ты добавляешь ключ, к примеру `My Laptop`. В поле `Key` вставь содержимое ключа, которое автоматически скопировалось после команды выше. Должно получиться вот так 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1696_1712934799.png)

Наконец, нажми кнопку `Add SSH key`, после которой ты увидишь новый ключ в списке.

Добавление репозитория

Теперь все команды будешь выполнять последовательно в терминале VS Code, а начнёшь с инициализации репозитория. Эта команда обращается к Git и создаёт локальный репозиторий в текущей папке проекта 👇🏻

git init

Гиту важно понимать, с каким репозиторием в GitHub связан этот локальный. Укажи адрес репозитория в гитхабе командой 👇🏻

git remote add origin git@github.com:твой-ник-на-github/название-репозитория.git

Замени фразу `твой-ник-на-github` на свой никнейм на GitHub, а также фразу `название-репозитория` на реальное название репозитория, который был создан в начале урока.

Обращаясь к гиту, мы говорим добавить удалённый репозиторий, который будет называться `origin`. По этому имени ты будешь обращаться к нему в будущем.

Добавление `.gitignore`

Каждый раз, заканчивая работу над проектом, перед тем как отправить его на проверку, важно убедиться, что ты не включаешь в репозиторий лишнее. Для этого в корне проекта в VS Code стоит создать `.gitignore`. Это специальный файл, который позволяет указать, что не нужно отправлять в репозиторий на GitHub. В твоих проектах нет ничего лишнего, кроме папки `node_modules`, которая занимает много места и совсем не нужна в репозитории. Также лишними будут и папки с настройками рабочей области: `.DS_Store` и `.vscode`

Чтобы при отправке проекта исключить их, укажи их в файле `.gitignore` 👇🏻

node_modules
.DS_Store
.vscode

Первый коммит

Для того чтобы Git понял, что нужно перенести из локального репозитория в удалённый, необходимо указать, какие изменения стоит внести в новый коммит. Добавлять файлы вручную скучно и долго, поэтому выполни команду `add`, добавив специальный флаг `-A` 👇🏻

git add -A

Благодаря указанному флагу гит добавит в новый коммит все изменённые файлы, уберёт из него все удалённые и не будет включать запрещённые (те, что указаны в файле `.gitignore`).

Теперь можно указать и сам коммит командой 👇🏻

git commit -m "Comment to commit"

Флаг `-m` в команде позволяет задать комментарий, чтобы при просмотре списка всех коммитов было понятно, какие изменения происходили с проектом.

Коммит создан, но перед отправкой изменений в репозиторий на GitHub определимся с главной веткой. Зафиксируй её название 👇🏻

git branch -M main

Эта команда переименует стандартную `master` в `main`, которая и будет основной веткой всего проекта.

Отправить созданный коммит со всеми изменениями в проекте можно командой 👇🏻

git push -u origin main

Здесь флаг `-u` укажет гиту запомнить выбранный репозиторий и ветку.

В будущем для добавления изменений в главную ветку уже существующего репозитория тебе понадобится всего три команды:

- `git add -A` — для добавления новых изменений - `git commit -m “Новая фича”` — для добавления описания к коммиту - `git push` — для отправки изменений в GitHub в ветку `main` - или `git push origin название_ветки` — для отправки изменений в определённую ветку в гитхаб

Работая с Git, важно, чтобы не возникало конфликтов в файлах проекта между локальным репозиторием и удалённым. Для синхронизации изменений существует команда 👇🏻

git pull

Отправка на проверку

После первого коммита у тебя в проекте есть всего один файл — `.gitignore`. Пришло время добавить основные файлы приложения в проект, как на этом видео 👇🏻

{video:https://code.s3.yandex.net/kids-web/vids/directs.mp4|controls:true|autoplay:0|pip:false|controlsList:nodownload}

{quiz-task} background: | #f1f1ef content: | ❗ Отправлять изменения в главную ветку сразу после их добавления не совсем правильное решение. Чтобы наставник мог проверить результат работы и указать на возможные недочёты, стоит создать отдельную ветку. {/quiz-task}

Вот как это делается 👇🏻

git checkout -b 'review-branch'

Эта команда создаёт отдельную ветку, которая переводится с английского как «обзорная ветка», а Git сразу переключается на неё.

Чтобы отправить изменения в новую ветку, используй знакомые команды 👇🏻

git add -A
git commit -m "Дэзэшечка на проверку"

Сама команда для отправки будет немного отличаться: вместо `main` в ней нужно будет указать название новой обзорной ветки, вот так 👇🏻

git push origin 'review-branch'

Таким образом, изменения в проекте не коснутся главной ветки, а будут храниться в соседней.

Создание Pull Request

Создав отдельную ветку и отправив изменения, GitHub заметит это и предложит создать **Pull Request**. На сленге разработчиков **пиар** (сокращённо от PR) — это запрос на добавление новых изменений в основную ветку проекта. Он поможет наставнику увидеть изменения и предложить доработать проект, если это необходимо.

Для создания пиара нужно перейти в свой репозиторий на гитхабе, нажав на кнопку `Compare & pull request` 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1697_1_1712934858.png)

После чего ты можешь указать всю необходимую сопроводительную информацию:

- В поле `Add a title` указывается название пулл реквеста. К примеру, если работать над проектом нужно несколько недель подряд, можно отобразить это в названии — «Дэзэшечка первой недели» и так далее. - В поле `Add a description` указывается описание к пиару. Здесь можно оставить развёрнутый комментарий о том, как тяжело или, наоборот, легко было работать над этим проектом. Или можно указать наставнику на проблему в коде, которую так и не удалось решить.

Заполнив название и описание, нужно подтвердить создание пулл реквеста. Пролистав страницу ниже, нажми на кнопку `Create pull request`

Когда наставник проверит работу, ты увидишь общий комментарий во вкладке `Conversation` 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1698_1712934885.png)

А комментарии на конкретные строки кода можно посмотреть во вкладе `Commits` 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1699_1712934898.png)
