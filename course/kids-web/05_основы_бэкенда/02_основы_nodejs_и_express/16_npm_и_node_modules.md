## Модули: свои и чужие

Модули играют ключевую роль в построении структуры приложений на Node.js, обеспечивая организацию кода и повторное использование. Рассмотрим два типа модулей: созданные вручную и созданные сторонними разработчиками.

**Собственные модули**

Да, для его создания нужно определить логически связанные части приложения, которые можно вынести в отдельный модуль. Затем использовать переменные `module` и `exports` для экспорта функций, объектов или переменных из созданного модуля. Переменная `require` поможет импортировать всё необходимое, чтобы использовать возможности модуля в любом месте приложения.

Создание собственных модулей обладает рядом преимуществ:

- Контроль — создавая модуль, мы имеем полный контроль над его работой, что позволяет в любой момент легко адаптировать его под свои потребности и задачи.
- Простота — загрузка только тех модулей, которые реально нужны, минимизирует объём кода, что делает приложение лёгким и быстрым.

**Сторонние модули**

Пакеты npm представляют собой сторонние модули, которые разработаны сообществом или отдельными командами разработчиков для широкого использования.

Для внедрения сторонних модулей в проект необходимо выбрать подходящий, учитывая его функциональность и другие важные параметры, которые мы подробно разобрали в уроке «Пошумим в библиотеках?».

Использование сторонних модулей обладает рядом преимуществ:

- Разнообразие решений — широкий выбор пакетов npm позволяет решать различные задачи, а понятные документации с примерами кода делают внедрение сторонних модулей доступным за считанные минуты.
- Сообщество и поддержка — сторонние модули активно поддерживаются сообществом, что обеспечивает стабильность и актуальность кода.

### Что же выбрать

Выбор между собственными и сторонними модулями — это вопрос, требующий тщательного обдумывания. Идеальным решением может стать сочетание обоих видов модулей с учётом их преимуществ.

Собственные модули полезны, когда необходим полный контроль над работой приложения, а также его адаптация под уникальные задачи. Для общих задач, где уже существуют эффективные решения, стоит обратить внимание на сторонние модули.

Сторонние модули, представленные в npm, предлагают проверенные решения, использование которых ускоряет процесс разработки. Но важно тщательно выбирать такого вида модули, учитывая их обновления и поддержку, чтобы избежать возможных проблем, нагрузки на приложение и лишних зависимостей.

## `Node_modules`

Когда мы выполняем команду `npm install название_модуля`, пакетный менеджер npm скачивает сторонний модуль из интернета и помещает его в папку `node_modules`. При импортировании модуля в приложение Node.js автоматически ищет его внутри этой папки, что облегчает задачу разработчикам, не требуя полного указания пути.

Можно легко удалить и воссоздать папку `node_modules`. Для того чтобы npm знал, какие пакеты нужно скачать, существуют файлы `package.json` и `package-lock.json`

Файл `package.json` содержит описание приложения и его зависимостей. **Зависимостями** называют сторонние модули, используемые в приложении. Такое определение выбрано потому, что приложение **зависит** от них и в их отсутствие оно не сможет выполнять определённые функции. Сами же зависимости, описанные в `package.json`, бывают двух типов:

- **dependencies** — основные зависимости, необходимые приложению.
- **devDependencies** — зависимости, используемые только во время разработки, такие как тестовые библиотеки или инструменты сборки.

Для правильной работы npm и установки нужных сторонних модулей необходимо более точно указывать их версии. Фиксирует их файл `package-lock.json`, гарантируя, что при повторной установке или переносе приложения все пакеты будут скачаны с нужными версиями. Это также полезно для совместной разработки: обеспечивается одинаковая работа приложения и его зависимостей для всех разработчиков.

## Node Package Manager

**Node Package Manager** — это не просто инструмент для скачивания пакетов. Он также позволяет управлять всем приложением, выполнять различные действия по заготовленным сценариям и эффективно работать с зависимостями.

### Инициализация проекта

Для использования сторонних модулей в приложении, в папке, где ты пишешь код, необходимо проинициализировать проект, выполнив команду `npm init` в терминале VS Code. В ходе выполнения этой команды npm задаст несколько вопросов для создания файла `package.json`, описывающего проект.

Давай разберёмся с этими вопросами:

1. `package name:` — название проекта (на английском, без пробелов).
2. `version:` — версия проекта (по умолчанию `1.0.0`). Вопрос можно пропустить, нажав клавишу `enter`
3. `description:` — описание проекта. Вопрос можно пропустить, нажав клавишу `enter`, или кратко описать проект парой слов.
4. `entry point:` — точка входа (по умолчанию файл `index.js`). В твоём проекте главный исполняемый файл приложения — `app.js`. Поэтому следует указать именно его.
5. `test command:` — команда для запуска тестов. В твоём проекте не используются тесты, поэтому вопрос можно пропустить, нажав клавишу `enter`
6. `get repository:` — ссылка на репозиторий. Стоит сразу указать ссылку на репозиторий, в котором будет храниться проект.
7. `keywords:` — ключевые слова. Вопрос можно пропустить, нажав клавишу `enter`
8. `author:` — автор проекта. В ответе на вопрос можно указать свой крутой никнейм.
9. `license:` — лицензия проекта (по умолчанию ISC). В крупных проектах используются другие виды лицензий, но для твоего проекта открытой лицензии вполне достаточно, поэтому вопрос можно пропустить, нажав клавишу `enter`

После ответа на эти вопросы npm выведет в терминал предварительную версию файла `package.json` и задаст финальный вопрос `Is this OK?`. Если все данные заполнены правильно, нужно ввести `yes`, после чего инициализация проекта будет завершена.

Для проверки держи пример файла `package.json` после инициализации 👇🏻

### Управление зависимостями

При работе с npm сторонние модули важно не только уметь устанавливать, но и управлять ими — обновлять и удалять. Для этого используются следующие команды:

- `npm install название_модуля` — устанавливает указанный модуль. Если модулей несколько, их можно перечислить через пробел, например `npm install модуль_1 модуль_2 модуль_3`
- `npm install` (без названия модуля) — устанавливает все зависимости, указанные в файле `package.json`. Команда часто используется при клонировании репозитория на компьютер, так как папка `node_modules` обычно не хранится в GitHub.
- `npm update` — обновляет все установленные модули, указанные в файле `package.json`, до их последней версии.
- `npm uninstall название_модуля` — удаляет зависимость из проекта. Это полезно, если какой-то модуль не нужен или был установлен по ошибке.

Давай более детально рассмотрим команду `npm install название_модуля`

В этом уроке мы узнали, что зависимости бывают двух типов: `dependecies` — основные и `devDependencies` — для разработки. По умолчанию все зависимости, которые устанавливаются этой командой, считаются основными. Если нужно указать npm, что мы хотим установить зависимость только для разработки, следует добавить флаг `--save-dev` после названия модуля 👇🏻

```javascript
npm install название_модуля --save-dev
```

Теперь закрепим знания на практике и установим сторонний модуль `nodemon`. Это удобный инструмент, который работает подобно расширению «Live Server» для VS Code. Он следит за изменениями в коде проекта и перезапускает сервер для их моментального отображения. А ещё отлично подойдёт на этапе разработки, поэтому установи его, добавив соответствующий флаг 👇🏻

```javascript
npm install nodemon --save-dev
```

Если перейти в файл `package.json`, можно заметить, что `nodemon` появился в списке зависимостей для разработки `devDependencies` 👇🏻

### Поговорим о скриптах

**Сценарии запуска** — это пользовательские команды, которые мы создаём самостоятельно и выполняем командой `npm run название_сценария`. При инициализации проекта команда `npm init` автоматически добавляет скрипт с именем `test`, чтобы показать, в каком формате создавать свои сценарии.

Выбор названий для сценариев остаётся за веб-разработчиком, но существуют общие договорённости, которых многие стараются придерживаться:

- `dev` — запускает скрипты для разработки, включая автоматическую перезагрузку сервера при изменениях кода и другие инструменты.
- `start` — запускает скрипты, необходимые для запуска готового приложения в рабочем режиме. Запуск этого сценария проводится перед сборкой и развёртыванием проекта на реальном сервере, где с ним будут взаимодействовать пользователи.
- `build` — запускает скрипты для сборки проекта, включая оптимизацию кода и уменьшение размера файлов (минификацию).

В твоём проекте, где не используются инструменты сборки, команда `build` не понадобится. А вот команду для запуска приложения в режиме разработки добавить советуем 👇🏻

```javascript
"scripts": {
	"dev": "nodemon app.js",
}
```

Здесь `"dev"` — это название сценария, а следующий код — это команда для запуска приложения. Установленный модуль `nodemon` используем для автоматической перезагрузки приложения при изменениях.

Добавь также команду для запуска приложения после завершения разработки 👇🏻

```javascript
"scripts": {
	"dev": "nodemon app.js",
	"start": "node app.js"
}
```

Напомним, что запустить эти скрипты можно, выполнив команду `npm run название_скрипта`, как в скринкасте 👇🏻
