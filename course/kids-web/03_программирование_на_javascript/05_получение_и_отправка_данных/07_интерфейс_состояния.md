# Интерфейс состояния

![](https://pictures.s3.yandex.net:443/resources/Untitled_Artwork_598_1703265160.png)

В общем-то, да!

Представь, наш бедный Аски заполнил форму и нажимает «Отправить», но ничего не происходит: ни стили, ни текст кнопки не меняются.

В этом случае вместо одного запроса к серверу отправятся 100500.

Проблемы налицо.

Во-первых, такое неочевидное поведение сайта очень раздражает обычного пользователя (не только Аски), ведь он не может понять, в каком состоянии отправленные им данные: они отправляются, или получены на сервере, или всё сломалось и данные просто пропали?

Во-вторых, у серверов ограниченные ресурсы и желательно не отправлять им слишком много запросов, чтобы не вызвать неполадки в работе.

В этом уроке мы расскажем, как можно избежать ситуации, когда пользователь будет без остановки кликать на «Отправить», перегружая сервер.

К настоящему моменту мы уже сделали так, что при отправке формы данные уходят на наш сервер.

```jsx
// Получение элементов формы
const form = document.forms.addHero; // Получаем форму
const titleInput = form.elements.title; // Получаем поле с именем
const descriptionInput = form.elements.description; // Получаем поле с описанием
const strInput = form.elements.str; // Получаем поле с уровнем силы
const agiInput = form.elements.agi; // Получаем поле с уровнем ловкости
const hpInput = form.elements.hp; // Получаем поле с уровнем здоровья
const intInput = form.elements.int; // Получаем поле с уровнем интеллекта

// Вешаем на форму обработчик события submit
form.addEventListener('submit', function (evt) {
  // Отменяем стандартное поведение
  evt.preventDefault();
	// Создаём объект с новым персонажем и записываем данные
	let newHero = {
		title: titleInput.value,
	  description: descriptionInput.value,
	  str: strInput.value,
	  agi: agiInput.value,
	  hp: hpInput.value,
	  int: intInput.value,
	};
	// Формируем JSON-строку из объекта
	let newHeroJSON = JSON.stringify(newHero);
	
	// Отправляем запрос на сервер с новым персонажем
	// Используем API нашего сервера 
	fetch("https://api-code.practicum-team.ru/heroes", {
		method: "POST", // POST нужен для сохранения и записи данных
	  body: newHeroJSON, // Тело запроса в JSON-формате
	  headers: {
		  // Добавляем необходимые заголовки
		  "Content-type": "application/json; charset=UTF-8",
		},
	})
		.then((response) => response.json())
		// Cмотрим ответ сервера на наш запрос
	  .then((data) => console.log(data))
		// Cбрасываем все поля
		form.reset();
});
```

Теперь надо сделать так, чтобы во время загрузки данных кнопка «Добавить героя» становилась неактивной. Для этого у кнопок существует атрибут `disabled` (если он указан, то нажатие на кнопку не вызывает никакого действия). Добавим это в самое начало нашего обработчика событий, прямо после `evt.preventDefault()`:

```javascript
let addHeroButton = document.querySelector("#addHero");

form.addEventListener('submit', function (evt) {
  // Отменяем стандартное поведение
  evt.preventDefault();
	// Отключаем кнопку "Добавить героя"
	addHeroButton.disabled = true;
	/* Остальной код слушателя события submit */
	}
)
```

Но нам нужно сделать и так, чтобы кнопка снова была активна после получения ответа от сервера. Для этого нужно добавить блок `finally` в цепочку после `fetch`

`finally` — ещё одна функция промисов, похожая на `then` и `catch`, но выполнится она независимо от того, в какой статус перейдёт промис после нашего запроса. То есть, и если запрос будет успешным (`fulfilled`), и если запрос будет неудачным (`rejected`), блок кода `finally` исполнится. Если подзабылось, как работают промисы и что это за `then` и `catch`, — вернись ещё раз к уроку про асинхронность.

```javascript
let addHeroButton = document.querySelector("#addHero");

form.addEventListener('submit', function (evt) {
  // Отменяем стандартное поведение
  evt.preventDefault();
	// Отключаем кнопку "Добавить героя"
	addHeroButton.disabled = true;

	/* Код слушателя события submit (кроме отправки данных) */

	// Отправляем запрос на сервер с новым персонажем
	// Используем API нашего сервера 
	fetch("https://api-code.practicum-team.ru/heroes", {
		method: "POST", // POST нужен для сохранения и записи данных
	  body: newHeroJSON, // Тело запроса в JSON-формате
	  headers: {
		  // Добавляем необходимые заголовки
		  "Content-type": "application/json; charset=UTF-8",
		},
	})
	.then((response) => response.json())
	// Cмотрим ответ сервера на наш запрос
	.then((data) => {
		console.log(data);
		// Cбрасываем все поля
		form.reset();
	})
	.finally(() => {
		addHeroButton.disabled = false;
	})
	}
)
```

Для того чтобы стилизовать выключенные кнопки, в CSS можно использовать псевдокласс `disabled` (в первом модуле уже рассказывали о псевдоклассах). Вот как это будет выглядеть:

```css
.button:disabled {
	opacity: 0.6;
}
```

Итак, теперь на кнопку нельзя будет нажимать бесконечное количество раз, пока запрос пользователя обрабатывается, — это хорошо. 

Можем добавить к этому и замену текста кнопки на что-нибудь показывающее пользователю, что отправка в процессе. Простой пример: сделаем так, чтобы на время загрузки текст кнопки менялся на «Отправляем данные...». Не забудь, как и в случае с текстом кнопки, вернуть всё к изначальному состоянию.

Пропишем это в том же блоке `finally`, с которым работали до этого. 

```javascript
let addHeroButton = document.querySelector("#addHero");

form.addEventListener('submit', function (evt) {
  // Отменяем стандартное поведение
  evt.preventDefault();
	// Отключаем кнопку "Добавить героя"
	addHeroButton.disabled = true;
	addHeroButton.textContent = "Отправляем данные...";

	/* Код слушателя события submit (кроме отправки данных) */

	// Отправляем запрос на сервер с новым персонажем
	// Используем API нашего сервера 
	fetch("https://api-code.practicum-team.ru/heroes", {
		method: "POST", // POST нужен для сохранения и записи данных
	  body: newHeroJSON, // Тело запроса в JSON-формате
	  headers: {
		  // Добавляем необходимые заголовки
		  "Content-type": "application/json; charset=UTF-8",
		},
	})
	.then((response) => response.json())
	// Cмотрим ответ сервера на наш запрос
	.then((data) => {
		console.log(data);
		// Cбрасываем все поля
		form.reset();
	})
	.finally(() => {
		addHeroButton.disabled = false;
		addHeroButton.textContent = "Отправить";
	})
	}
)
```

Ещё нам стоит добавить обработку ошибок, чтобы пользователь видел: что-то пошло не так. 

Для примера сделаем простейший вариант: пользователю будет показываться, что произошла ошибка (без уточнения, что именно случилось). 

Для этого нам понадобится добавить ещё один элемент — текстовый блок чуть ниже поля ввода формы. Дадим ему id `errorText`

Найдём добавленный элемент с помощью `querySelector`. А затем добавим в цепочку обработки запроса `catch` — на случай, если не получается отправить данные. 

При этом в начале каждого отправления данных можно сбрасывать текст ошибки, чтобы у пользователя была возможность попробовать отправить что-то ещё раз.  

```javascript
let addHeroButton = document.querySelector("#addHero");
let errorText = document.querySelector("#errorText");

form.addEventListener('submit', function (evt) {
  // Отменяем стандартное поведение
  evt.preventDefault();
	// Отключаем кнопку "Добавить героя"
	addHeroButton.disabled = true;
	addHeroButton.textContent = "Отправляем данные...";

	/* Код слушателя события submit (кроме отправки данных) */

	// Отправляем запрос на сервер с новым персонажем
	// Используем API нашего сервера 
	fetch("https://api-code.practicum-team.ru/heroes", {
		method: "POST", // POST нужен для сохранения и записи данных
	  body: newHeroJSON, // Тело запроса в JSON-формате
	  headers: {
		  // Добавляем необходимые заголовки
		  "Content-type": "application/json; charset=UTF-8",
		},
	})
	.then((response) => response.json())
	// Смотрим ответ сервера на наш запрос
	.then((data) => {
		console.log(data);
		// Сбрасываем все поля
		form.reset();
	})
	.catch((e) => {
		errorText.textContent = "Произошла ошибка"
	})
	.finally(() => {
		addHeroButton.disabled = false;
		addHeroButton.textContent = "Отправить";
	})
	}
)
```
