Клиент🤝Сервер

Действительно, на данный момент сайт не прокачан до того, чтобы сохранять изменения, которые внёс пользователь. Чтобы решить эту проблему, сперва необходимо узнать:

- что такое клиент и сервер - как они взаимодействуют с помощью API (реальный пример взаимодействия тоже покажем)

Клиент и сервер

Программа на твоём устройстве, которая отображает данные, — это **клиент**. Клиентом может быть мобильное приложение, но в нашем случае отображением занимается браузер. На твоём компьютере в браузере открыт сайт, он показывает в удобном формате курс Практикума. А где-то далеко есть ещё один компьютер (а может быть, даже не один), который хранит и обрабатывает данные и отправляет их пользователю, — такой компьютер называют **сервером**.

{quiz-task} background: | #f1f1ef content: | ♻️ Клиент и сервер постоянно общаются друг с другом. Это особенно заметно при работе с социальными сетями. К примеру, когда ты лайкаешь фото, с клиента отправляется сообщение на сервер об изменении количества лайков, сервер же увеличивает счётчик лайков у этой фотографии. В результате другой человек, открыв ту же фотографию, получит с сервера уже обновлённые данные, в которых будет и твой лайк. Так же работает и с комментариями, просмотрами — да практически с любыми данными, с которыми может взаимодействовать юзер. {/quiz-task}

Клиент и сервер — это две разные части одного сайта:

1. Часть кода сайта, которая отвечает за клиент, называется **фронтенд (frontend)**. Это именно то, чем мы с тобой занимаемся с самого начала курса: создаём сайты, которые видит пользователь, используя для этого HTML, CSS и JS. 2. Другая часть кода сайта — это программа, которая постоянно запущена на сервере, она называется **бэкенд** (**backend**). Эта программа может быть написана на JavaScript, ведь это универсальный язык программирования. Но зачастую для неё используются и другие языки: к примеру, Python или Java (да, это не то же самое, что JS).

На этой неделе, чтобы связать клиент и сервер в проекте, ты будешь использовать готовый backend, а к четвёртому модулю обязательно попробуешь самостоятельно написать часть кода, отвечающую за работу сервера.

Для этого им нужен специальный переводчик — **API**.

API

**API** (с английского Application Programming Interface — «программный интерфейс») — это набор способов взаимодействовать с бэкенд-частью сайта, этакая инструкция по работе с сервером. В ней указано, что нужно написать в запросе, чтобы взаимодействовать с данными (предоставлять, получать, сохранять, изменять и обновлять их).

Как ты знаешь, чтобы попасть на любой сайт, нужно пройти по ссылке. Написать запрос в браузере, который вернёт список ссылок, и по ним выбрать нужный сайт. API тоже может выступать как набор ссылок в случае c клиент-серверным общением.

Например, популярный сервис для небольших демосайтов [jsonplaceholder](https://jsonplaceholder.typicode.com/){target="_blank"} использует разные окончания ссылки запроса к серверу, чтобы определить, с какими данными необходимо работать:

![](https://pictures.s3.yandex.net:443/resources/Frame_1362_1_1703092837.png)

Сервер может предоставить посты, комментарии, альбомы и фотографии согласно API сервиса. Подробнее о его использовании можно почитать [на сайте](https://jsonplaceholder.typicode.com/){target="_blank"}.

А вот сервис стоковых фотографий [unsplash](https://unsplash.com/developers){target="_blank"} имеет более сложный API. Для работы с сервером используются разные ссылки, большое разнообразие параметров и ключевых слов.

Так как API — это инструкция по работе с сервером, её обычно пишут бэкенд-разработчики. Большинство сайтов создают свой сервер только под собственные нужды, поэтому найти API для любого сайта невозможно. Но в то же время существуют фирмы, предоставляющие свои серверы и вычислительные мощности всем желающим разработчикам за определённую плату, с их помощью каждый может сделать сайт на разные тематики без затрат на оборудование, вычисления и серверы: сайт с прогнозами погоды или картами и навигацией, новостной агрегатор, музыкальный сервис и многое другое.

С удовольствием! Давай получим что-то от сервера, например фото котиков и собачек.

Для этого используем сервер сервиса [unsplash](https://unsplash.com/developers){target="_blank"} — там хранится отличная коллекция фотографий. Жми на кнопки в песочнице и смотри на фото, которые отправил тебе сервер.

Нажимая на кнопку «Получить кота» или «Получить собаку», ты активируешь следующие действия:

- отправление запроса на сервер - обработку сервером запроса и возвращение на клиент фоточки питомца - использование фронтендом полученных данных с сервера для отображения фотографии на странице

Код в песочнице сейчас может выглядеть довольно страшно, но не бойся, к концу недели самостоятельно сможешь написать такой же.
