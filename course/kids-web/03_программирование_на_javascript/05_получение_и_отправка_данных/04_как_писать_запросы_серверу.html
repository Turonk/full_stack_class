Про функцию `fetch()`

Есть несколько вариантов, как можно отправлять свои запросы на сервер, но мы поговорим о наиболее используемом сейчас — с помощью функции `fetch()`

Эта функция принимает два параметра: URL (адрес сайта), к которому будет отправляться запрос, и необязательный параметр `options`, в котором можно настроить запрос 👇🏻

// Первому параметру даём аргумент – URL, второму – options (в нашем примере пустой)
fetch("https://url", {});

По умолчанию такой запрос должен получать данные с указанного адреса. Но что делать, если мы хотим передать что-то дополнительно? Тут нам надо поговорить о параметре `options` подробнее.

Предположим, мы хотим отправить текст `"Привет, мир!"` на наш сервер. Давай рассмотрим отправку данных в формате JSON, для этого запишем текст сообщения в виде объекта

`{ message: "Привет, мир!" }`

Выбираем метод запроса

Они нужны для того, чтобы сказать, какой тип запроса мы хотим сделать: получить, отправить, обновить или удалить данные. Вот методы запросов, о которых мы будем больше всего говорить в уроках этой недели:

- `GET` запрос на получение данных с сервера (выбран по умолчанию)

    fetch("https://url", {
    	method: "GET"
    });

    // Метод GET выбран в fetch по умолчанию, в таком случае можно 
    // не указывать его и не указывать параметр options
    fetch("https://url");

- `POST` запрос, отправляющий данные на сервер

    fetch("https://url", {
    	method: "POST"
    });

- `PUT` запрос, обновляющий данные на сервере - `DELETE` запрос на удаление данных с сервера

Соответственно, раз мы хотим отправить текст на сервер, выбираем метод `POST`

Указываем тип данных и вкладываем их в запрос

Теперь надо понять, как вложить данные в запрос, ведь в `POST`/`PUT` запросах нужно как-то передавать новую информацию на сервер.

Для начала нам стоит указать, какой тип данных мы передаём.

Сейчас мы отправляем объект `{ message: "Привет, мир!" }`, который мы преобразуем в JSON. Для того чтобы указать тип, нам нужно добавить дополнительную информацию о запросе. Это делается в `headers` — заголовках запроса.

fetch("https://url", {
	method: "POST",
	headers: {
		// Сообщаем, что тип контента нашего запроса – json
		"Content-Type": "application/json"
	},
});

Отлично! А сейчас перейдём к данным.

У запроса есть тело — `body`. Туда и надо передавать необходимые данные. Соответственно, если мы хотим отправить `{ message: "Привет, мир!",}`, то предварительно его нужно преобразовать в формат JSON при помощи функции `JSON.stringify()`. Осталось добавить такую запись:

fetch("https://url", {
	method: "POST",
	headers: {
		// Сообщаем, что тип контента в body нашего запроса – текстовая строка
		"Content-Type": "text/plain"
	},
	// Добавляем в body данные, которые хотим передать на сервер
	body: JSON.stringify({ message: "Привет, мир!",})
});

Теперь у нас готов запрос, отправляющий объект с сообщением на адрес. Повторим ещё раз, что, используя `fetch`, в `options` можно включить:

- `method` — какой запрос мы отправляем (`GET`/`POST`/`PUT`/`DELETE`) - `headers` — дополнительную информацию о запросе (например, тип содержания запроса) - `body` — данные, которые мы отправляем на сервер

`fetch()` на практике

Попробуем сделать fetch-запрос к серверу, на котором хранятся данные о героях с наших карточек (мы заранее подготовили его специально для этой недели, в дальнейшем ты будешь уметь обращаться к нему, чтобы получать и отправлять данные о героях).

Пока что выведем ответ в консоли, чтобы посмотреть, что в нём происходит. Не пугайся слова `.then` в коде — мы обсудим подробнее, зачем оно нужно, в следующем уроке.

fetch("https://api-code.practicum-team.ru/heroes?_where[_or][0][studentEmail]=${studentEmail}&_where[_or][1][studentEmail]=")
  .then(response => console.log(response))

![](https://pictures.s3.yandex.net:443/resources/Frame_1365_2_1703272561.png)

В ответ от сервера приходит `Response` — данные о произошедшем запросе. Посмотрим, что хранится в `Response`:

- `body` Тело ответа. Там будут находится нужные нам данные о героях в виде JSON. - `ok` Показывает, был ли запрос к серверу успешным (`true`/`false`). - `status` Статус ответа. В нашем примере `200` значит, что ответ получен и с ним всё ок. Часто встречаются такие коды: - `400 Bad Request` — если запрос содержит ошибку - `403 Forbidden` — доступ запрещён - `404 Not Found` — ничего не найдено по указанному адресу - `500 Internal Server Error` — ошибка сервера

Но вывод запроса в консоль может быть не очень удобен для того, чтобы его изучить, так что посмотрим на другой способ — через инструменты разработчика в браузере.

Ты уже знаешь об инструментах разработчика и, наверное, очень часто пользуешься списком HTML-элементов на странице и консолью. Среди инструментов также есть и средство для отслеживания сетевой активности — вкладка Network. В ней можно посмотреть, что и как загружается на сайт: там регистрируются все загрузки файлов, необходимых для отображения сайта, от HTML-страницы до картинок. В частности, там можно найти и запросы, которые отправляются из кода с помощью `fetch`

В панели Network можно увидеть больше информации о свойствах запроса, чем при его выводе в консоль: например, адрес сервера или список заголовков ответа (напоминаем, заголовки ответа — дополнительная информация о переданном между сервером и клиентом сообщении).

Ещё подробнее о сообщениях, которыми обмениваются клиент и сервер, ты можешь почитать в статье в [Доке](https://doka.guide/tools/http-protocol/){target="_blank"}.

И помни: запросы к серверу не происходят мгновенно, нужно время, чтобы их обработать. Когда запрос уходит на сервер, он обещает, что скоро вернётся… И его надо ждать. Поэтому в следующем уроке мы поговорим о том, как дождаться данных с сервера.
