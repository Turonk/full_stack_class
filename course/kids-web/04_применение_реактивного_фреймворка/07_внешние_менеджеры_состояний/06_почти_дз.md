## Чек-лист

### Часть 1. Создание отдельного компонента `App.jsx`

{quiz-task}
    background: |
        #f1f1ef
    content: |
        📚 Впервые мы создавали `App.jsx` в уроке про **React Context** — код компонента можно подсмотреть там же, но помни, что он видоизменился после использования **Zustand**. Компонент `App` — обёртка для всего приложения, в нём будем проверять авторизацию пользователя. Если чувствуешь, что необходима пошаговая инструкция, смотри, как это было, в уроках «Встроенное решение — React Context» и  «Внешние стейт-машины. Zustand».
{/quiz-task}

- Создай компонент `App.jsx` внутри основной директории `app`
    
    а) Это клиентский компонент, в который нужно импортировать компоненты `Header`, `Footer`, хуки `useEffect` и `useStore`
    
    б) В компоненте нужно получить доступ к `store` и при монтировании компонента вызывать функцию проверки авторизации из стора — в этом поможет `useEffect`
    
    в) `App` должен возвращать фрагмент в котором объединены `Header`, `{props.children}`, `Footer`
    
- Импортируй App в `layout.js` и используй его внутри тега `body` , и передай в `App`  `{children}`

### Часть 3. Создание store

{quiz-task}
    background: |
        #f1f1ef
    content: |
        📚 Всё точно так же, как в уроке «Внешние стейт-машины. Zustand». Главное — создать отдельный файл для стора, используя Zustand, конечно.
{/quiz-task}

- Установи библиотеку Zustand: `npm install zustand`
- Создай папку `/app/store` и в ней файл `app-store.js`
- Из файла `app-store.js` должна экспортироваться константа `useStore` , в которой нужно описать следующие поля:

    а) boolean-переменная `isAuth`
    
    б) Переменная `user` по умолчанию со значением `null`
    
    в) Переменная `token` по умолчанию со значением `null`
    
    г) Метод `login`, который использует данные `user` и `token` для авторизации
    
    д) Метод `logout` для удаления данных авторизованного пользователя
    
    е) Метод `checkAuth` , использующий `JWT`-токен для проверки авторизации пользователя

### Часть 4. Получение данных

{quiz-task}
    background: |
        #f1f1ef
    content: |
        📚 Компоненты, использующие данные об авторизированном пользователе, должны получать их с помощью Zustand.
{/quiz-task}

- В компоненте `App` `useStore` используется для проверки авторизации пользователя — метод `checkAuth`
- В компоненте `AuthForm`, используя `useStore`, данные из стора сохраняются в переменную `authContext`

    а) `authContext.login()` помогает авторизовать пользователя в обработчике `handleSubmit`
    
    б) В хуке `useEffect` данные о пользователе `authContext.user` помогают закрыть форму.

- В компоненте `Header`, используя `useStore`, данные из стора сохраняются в переменную `authContext`
    
    а) В обработчике `handleLogout` за удаление данных о пользователе отвечает метод `authContext.logout`
    
    б) В JSX-верстке компонента за условный рендер кнопки `Войти` или `Выйти` должно отвечать значение из стора `authContext.isAuth`
    
- В компоненте `GamePage`, используя `useStore`, данные из стора сохраняются в переменную `authContext`
    
    а) Данные о пользователе `authContext.user` используются в хуке `useEffect` для изменения состояния переменной состояния `isVoted`
    
    б) В обработчике `handleVote`

        1) Данные о `jwt` нужно получать из стора — `authContext.token`
    
        2) В переменную `usersIdArray` пушим `id` авторизованного пользователя, а его получаем также из стора — `authContext.user.id`

        3) Обновляя данные об игре, необходимо перезаписать данные пользователей, используя пользователя из стора `users: [...game.users, authContext.user]`
    
    в) За состояние `disabled` кнопки в JSX-разметке кнопки голосования должна отвечать переменная `authContext.isAuth`
