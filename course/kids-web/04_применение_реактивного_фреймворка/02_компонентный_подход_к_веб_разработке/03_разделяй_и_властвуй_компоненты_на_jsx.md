## Что такое компонент

Компонент — независимый кусок кода, который можно переиспользовать в любом месте приложения неограниченное количество раз. 

Самый сок в том, что при изменении внутренней структуры этого куска кода нам достаточно изменить его всего в одном месте, а в остальных замена произойдёт автоматически.

Уверены, ты уже предвкушаешь, как это просто и удобно. Давай посмотрим, есть ли в коде нашего проекта Pindie компоненты.

Рассмотрим файл `page.js` в папке `app` .

Внутри этого файла экспортируется функция `Home`. Сама функция `Home` возвращает разметку страницы, которая очень сильно напоминает обычную HTML-разметку. На самом деле это не HTML. React в качестве разметки использует JSX. 

Компонент в React — это функция, которая возвращает JSX-разметку. Получается, функция `Home` из нашего проекта — это React-компонент.

## JSX-разметка

Разметку компонентов пишут на JSX. JSX-разметка — это расширение языка JavaScript. Несмотря на то что JSX-разметка внешне очень похожа на уже знакомый тебе HTML, у неё есть ряд собственных правил, которые необходимо соблюдать. Делимся ими ниже.

### Компонент должен возвращать один корневой элемент

Функция-компонент всегда возвращает JSX-разметку, но это может быть только один корневой элемент. Если вёрстка твоего компонента подразумевает использование множества тегов, то их необходимо оборачивать в единственный корневой тег `div`

```javascript
function MyComponent() {
  return (
      <div> // Здесь div - это корневой элемент компонента
          <h1>Мой крутой компонент</h1>
          <ul>
              <li>Пункт один</li>
              <li>Пункт два</li>
              <li>Пункт три</li>
          </ul>
      </div>
  );
}
```

Если вёрстка компонента будет состоять только из одного тега, его необязательно оборачивать в `div`. Пример — компонент заголовка 👇🏻

```javascript
function Header() {
    return <h1>Мой крутой компонент</h1>; // Здесь тег сам по себе является корневым элементом
}
```

В двух примерах выше обрати внимание на скобки `()` (или их отсутствие) после `return`. Их необходимо использовать только в том случае, если после `return` нужно сделать перенос строки. 

### Все теги должны быть закрыты

Есть два вида тегов: **самозакрывающиеся** и **оборачивающие.** 

Самозакрывающиеся теги пишутся так: `< {имя тега} {атрибуты тега} />`

Оборачивающие (они же парные) теги выглядят таким образом: `< {имя тега} {атрибуты тега} > {то, что оборачиваем} </ {имя тега} >`

Примеры в коде 👇🏻

```javascript
function MyComponent() {
  return (
      <div> // Оборачивающий тег
          <h1>Мой крутой компонент</h1> // Оборачивающий тег
          <img
              src="https://i.imgur.com/yXOvdOSs.jpg"
              alt="Hedy Lamarr"
              className="photo"
          /> // Самозакрывающийся тег
          <ul> // Оборачивающий тег
              <li>Пункт один</li> // Оборачивающий тег
              <li>Пункт два</li>
              <li>Пункт три</li>
          </ul>
      </div>
  );
}
```

```javascript
function MyComponent() {
  return (
      <div> // Оборачивающий тег
          <h1>Мой крутой компонент</h1> // Оборачивающий тег
          <img
              src="https://i.imgur.com/yXOvdOSs.jpg"
              alt="Hedy Lamarr"
              className="photo"
          /> // Самозакрывающийся тег

              <li>Пункт один</li> // Оборачивающий тег
              <li>Пункт два</li>

}
```

Всё так!

### Особенности в названиях атрибутов

Напомним, что атрибут — это некоторое свойство тега, которое указывается в самом теге после его названия: `< {имя тега} {имя атрибута}={значение атрибута} >`

В примерах выше в теге `<img/>` есть атрибуты `src`, `alt`, `className`

Теги в JSX-разметке имеют ограничения на имена атрибутов. К примеру, каждый HTML-тег имеет атрибут `class` для стилизации, в JSX-разметке для стилизации используется атрибут `className`, так как `class` — это зарезервированное слово в JavaScript. 

Обрати внимание на имена атрибута: они все пишутся в знакомом тебе стиле **camelCase.**

Да, JSX-разметка специально была придумана для того, чтобы можно было удобно делить интерфейс приложения на компоненты-функции и вызывать одни компоненты внутри других.

## Работа над Pindie

После этого урока тебе предстоит самостоятельно применить компонентный подход к проекту на Next, который ты разрабатываешь (считай, домашка). 

Но пока давай начнём выполнять его вместе.

❗️ Возьми файл  `layout.js` в папке `app` и выдели в нём компонент заголовка `Header`

На скринкасте мы сначала запускаем проект, проверяем, что всё работает, затем создаём рядом с `RootLayout` ещё одну функцию `Header`, в которую переносим всю JSX-разметку для этого компонента. 

В конце видео мы внутри JSX-разметки `RootLayout` заменяем всю вёрстку заголовка на один компонент `Header` и ещё раз проверяем, что всё корректно работает.

{video:https://code.s3.yandex.net/kids-web/vids/Разделяи_и_властвуи_Компоненты_на_jsx_скринкаст_1.mp4|controls:true|autoplay:0|pip:false|controlsList:nodownload}

Компонент `Header` — это отдельная функция, поэтому её можно вынести в отдельный одноимённый файл `Header.jsx`, а затем импортировать в файл с вёрсткой страницы `layout.js`

Приложение будет расти, и компонентов будет становиться больше. Чтобы избежать беспорядка в файловой структуре проекта, компоненты принято складывать в отдельную папку с компонентами. 

❗️Создай такую папку и назови её `components`. Внутри этой папки создай ещё одну с тем же именем, что и у компонента. Да, сейчас это может показаться лишним, но совсем скоро ты поймёшь, зачем это нужно.

{video:https://code.s3.yandex.net/kids-web/vids/Разделяи_и_властвуи_Компоненты_на_jsx_скринкаст_2.mp4|controls:true|autoplay:0|pip:false|controlsList:nodownload}

Кстати, для компонентов, из которых состоит страница, лучше всего использовать **именованные экспорты.** Мы говорили о них на прошлом уроке.

❗️Сделай то же самое с компонентом `Footer`. Выдели JSX-разметку этого компонента в отдельный файл `Footer.jsx` (оттуда позже мы будем его экспортировать). Сам файл `Footer.jsx` положи рядом, в специальную папку `Footer` внутри `components` (по аналогии с тем, как мы делали с компонентом `Header`). 

В файле `layout.js` мы импортируем компонент `Footer` и используем его в JSX-разметке компонента `RootLayout`

{video:https://code.s3.yandex.net/kids-web/vids/Разделяи_и_властвуи_Компоненты_на_jsx_скринкаст_3.mp4|controls:true|autoplay:0|pip:false|controlsList:nodownload}

Файлы, которые мы создали, имеют расширение `.jsx`. Это указывает на то, что в них содержатся именно компоненты.

Приложение будет развиваться, и в нём будут появляться новые и новые страницы. Нам нужно, чтобы на них тоже были компоненты `Header` и `Footer`, но при этом мы не хотим дублировать использование этих компонентов на каждой новой странице в отдельности. 

Для решения этой проблемы и существует файл `layout.js`. Он представляет собой общий каркас для страниц, в который вставляется содержимое каждой отдельной страницы. Посмотри ещё раз на получившийся код 👇🏻

```javascript
export default function RootLayout({ children }) {
    return (
        <html lang="ru">
            <body>
                <Header/>
                {children}
                <Footer/>
            </body>
        </html>
    )
}
```

`RootLayout` — это и есть тот самый каркас, а компоненты `Header` и `Footer` будут присутствовать на всех страницах. Содержимое самих страниц будет вставляться на место `{children}`. Пока для тебя это магия фреймворка Next.js, но скоро ты разберёшься, как именно это работает. Чтобы ускорить этот процесс, можешь выполнить домашнее задание — оно поможет лучше понять прочитанную теорию.
