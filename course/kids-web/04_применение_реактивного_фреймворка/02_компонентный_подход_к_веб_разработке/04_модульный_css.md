# Модульный CSS

![](https://pictures.s3.yandex.net:443/resources/Worn-Ass-Semi-Gloss_16_1706619041.png)

Прежде всего, давай разберёмся, какими вообще бывают стили.

## Глобальные стили

**Глобальные стили** отвечают за внешний вид всего сайта. Они обычно хранятся в файле `globals.css`

Когда мы хотим, чтобы изменения в стилях затрагивали каждый уголок нашего сайта (ну или красили в розовый не только табуретки, но и другую мебель, а заодно и все стены во всех квартирах), глобальные стили становятся отличным решением. 

Пример 👇🏻

```css
body {
  font-family: 'Anonymous Pro', sans-serif;
  font-size: 18px;
  background: #fafafd;
}
```

Свойства `body` охватывают все страницы и создают единый стиль для всего сайта.

Глобальные стили — это не всегда удобно. И вот почему 👇🏻

### Конфликт в глобальных стилях

В процессе вёрстки сайта мы задаём классы элементам, чтобы стилизовать их на CSS. 

Иногда мы сталкиваемся с ситуацией, когда хочется использовать один и тот же класс для разных элементов на странице — например, заголовка страницы и заголовка карточки. И если эти заголовки предполагают разные стили, возникает конфликт.

Можно, конечно, выдумывать разные классы для элементов, но когда их становится слишком много, легко запутаться.

Благо, уже существует способ применить каждый стиль только к своей собственной разметке, чтобы стили, применённые к заголовку в одном месте, не влияли на заголовок с таким же классом в другом. И это… 

## Модульные стили

Если же мы хотим, чтобы наши стили применялись только к определённым частям страницы, например, к карточкам в каталоге или всплывающим окнам, в ход идут **модульные стили.** 

Они применяются только к определённым компонентам, что делает код отделённым от остальных стилей. Например, такие стили будут применяться только для компонента `card` 👇🏻

```css
.card {
  width: 100%;
	max-width: 320px;
  background: #ffffff;
}
```

Иначе модульные стили называются CSS-модули. Давай научимся создавать, импортировать и использовать их. 

Покажем, как работают CSS-модули, на примере кода для карточек с домами наших персонажей. Этот пример никак не связан с Pindie, но поможет вникнуть в тему, чтобы потом применить знания в проекте.

### Создание файла модуля

1. Создай папку с названием компонента в директории `components`
Если это компонент Card, назови папку так же, чтобы не путаться в файловой структуре проекта и быстро находить нужные компоненты 👇🏻

    ```javascript
    app/
    	components/
    		Card/
    ```

    А вот и сам компонент `Card.jsx` — карточка с картинкой и текстом, которую нужно поместить в одноимённую папку 👇🏻

    ```javascript
    export function Card() {
      return (
        <div>
          <img src="/images/brutal.png" />
          <h3>Брутальная крепость</h3>
          <p>выбор для смелых и непоколебимых личностей, вроде Аски</p>
        </div>
      )
    }
    ```

2. Создай файл модуля с именем `Card.module.css`
Важно соблюдать правильный формат, чтобы Next.js мог автоматически распознать его как CSS-модуль 👇🏻

    ```javascript
    Название_Компонента.module.css
    ```

{video:https://code.s3.yandex.net/kids-web/vids/css-m-1.mp4|controls:true|autoplay:0|pip:false|controlsList:nodownload}

Файлы CSS-модулей для компонентов принято создавать в папке с этими компонентами. На то есть несколько причин:

- **Модульность**
Она гарантирует нам, что стили применятся только к этому конкретному компоненту и никак не повлияют на другие стили.
- **Удобная навигация**
Когда нужно изменить компонент, мы можем перейти в его папку и увидеть все файлы, которые к нему относятся, в том числе файл стилей. Это упрощает работу с кодом и навигацию по проекту.
- **Переиспользуемость**
Она позволяет легко переносить компоненты с их стилями из одного проекта в другой, просто копируя нужную папку.


3. Опиши стили компонента. 
Важно добавлять только те стили, которые относятся к нашей карточке и вложенным в неё элементам. Можешь также добавить сюда медиазапросы.

### Импорт и использование

Теперь, когда у нас есть модуль стилей для компонента `Card`, попробуем импортировать и использовать стили внутри компонента.

Добавь строку подключения стилей в файл `Card.jsx` 👇🏻

```javascript
import Styles from './Card.module.css';
```

Обрати внимание, что мы импортируем стили в виде объекта с псевдонимом `Styles`

Выведи его в консоль VS Code для наглядности 👇🏻

```javascript
import Styles from './Card.module.css'

export function Card() {
  
	console.log(Styles)

  return (
    <div>
      <img src="/images/brutal.png" />
      <h3>Брутальная крепость</h3>
      <p>выбор для смелых и непоколебимых личностей, вроде Аски</p>
    </div>
  )
}
```

![](https://pictures.s3.yandex.net:443/resources/Frame_1442_1706619199.png)

Поскольку при импорте модульных стилей мы получаем объект, каждый стиль становится свойством этого объекта. Раздай элементам соответствующие классы в атрибуте `className` 👇🏻

```javascript
import Styles from './Card.module.css'

export function Card() {
  return (
    <div className={Styles.container}>
      <img className={Styles.image} src="/images/brutal.png" />
      <h3 className={Styles.title}>Брутальная крепость</h3>
      <p>выбор для смелых и непоколебимых личностей, вроде Аски</p>
    </div>
  )
}
```

В примере выше `Styles` — это объект, который содержит все классы из файла модуля. 

Чтобы обратиться к каждому стилю, используй ключи объекта. Например, `Styles.container`, `Styles.image` и `Styles.title`

Если имена классов в наших стилях содержат спецсимволы вроде дефиса, нужно использовать квадратные скобки для доступа к этим стилям. Вот так 👇🏻

```css
.sub-title {
  font-size: 18px
}
```

```javascript
<img className={Styles["sub-title"]} />
```

Здесь мы использовали квадратные скобки вокруг `["sub-title"]`, чтобы правильно обратиться к стилю с именем, содержащим дефис.

Теперь, зная, как использовать модульные стили, давай заглянем за кулисы — в инструменты разработчика браузера.

## Хеширование

Если открыть DevTools и посмотреть на DOM, можно заметить, что у нашего компонента изменённые классы с необычными символами в конце.

![](https://pictures.s3.yandex.net:443/resources/Frame_1443_1706619307.png)

Код в конце каждого класса называется **хешем**. Когда мы добавляем хеш, наши понятные имена стилей превращаются в уникальные комбинации букв и цифр.

Когда мы задаём класс `container` компоненту, он трансформируется вот по такой формуле 👇🏻

```css
название_компонента__класс__хеш
```

В результате получаем 👇🏻

```css
Card__container__hK1DK
```

**hK1DK** — уникальный код класса.

Указывать хеши самостоятельно или обращаться к новым классам (уже с хешем) в коде не нужно. Этим занимается наш фреймворк для того, чтобы стили применялись только к нужным частям страницы и не мешали классам других компонентов.

Конечно, а заодно объясним ещё, что есть шаблонные строки.

## Шаблонные строки

Представь, что мы хотим сделать все карточки сайта про дома персонажей разными, со своими уникальными стилями. Но некоторые свойства у них повторяются, например отступы, ширина, цвет текста. Мы можем вынести эти стили в общий глобальный класс, например `.card` или `.card-main`

![](https://pictures.s3.yandex.net:443/resources/Frame_1441_2_1706619392.png)

Совмещая глобальные и модульные стили карточек, мы создаём своего рода микс стилей.

Если использовать **шаблонные строки**, мы сделаем такой микс, комбинируя глобальные и модульные стили для наших компонентов. 

Перенесём основные свойства карточки в файл `globals.css` 👇🏻

```css
 .card {
  display: flex;
  flex-direction: column;
  padding: 15px;
  gap: 15px;
  max-width: 350px;
  width: 100%;
}
```

И оставим только уникальные стили брутальной карточки 👇🏻

```css
.container {
	border-radius: 20px;
  background: #ffffff;
}
```

Применим общие и уникальные стили карточки, используя шаблонную строку в атрибуте `className` 👇🏻

```javascript
<div className={`card ${Styles.container}`}>
```

В этом примере мы просто комбинируем классы внутри строки, используя конструкцию `${}`. Такой подход делает код более лёгким и организованным.
