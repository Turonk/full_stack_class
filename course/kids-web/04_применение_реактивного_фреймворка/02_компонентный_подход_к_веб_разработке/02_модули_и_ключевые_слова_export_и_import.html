В нём в HTML-файле подключены скрипты 👇🏻

<body>
	<!-- Код проекта -->
	<script src="./biblioteka.js"></script>
  <script src="./page.js"></script>
  <script src="./data.js"></script>
</body>

Эти скрипты взаимосвязаны:

- в файле `data.js` лежат исходные данные - в файле `biblioteka.js` хранятся функции для отображения элементов страницы - в `page.js` всё собирается вместе

Поэтому в той последовательности подключения, как предложил Аски, есть проблема.

Браузер последовательно загружает файлы и запускает функции. Функции из `page.js` не смогут правильно отобразить страницу, потому что данные для них загрузятся только *после* их выполнения. Попробуй поменять местами подключение скриптов вот так 👇🏻

<body>
	<!-- код проекта -->
	<script src="./data.js"></script>
	<script src="./biblioteka.js"></script>
  <script src="./page.js"></script>
</body>

Теперь при первой загрузке ты сможешь увидеть ранее сохранённые данные.

В большом проекте файлов бывает очень много, и даже ошибки с их подключением приносят много проблем:

🔄 Перепутали очередность скриптов — сломали проект.

👥 Одинаково назвали переменные в разных скриптах (конфликт имен) — сломали проект.

🤼 Работали с напарником в одном файле и изменили одну и ту же функцию каждый по-своему, потому что она используется в разных скриптах, — сломали проект.

Сейчас в проекте подключена куча тегов `<script>` — загрузка сайта становится вечной, потому что их скачивание замедляет отображение страницы. Пользователи точно не будут пользоваться таким медленным сайтом.

Что такое модули

Модуль — это такой же отдельный файл, но с особенностями.

Файл JavaScript, который мы подключаем к HTML, тоже может быть модулем, для этого достаточно указать ему атрибут с типом `type="module"`

<script type="module" src="./page.js"></script>

Данная настройка делает из простого файла полноценный модуль. В нём появляется поддержка определённых ключевых слов (о них ниже), а переменные и функции перестают быть видны другим скриптам, если мы их специально не экспортируем.

Благодаря модулям мы можем забирать из файлов конкретные переменные и функции, указывая, что и из какого файла используем. Это решает большинство проблем, о которых мы говорили выше.

![](https://pictures.s3.yandex.net:443/resources/Frame_1438_2_1706280884.png)

Для подключения нужных функций и переменных из одного файла в другой используют ключевые слова `export` и `import`

Экспорт и импорт

`export` показывает, что можно вытащить из одного файла, а `import` — что требуется для работы другого.

А теперь объясним, как именно ключевые слова работают в коде.

`export`

Мы можем выбрать конкретную переменную или отдельную функцию модуля, которую хотим сделать доступной в других файлах, и экспортировать её. Для этого достаточно добавить ключевое слово `export` перед переменной или функцией, которые нужно экспортировать 👇🏻

// data.js
export const englishToRussianWords = [
  { english: "pineapple", russian: "ананас" },
  { english: "apple", russian: "яблоко" },
  { english: "pear", russian: "груша" },
  { english: "grapes", russian: "виноград" },
  { english: "orange", russian: "апельсин" },
  { english: "tangerine", russian: "мандарин" },
  { english: "plum", russian: "слива" },
  { english: "apricot", russian: "абрикос" },
  { english: "passion fruit", russian: "маракуйя" },
  { english: "peach", russian: "персик" }
];

**Экспорт в момент создания**

Переменные или функции можно экспортировать в момент создания. Для этого перед их созданием добавляют директиву `export`

// экспорт переменных
export const user = {
	username: "Миша",
	data: "Важная информация, которую нельзя потерять.",
}
export const password = "Пароль от сервера";

// экспорт функции
export function sayHi(name) {
  return `Hi, ${name} 👋`;
}

При импорте такого значения мы используем имя, которое дали при создании. Поэтому экспорт в момент объявления называют **именованным экспортом**.

**Экспорт после создания**

При экспорте также можно написать в конце файла один раз директиву `export` и указать несколько функций и переменных сразу, перечислив их через запятую в фигурных скобках 👇🏻

// biblioteka.js

const user = {
	username: "Миша",
	data: "Важная информация, которую нельзя потерять.",
}
const password = "Пароль от сервера";

function sayHi(name) {
  return `Hi, ${name} 👋`;
}

// Экспорт нескольких значений
export { user, password, sayHi };

Таким образом из модуля мы извлекаем только необходимые переменные и функции.

В этом примере после ключевого слова `export` неспроста идут фигурные скобки. В экспорте ****в момент создания** мы с помощью `export` помечали каждый кусочек кода (функция, переменная), который планируем использовать вне файла. В экспорте ****после создания** **всё нужное мы упаковываем в одну коробку и экспортируем её.

Экспорт короче

Случается иногда, что название ключа и значение в коде совпадают 👇🏻

export {user: user, password: password, sayHi: sayHi}

В таком случае JavaScript позволяет сократить повторяющиеся наименования 👇🏻

export { user, password, sayHi };

Эти два способа записи равнозначны. Программисты обычно стремятся сократить код и всё автоматизировать, поэтому чаще тебе будет встречаться короткий тип записи. Такой способ называется **деструктуризация объекта.**

`import`

Переменные и функции модуля можно получить внутри другого модуля. Для этого есть ключевое слово `import`, оно позволяет обращаться к переменным в других файлах 👇🏻

// page.js

// Импортируем переменную и функции по их именам
import { englishToRussianWords } from "./data.js";
import { renderCards, addCard } from "./biblioteka.js";

// После импорта их можно использовать в page.js
function handleClick() {
		// "Функция addCard из модуля biblioteka.js"
    addCard(englishInput, russianInput, container);
}
addButton.addEventListener("click", handleClick);
// "Переменная englishToRussianWords из модуля data.js"
// "Функция renderCards из модуля biblioteka.js"
renderCards(container, englishToRussianWords);

Импортировать можно каждый элемент отдельно, но удобнее перечислить сразу добавляемые в модуль элементы.

Как и в случае с экспортом, делается это через запятую и в фигурных скобках (снова **деструктуризация объекта**):

// script.js

// Импорт нескольких переменных из модуля biblioteka.js
import { user, password, sayHi } from "./data.js"

console.log(user); // { username: "Миша", data: "Важная информация, которую нельзя потерять.",}
console.log(password); // "Пароль от сервера"

**Экспорт и импорт по умолчанию**

Из модуля можно возвращать одно или несколько значений. Если нужно экспортировать одну функцию, достаточно использовать экспорт по умолчанию.

Тогда после директивы `export` пишут `default`, а дальше — значение, которое нужно экспортировать 👇🏻

// header.js

export default function renderHeader() {
  // Код функции
}

Отличие импорта по умолчанию в том, что фигурные скобки не ставятся 👇🏻

// script.js

import renderHeader from "./header.js";

renderHeader();

При экспорте по умолчанию не важно, как называется функция в файле экспорта. Она может быть анонимной, её имя не играет роли (при обычном экспорте такое невозможно) 👇🏻

// Этот код в разных файлах

// biblioteka.js
export default let myFunction = function() {
  console.log("Это анонимная функция");
};

// info.js
export default ["Группа 4", "Группа 8", "Группа 15"];

Имена дают экспортированным данным позже, уже при импорте 👇🏻

// script.js
import anonymousFunction from './biblioteka.js';
import Groups from './info.js';
