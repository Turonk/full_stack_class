Опять fetch. Синтаксиc async/await

Действительно, уроки второго модуля помогли разобраться во взаимодействиях сервера и клиента, узнать про запросы, промисы, их обработку.

function getEnemyHero() {
    // Получаем героя оппонента с сервера
    fetch(`https://api-code.practicum-team.ru/heroes`)
    // Обрабатываем ответ сервера
		  .then((response) => response.json())
      .then((data) => {
	      // Смотрим на данные в консоли
        console.log(data);
      })
      // В случае ошибки запроса выводим сообщение об ошибке в консоль 
      .catch((error) => console.error("Ошибка:", error));
};

Но код тогда, честно говоря, был не супер: несколько уровней вложенности, использование разных функций в разных методах — есть что упростить.

Благо, придумывать ничего не надо, уже существует альтернативный способ для асинхронного кода 👇🏻

const getEnemyHero = async () => {
	try {
		const response = await fetch(`https://api-code.practicum-team.ru/heroes`);
		const data = await response.json();
		console.log(data);
	} catch (error) {
		console.error("Ошибка:", error)
	}
}

`async/await`

Если нужно выполнить асинхронную функцию и дождаться выполнения промиса, достаточно пометить такую функцию ключевым словом `async` 👇🏻

async function getEnemyHero(url) {
	// Код функции
}

Ранее, обращаясь к функции `fetch`, мы дожидались выполнения промиса. Затем с помощью метода `.then()` обрабатывали полученный результат — он также возвращал промис, который в следующей конструкции `.then()` продолжал обрабатываться с помощью функций колбэков. В этом и заключалась цепочка вызовов функций.

Ключевые слова `async/await` позволяют избавиться от цепочек функций.

Ключевое слово `await` заставит JavaScript-программу ждать до тех пор, пока промис справа от `await` не выполнится. Пока промис выполняется, JS-код может обрабатываться далее — выполнять скрипты и обрабатывать события. В результате взаимодействие с сайтом не блокируется. Как только промис вернёт результат, выполнение кода асинхронной функции продолжится.

Ключевое слово `await` можно использовать только внутри асинхронных функций со словом `async` в методах, которые возвращают промис 👇🏻

async function getEnemyHero(url) {
	// Асинхронная процедура, возвращающая промис 
	const response = await fetch(url);
	// response.json() - асинхронная процедура, результата её выполнения также нужно дождаться 
	const data = await response.json();
	return data
}

Ключевое слово `async` перед функцией гарантирует, что функция в любом случае вернёт промис. Поэтому с такими асинхронными функциями можно встретить использование конструкции `.then()` для последующей обработки данных в колбэках 👇🏻

async function getEnemyHero(url) {
	const response = await fetch(url);
	const data = await response.json();
	return data
}

getEnemyHero(`https://api-code.practicum-team.ru/heroes`).then(
	// Колбэк для обработки промиса
)

Работая с промисами, всегда нужно помнить, что у промиса может быть состояние `rejected` — `выполнено с ошибкой`. В том числе ошибки могут возникать в нашем коде либо при работе со сторонними сервисами и инструментами.

Так, при опечатке в запросе или отсутствии интернет-соединения выполнение промиса завершается ошибкой (состояние `rejected`) 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1532_1708612094.png)

Подобные ошибки (ошибки в отображении, долгая загрузка, некорректная обработка действий пользователя, плохая обратная связь) способны сломать приложение, негативно повлиять на отображение интерфейса и отбить желание пользоваться сайтом. Поэтому важно уметь их обрабатывать.

Обработка ошибок

В подходе с цепочками функций `.then()` на случай любой ошибки есть свой «перехватчик» — `.catch()` (метод для обработки ошибок).

Если на одном из этапов обработки асинхронной функции произойдёт ошибка, метод `.catch()` её перехватит, а внутри метода ты уже можешь обработать ошибку — вывести всплывающую подсказку с сообщением об ошибке, изменить элементы интерфейса, чтобы корректно информировать пользователя о происходящем.

В случае подхода с синтаксисом `async/await` обрабатывать ошибки помогает конструкция `try..catch`. Код выполняемой функции нужно поместить в блок `try {…}`, а код для обработки ошибки — в блок `catch {…}` 👇🏻

const getData = async () => {
	try {
		// Код асинхронной функции
	} catch (error) {
		// Код обработки ошибок
	}
}

Блоком `try` можно обернуть несколько строк кода. В случае ошибки выполнение кода в блоке `try` прерывается и переключается на блок `catch`, в котором ошибка, полученная аргументом в функцию `catch`, обрабатывается понятным для пользователя образом 👇🏻

Объясняем!

`fetch` отправляет запрос на сервер.

В ответ с сервера приходит промис (это объект, который может либо выполниться — отдать результат, либо нет — отдать ошибку).

Когда промис выполняется, приходит результат, который в коде выше называется `response`, и этот `response` содержит те заголовки, которые прислал сервер в ответ.

Заголовки — это специальный технический блок в ответах (там, например, размещается статус ответа: успешно или нет, кодировка, тип данных, который придёт, и так далее).

Мы можем увидеть статус запроса в свойствах ответа:

- `status` — код статуса запроса, - `ok` – логическое значение: `true` или `false`

На этом этапе мы можем определить, выполнился ли запрос успешно, а также посмотреть заголовки.

Промис завершается ошибкой, если `fetch` не смог выполнить запрос (например, при ошибке сети или когда искомый сайт не найден).

При успешном запросе код статуса — `200`, а у `ok` значение `true` 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Untitled_3_1708612340.png)

Рассмотрим самые частые ошибки. Их можно объединить в две группы по коду: **ответы 4XX** и **ответы 5XX.** Первые говорят о проблеме с запросом со стороны клиента, а вторые — о проблеме с сервером:

- **400 — Bad Request** Ошибка связана с некорректным вводом (например, опечатка в логине или адресе почты). - **401 — Unauthorized** Ошибка, описывающая проблему с авторизацией пользователя (когда пользователь пытается выполнить действие, на которое у него нет прав). - **404 — Not Found** Ошибка сообщает, что запрошенный ресурс не найден из-за некорректного URL, удалённой или перемещённой страницы. - **500 — Internal Server Error** Ошибка некорректной работы сервера.

Это лишь часть статусов запроса, которые тебе могут встретиться. Каждый из них требует определённой обработки: для каких-то достаточно сообщения, для некоторых верстают целую страницу 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1533_1708612365.png)

Когда ты пользуешься современным популярным сайтом, ты можешь встретить много интересных изменений интерфейса, так или иначе обрабатывающих ошибки:

- `loading…`, гифка или анимированный элемент, скрывающий период загрузки контента; - изменение интерфейса в случае ошибки доступа к серверу или в результате ошибки сети; - вывод сообщения о типе ошибки и советов, как её решить.

Сервер вернул Аски пустой массив, но это не является ошибкой в привычном виде. В таких случаях важно дать пользователю исчерпывающий фидбэк: `Товар не найден` или `По вашему запросу ничего не найдено`

Такого изменения интерфейса нельзя добиться, если JS будет определять ошибки сам. Некоторые из них лучше объяснить самостоятельно.

Для этого существует специальный механизм — **пользовательские ошибки**.

Чтобы создать пользовательскую ошибку:

1. Оборачиваем код, который может вызвать ошибку, в блок `try` (попытайся выполнить это), а после `try` создаём блок `catch` — в нём будем писать код, если в блоке `try` произойдёт ошибка. 2. В блоке `try` описываем условие возникновения ошибки: `if (условие ошибки)` 3. Внутри блока `if` пользуемся ключевым словом `throw` (выброси/выдай), чтобы сказать программе: «если условие с ошибкой выполнилось, выдай…». 4. После слова `throw` описываем, что надо выдать/выбросить, а именно экземпляр ошибки `new Error` — в экземпляр обычно помещают сообщение, говорящее, что это за ошибка. 5. В блоке `catch` пишем код, который выполнится, когда сработает `throw`. Ошибка, которую выбросит `throw`, придёт аргументом в функцию `catch`

 const getData = async (url) => {
	try {
		const response = await fetch(url);
    if (response.status !== 200) {
      throw new Error("Ошибка получения данных");
    }
		const data = await response.json();
		console.log(data);
	} catch (error) {
		console.error("Ошибка:", error.message)
	}
}

В песочнице по клику на кнопку отправляется запрос по неверному адресу.

Уточним причину ошибки для пользователя, применив знания о пользовательских ошибках. Добавим условие с проверкой статуса запроса: если статус будет отличаться от кода `200`, выведем сообщение `Ошибка получения данных` 👇🏻

Чтобы обрабатывать различные особенности программы, мы можем разрабатывать свои персональные ошибки при помощи наследования и расширения стандартного класса ошибки `Error`. И создавать вспомогательные функции для определения ошибок 👇🏻

export const isResponseOk = (response) => {
  return !(response instanceof Error);
};

Уже по названию функции понятно, в чём её суть. Она принимает в качестве аргумента ответ от сервера и возвращает `true`, если ответ является успешным (не является экземпляром ошибки — `instanceof Error`), и `false` в противном случае.

Эту функцию удобно использовать для проверки: если пришла ошибка — вызвать какое-то другое действие, в обратном случае ничего не делать.
