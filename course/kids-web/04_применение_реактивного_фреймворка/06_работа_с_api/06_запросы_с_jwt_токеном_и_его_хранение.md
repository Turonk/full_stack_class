# Запросы с JWT-токеном и его хранение

![](https://pictures.s3.yandex.net:443/resources/Frame_1551_1709111725.png)

В этом уроке как раз разберёмся, что это за строка и какие преимущества даёт разработчикам использование JWT.

Нечитаемая строка — это `JWT-токен`, сервер присылает его в обмен на идентификатор и пароль пользователя. Когда человек пользуется сайтом, ко всем запросам к серверу прикладывается полученный `JWT-токен`, чтобы сервер мог определить, от чьего имени сделан запрос и достаточно ли у данного пользователя прав, чтобы вообще его выполнить.

Типа того!

Токен генерируется на сервере и имеет ограниченное время жизни, которое устанавливает разработчик сервера. Когда время жизни токена истекает, он становится бесполезным и запросы с ним выполняют как от неавторизованного пользователя. Такой токен необходимо обновлять.

![](https://pictures.s3.yandex.net:443/resources/IMG_4699_1709111920.jpg)

## Делаем запрос с `JWT-токеном`

На сервере Pindie есть эндпоинт `/users/me`, он позволяет получить данные о конкретном пользователе. 

Чтобы сервер понимал, о каком пользователе нужно вернуть данные, запрос на `/users/me` должен содержать `JWT-токен`. Мы подготовили функцию `getMe` , которая будет выполнять `GET`-запрос к эндпоинту `/users/me` и передавать в нём токен 👇🏻

```javascript
/**
 * 
 * URL-адрес в виде строки, куда будет выполнен запрос
 * JWT–токен в виде строки
 */
export const getMe = async (url, jwt) => {
  try {
    // Выполняем запрос
    const response = await fetch(url, {
      // Запрос выполняется методом GET
      method: "GET",
      // JWT-токен передаётся в специальном заголовке Authorization
      headers: { Authorization: `Bearer ${jwt}` },
    });
    if (response.status !== 200) {
      throw new Error("Ошибка получения данных");
    }
    const result = await response.json();
    return result;
  } catch (error) {
    return error;
  }
};
```

`async`/`await` и `fetch` в коде выше тебе уже понятны. Поэтому давай обратим пристальное внимание на то, как передаётся `JWT-токен` в запросе. Для этой цели использован специальный заголовок `Authorization`, он предназначен как раз для того, чтобы передавать в нём токен для авторизации. Сервер, получив запрос с таким заголовком, достаёт из него токен и производит процедуру авторизации. `Bearer` — это тип токена, который говорит о том, что токен используется именно для авторизации. 

Чтобы продемонстрировать, как работает функция `getMe`, в видео ниже мы:

1. Экспортируем её из файла `api-utils.js` 
2. Создадим в файле `config.js` новый эндпоинт `/users/me`
3. Вызовем `getMe` в компоненте `AuthForm` сразу после того, как осуществим авторизацию через форму и получим в ответ от сервера `JWT-токен`
4. Зайдём на сайт Pindie и авторизуемся с такими данными: `{identifier: 'aski@example.com', password: 'ilovehtml'}`

## Как хранить `JWT`

Чтобы решить проблему, обозначенную Аски, нужно выполнить следующие шаги 👇🏻

1. Сразу после прохождения авторизации и получения ответа сервера с `JWT-токеном`, его необходимо положить в какое-нибудь хранилище.
2. В компоненте `Header`:

    a. В процессе отрисовки (то есть выполнения функции компонента) необходимо достать токен из хранилища и выполнить запрос с помощью `getMe`

    b. В зависимости от результата запроса выставить значение переменной `isAuthorized` 

    c. В `JSX-разметке` компонента в зависимости от значения переменной `isAuthorized` текст кнопки должен быть либо `Войти`, либо `Выйти`

Чтобы проверить, что всё работает, нужно выполнить авторизацию, перезагрузить страницу и убедиться, что в шапке отображается кнопка `Выйти` — то есть мы сохранили в браузере знание о том, что пользователь авторизован, и отобразили это в интерфейсе.

Отдельно стоит упомянуть, что при нажатии на кнопку `Выйти` мы должны удалить токен из хранилища, тем самым разлогинив пользователя.

В качестве хранилища для `JWT-токена` мы будем использовать `localStorage`

## Как работать c `localStorage`

`localStorage` — это хранилище внутри браузера, предназначенное для хранения данных вида «ключ — значение».

Чтобы записать данные в `localStorage`, нужно вызвать метод `setItem` следующим образом 👇🏻

```javascript
/**
* Первый аргумент — имя ключа, по которому будет храниться значение
* Второй аргумент – само значение
**/
localStorage.setItem("keyName", "value");
```

Чтобы получить данные из `localStorage`, нужно вызвать метод `getItem`. Данный метод позволяет получить значение, которое было сохранено методом `setItem` по определённому имени ключа👇🏻

```javascript
/**
* Первый аргумент – имя ключа, по которому нужно получить значение
**/
localStorage.getItem("keyName");
```

Чтобы удалить значение из `localStorage`, нужно вызвать метод `removeItem` 👇🏻

```javascript
/**
* Первый аргумент – имя ключа, по которому нужно удалить значение
**/
localStorage.removeItem("keyName");
```

## Кнопка авторизации в шапке

Для начала создай три функции:

1. `setJWT(jwt)` — для сохранения токена
2. `getJWT()` — для получения токена
3. `removeJWT()` — для удаления токена

Все эти функции мы будем экспортировать из файла `api-utils.js`

```javascript
export const setJWT = (jwt) => {
  localStorage.setItem("jwt", jwt);
};

export const getJWT = () => {
	return localStorage.getItem("jwt");
};

export const removeJWT = () => {
  localStorage.removeItem("jwt");
};
```

Теперь, сразу после успешной авторизации, нужно сохранять токен в хранилище браузера. 

Для этого в компоненте формы авторизации `AuthForm` модифицируй функцию `handleSubmit`, добавив в неё вызов `setJWT` с полученным токеном.

В компонент шапки `Header`  добавь вызов хука `useEffect`, внутри которого ты выполнишь запрос к эндпоинту `/users/me` через функцию `getMe` 

Если запрос успешен, то переменную `isAuthorized` выставишь в `true`, иначе — в `false`

Чтобы вызвать `getMe`, передай в неё токен, который можно получить при помощи `getJWT`. Следующим этапом необходимо изменить JSX-разметку компонента таким образом, чтобы в зависимости от значения `isAuthorized` в кнопке отображался текст `Войти` или `Выйти`.

## Кнопка `Голосовать` на странице игры

В Pindie на странице отдельной игры по роуту `/game/id` есть кнопка `Голосовать`. Чтобы эта кнопка была доступна пользователю, он должен быть авторизован. В целом, чтобы это сделать, тебе нужно выполнить практически те же шаги, что и для компонента `Header` 👇🏻

1. Добавить в компонент страницы две переменные состояния: `isAuthorized`, которая изначально будет иметь значение `false`, и `currentUser`, в которой мы будем хранить данные пользователя (её изначальное значение будет равняться `null`).
2. Добавить в компонент страницы `useEffect`, где мы будем с помощью `getJWT` и `getMe` проверять авторизацию пользователя и выставлять значение переменной `isAuthorized`
3. В JSX-разметке компонента страницы `GamePage` в элемент `button` c текстом `Голосовать` добавить атрибут `disabled`, который будет принимать значение `!isAuthorized`. Таким образом ты сможешь заблокировать кнопку для неавторизованных пользователей. Чтобы визуально подчеркнуть, что кнопка заблокирована, добавь такой стиль: 

    ```css
    .about__vote-button:disabled {
      opacity: 0.5;
      pointer-events: none;
    }
     ```

Осталась небольшая проблема. 

Если пользователь попробует авторизоваться, находясь на странице игры, то после успешной авторизации кнопка `Голосовать` автоматически не станет активной. Она разблокируется только после перезагрузки страницы, в результате чего в странице `GamePage` сработает добавленный тобой `useEffect` с проверкой авторизации и выставления нужного значения в переменную `setIsAuthorized`
