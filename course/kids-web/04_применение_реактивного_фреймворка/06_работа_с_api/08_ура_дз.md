## Чек-лист

### Часть 1. Получение данных игр

{quiz-task}
    background: |
        #f1f1ef
    content: |
        📚 Понять, как Pindie должен общаться со своим API, помогут уроки «Опять `fetch`. Синтаксис `async`/`await`» и «`fetch` на сервере и клиенте». А запросто составить функции получения данных игр и их нормализации можно после изучения урока «`GET`-запросы. Нормализация данных и прелоадер».
{/quiz-task}

- Страницы категорий игр (роуты) получают данные по правилам серверных компонентов, используя `async`/`await`
- Детальная страница игры получает данные по правилам клиентских компонентов, используя хук `useEffect`
- Детальная страница игры устанавливает **прелоадер**, который отражает процесс загрузки данных, пока они не вернутся с API.
- На детальной странице игры функция получения данных внутри хука `useEffect` проверяет наличие ошибок перед отображением игры.

- Создай папку `api` внутри основной директории `app`
- Внутри новой папки `api` создай файл конфигурации `config.js`

    а) Создай константу `BASE_URL` для хранения `URL`-адреса API и помести внутри ссылку.

    б) Создай экспортируемый объект `endpoints` с маршрутами API. Он должен содержать три основных эндпоинта. В начале каждого эндпоинта помести константу `BASE_URL`, чтобы составить правильный адрес к API:

        1) Эндпоинт для получения данных игр `games` с адресом `/games`

        2) Эндпоинт для авторизации пользователя `auth` с адресом `/auth/local`

        3) Эндпоинт для получения данных пользователя `me` с адресом `/users/me`


- Внутри новой папки `api` создай файл с функциями и запросами к API — `api-utils.js`

    а) Создай асинхронную функцию `getData` для получения любых открытых данных из API по его `URL`-адресу.
    
    б) Создай экспортируемую функцию `isResponseOk` для проверки возвращаемых данных из любой функции на наличие ошибок.
    
    в) Создай функцию `normalizeDataObject` для создания нормализованных объектов, получаемых при совершении `GET`-запросов.
    
    г) Создай экспортируемую функцию `normalizeData` для создания нормализованных массивов объектов, получаемых при совершении `GET`-запросов.
    
    д) Создай асинхронную экспортируемую функцию `getNormalizedGameDataById` с параметрами `url` и `id` для получения данных определённой игры по её идентификатору. Функция внутри себя проверяет данные, возвращаемые API, и нормализует их в случае отсутствия ошибок.
    
    е) Создай асинхронную экспортируемую функцию `getNormalizedGamesDataByCategory` с параметрами `url` и `category` для получения данных игр по названию определённой категории. Функция внутри себя проверяет данные, возвращаемые API, и нормализует их в случае отсутствия ошибок.

### Часть 2. Авторизация

{quiz-task}
    background: |
        #f1f1ef
    content: |
        📚 Продолжая работать с файлом `api-utils.js`, необходимо создать функции для авторизации пользователя и записи `JWT`-токена. В этом поможет изучение уроков «Авторизация с `POST`-запросом» и «Запросы с `JWT`-токеном и его хранение».
{/quiz-task}

- Компонент `<AuthForm/>` позволяет пользователю авторизоваться по логину и паролю.
- Форма выводит сообщение об авторизации или возникшей ошибке в интерфейс.
- После авторизации `JWT`-токен пользователя сохраняется в памяти браузера.
- После авторизации меняется состояние и текст кнопки в шапке сайта.
- После авторизации форма скрывается через таймаут в одну секунду.

- Создай асинхронную экспортируемую функцию `autorize` с параметрами `url` и `data`. Функция должна отправлять `POST`-запрос с указанием параметров: `method`, `headers` и `body`

    а) Внутри параметра `body` необходимо передать данные пользователя `data`, приведённые к формату JSON.
    
    б) Результат запроса должен проверяться на наличие ошибок и возвращаться функцией в формате JSON.

- Создай экспортируемую функцию `setJWT` с параметром `jwt`. Функция должна записывать токен пользователя в память браузера, а именно в `localStorage`

### Часть 3. Проверка авторизации и выход

{quiz-task}
    background: |
        #f1f1ef
    content: |
        📚 Для проверки авторизации пользователя и возможности выйти из своего аккаунта нужно создать ещё три функции в файле `api-utils.js`. Про все способы работы с `JWT`-токеном можно узнать из урока «Запросы с `JWT`-токеном и его хранение».
{/quiz-task}

- Компоненты `<Header/>` и `<GamePage/>` при первом отображении запрашивают `JWT`-токен пользователя из памяти браузера. Чтобы проверить корректность токена, отправляется `GET`-запрос на эндпоинт `/users/me`
- Если `JWT`-токен корректный, после выполнении запроса `/users/me` данные пользователя сохраняются в состояние компонента `<GamePage/>`
- Если `JWT`-токен корректный, после выполнения запроса `/users/me` компонент `<GamePage/>` меняет состояние кнопки для голосования.
- Если `JWT`-токен корректный, после выполнения запроса `/users/me` компонент `<Header/>` меняет состояние кнопки для авторизации.
- При клике на кнопку в шапке сайта авторизованный пользователь выходит из аккаунта.
- После выхода из аккаунта `JWT`-токен удаляется из памяти браузера, меняются состояние и текст кнопки в шапке сайта.

- Создай экспортируемую функцию `getJWT` без параметров. Функция должна проверять наличие `JWT`-токена в `localStorage` и, если он не обнаружен, возвращать пустое значение.
- Создай экспортируемую функцию `removeJWT` без параметров. Функция должна удалять JWT-токен из `localStorage`
- Создай асинхронную экспортируемую функцию `getMe` с параметрами `url` и `jwt` для получения данных авторизованного пользователя. Функция должна отправлять `GET`-запрос с указанием параметров `method` и `headers`

    а) Внутри параметра `headers` необходимо передать `JWT`-токен авторизованного пользователя.
    
    б) Результат запроса должен проверяться на наличие ошибок и возвращаться функцией в формате JSON.

### Часть 4. Голосование

{quiz-task}
    background: |
        #f1f1ef
    content: |
        📚 Завершающими функциями работы с API в файле `api-utils.js` должны быть функции голосования авторизованного пользователя за выбранную игру. С этим легко поможет освоение урока «Время голосовать. `PUT`-запрос».
{/quiz-task}

- Детальная страница игры, получая данные об авторизованном пользователе, проверяет наличие голоса за эту игру.
- Если пользователь голосовал, кнопка голосования меняет текст внутри себя, а также принимает атрибут `disabled` и становится недоступна для клика.
- Если пользователь не голосовал, при клике на кнопку голосования отправляется `PUT`-запрос на эндпоинт игры. В ключ `users` записывается новый голос.
- Если `PUT`-запрос отправлен, информация о голосе авторизованного пользователя записывается в состояние игры, обновляя ключ `users`

- Создай экспортируемую функцию `checkIfUserVoted` с параметрами `game` и `userID` для проверки наличия голоса за определённую игру.

    а) Функция должна проверять наличие идентификатора пользователя в объекте игры `game` по ключу `users`, используя метод `find`
    
    б) Функция должна возвращать `true` в случае, если пользователь голосовал за игру, и `false`, если не голосовал.

- Создай асинхронную экспортируемую функцию `vote` с параметрами `url`, `jwt` и `usersArray` для учёта голоса пользователя. Функция должна отправлять `PUT`-запрос с указанием параметров `method`, `headers` и `body`

    а) Внутри параметра `headers` необходимо передать `JWT`-токен авторизованного пользователя.
    
    б) Внутри параметра `body` необходимо передать новый массив пользователей `usersArray`, приведённый к формату JSON.
    
    в) Результат запроса должен проверяться на наличие ошибок и возвращаться функцией в формате JSON.
