# Время голосовать. Запрос на обновление

## Как устроено голосование

Попав на сайт Pindie, пользователь видит каталог игр — на каждой карточке есть описание игры и счётчик голосов 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1552_1709112805.png)

Выбрав конкретную игру, он попадает на детальную страницу с ней, может проверить свои навыки и при желании отдать за игру голос, чтобы повысить её популярность, — для этого достаточно нажать `голосовать` 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1553_1709112818.png)

Чтобы счётчик голосов не накручивали, **проголосовать может только зарегистрированный пользователь**. 

Как только пользователь введёт логин и пароль, кнопка входа в шапке сайта изменится с `войти` на `выйти`. В этот момент интерфейс детальной страницы игры определит, что пользователь зарегистрирован, и кнопка голосования активируется 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1554_1709112831.png)

После клика на кнопку `голосовать` отправится запрос на сервер (чтобы учесть голос зарегистрированного пользователя), а также изменится интерфейс. Программе необходимо помнить, за какие игры голосовал конкретный пользователь, и учитывать это в счётчике и кнопке, чтобы проголосовать можно было **только один раз** 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1555_1709112845.png)

## Как реализовать голосование в проекте

При клике на карточку игры осуществляется переход на страницу с её детальным описанием — компонент `GamePage`. Это клиентский компонент, и в момент его монтирования в браузере пользователя вызывается два хука `useEffect` 👇🏻

```javascript
// Загружаем информацию об игре
useEffect(() => {
	async function fetchData() {
	  const game = await getNormalizedGameDataById(
		  endpoints.games,
	    props.params.id
	  );
	  isResponseOk(game) ? setGame(game) : setGame(null);
	  setPreloaderVisible(false);
  }
  fetchData();
}, []);

// Получаем данные о пользователе и сохраняем их
useEffect(() => {
	const jwt = getJWT();
  if (jwt) {
	  getMe(endpoints.me, jwt).then((userData) => {
		  if (isResponseOk(userData)) {
	      setIsAuthorized(true);
        setCurrentUser(userData);
      } else {
        setIsAuthorized(false);
        removeJWT();
      }
    });
  }
}, []);
```

В первом хуке функция `fetchData` загружает информацию об игре, эти данные проходят этап нормализации в функции `getNormalizedGameDataById`, и затем, если всё прошло успешно, в состояние компонента сохраняются нормализованные данные об игре в переменную состояния `game`

Во втором хуке при содействии `JWT` и функции `getMe` получаем данные о пользователе и сохраняем их в переменные состояния компонента:

- `isAuthorized` — `boolean`-переменная, описывающая, зарегистрирован ли пользователь
- `currentUser` — данные о конкретном пользователе (самая важная часть которых — `id` пользователя)

Все эти данные пригодятся нам для организации голосования.

### Изменяем интерфейс

**Шаг 1. Функция-помощник `checkIfUserVoted`**

Для начала добавь функцию-помощник для определения, голосовал ли за игру пользователь ранее. 

В файл `api-utils.js` запиши функцию `checkIfUserVoted` 👇🏻

```javascript
export const checkIfUserVoted = (game, userId) => {
  return game.users.find((user) => user.id === userId);
};
```

Аргументами она принимает данные об игре `game` и идентификатор пользователя `userId`. В каждом объекте с описанием игры есть массив пользователей — `users` 👇🏻

![](https://pictures.s3.yandex.net:443/resources/Frame_1556_1709112927.png)

Массив хранит информацию о пользователях, которые проголосовали за эту игру. 

Методом `find` ты можешь пройтись по массиву пользователей и сравнить `id` тех, кто уже голосовал с `userId`, определив, принимал ли ранее пользователь с `userId` участие в голосовании.

**Шаг 2. Импорт функции `checkIfUserVoted` и добавление хуков**

Теперь импортируем функцию `checkIfUserVoted` в компонент `GamePage` и добавим пару хуков для возможности голосования.

Добавь хук `useState` для хранения значения, голосовал ли пользователь ранее. Это будет простая `boolean`-переменная, изначально запиши в неё `false` 👇🏻

```javacsript
const [isVoted, setIsVoted] = useState(false);
```

Круто! Зная данные о пользователе и выбранной игре, ты можешь изменять интерфейс детальной страницы.

Запиши ещё один хук `useEffect`

После выполнения первых двух хуков `useEffect` в компоненте хранится информация о пользователе (`currentUser`) и об игре (`game`). Проверь, есть ли необходимые данные, функцией `checkIfUserVoted`, передав в неё `game` и `currentUser.id` 👇🏻

```javascript
useEffect(() => {
  if (currentUser && game) {
    setIsVoted(checkIfUserVoted(game, currentUser.id));
  } else {
		setIsVoted(false);
	}
}, [currentUser, game]);
```

В результате с помощью `setIsVoted()` ты сохраняешь в состояние компонента значение `true`, если пользователь ранее голосовал, или `false`, если нет (а также в случае некорректной загрузки данных).

**Шаг 3. Условия в интерфейс кнопки**

Значение переменной `isVoted` поможет изменять поведение кнопки голосования в зависимости от текущих данных. 

Добавь в её интерфейс пару условий 👇🏻

- Отключение кнопки, если пользователь не авторизован или голосовал ранее
- Изменение текста кнопки в зависимости  от переменной `isVoted`: 
а) если пользователь голосовал ранее `isVoted = true` — `"Голос учтён"`
б) в случае `isVoted = false` — `"Голосовать"`

```javascript
<button
  disabled={!isAuthorized || isVoted}
  className={`button ${Styles["about__vote-button"]}`}
  onClick={handleVote}
>
  {isVoted ? "Голос учтён" : "Голосовать"}
</button>
```

Для выполнения логики голосования добавь кнопке свойство `onClick={handleVote}` с обработчиком голосования.

Всегда пожалуйста!

### Как данные обновляются

Как ранее описано, данные об игре проходят сложный путь. 

Само описание игр хранится на сервере в API проекта. 

В компоненте `GamePage` они попадают через `fetch`-запрос к API и к последующей нормализации через функцию `getNormalizedGameDataById` (в ней изменяются поля `category` и `users` в объекте, описывающем игру).

В результате в нашем проекте есть два объекта с описанием игры:

- Один хранится на сервере с полями `categories` и `users_permissions_users` (его мы получаем с помощью get-запроса к API).
- Второй — это объект, прошедший нормализацию данных с полями `category` и `users` (он хранится локально на клиенте и используется для построения интерфейса).

Чтобы синхронизировать данные и учитывать голос пользователя при клике на кнопку, нужно обновлять информацию о проголосовавших пользователях сразу в двух местах:

- Обновить API.
- Обновить состояние в проекте.

### Время голосовать

**Шаг 1. Обновление API**

Начнём с обновления API. Для этого необходимо сделать **`PUT`-запрос** на сервер. 

Тебе уже знакомы методы `GET` для получения данных, `POST` для отправки и сохранения новых данных. Метод `PUT` в свою очередь позволяет обновить объект с данными на сервере (как правило, весь объект целиком). Вместе с этим методом на сервер нужно отправить непосредственно объект с обновлёнными данными. 

Реализуй в файле `api-utils.js` асинхронную функцию `vote` с методом `PUT` для обновления списка проголосовавших пользователей в объекте с описанием игры.

Как и в предыдущих запросах к API, тебе понадобятся все накопленные знания про `async`/`await`, блок `try{…} catch{…}` и функцию `fetch`. Функция должна принимать аргументами:

- `url`-адрес для запроса
- `jwt`-токен зарегистрированного пользователя (во избежание нечестных накруток голосов)
- `usersArray` — новый массив проголосовавших пользователей (именно его ты и будешь обновлять в описании игры)

От функции `getMe` запрос `vote` должен отличаться лишь в функции `fetch`

Вот тебе описание того, что должно происходить в твоём коде:

1. В методе запроса укажи значение `'PUT'`
2. В заголовках добавь свойство `'Content-Type': 'application/json',` так как будешь передавать часть кода с помощью JSON
3. Добавь свойство `body`, в котором передашь объект с новым массивом проголосовавших пользователей
На стороне API в описании игры на сервере этот массив хранится в поле `users_permissions_users`, поэтому новый массив ты передаёшь в качестве значения для ключа `users_permissions_users`. И, конечно же, запаковываешь всё в JSON 👇🏻

    ```javascript
    body: JSON.stringify({ users_permissions_users: usersArray }),
    ```

```javascript
export const vote = async (url, jwt, usersArray) => {
  try {
    const response = await fetch(url, {
      method: 'PUT',
      headers: {
        'Content-Type': 'application/json',
        Authorization: `Bearer ${jwt}`,
      },
      body: JSON.stringify({ users_permissions_users: usersArray }),
    })
    if (response.status !== 200) {
      throw new Error('Ошибка голосования')
    }
    const result = await response.json()
    return result
  } catch (error) {
    return error
  }
}
```

**Шаг 2. Сообщение об ошибке**

Осталось только изменить сообщение об ошибке: если в результате запроса функции `vote` ответ сервера будет отличным от статуса 200, выведи ошибку с сообщением `'Ошибка голосования'` 👇🏻

```javascript
    if (response.status !== 200) {
      throw new Error('Ошибка голосования')
    }
```

Время научить программу изменять состояние приложения и обновлять интерфейс после голосования.

Последний штрих, и новая функциональность в приложении будет готова.

**Шаг 3. Функция `handleVote`**

`**handleVote**` — это функция-обработчик клика по кнопке голосования, она должна выполнять два действия:

- обновлять API
- обновлять состояние в проекте

Обновить API поможет PUT-запрос из функции `vote`, импортируй её в компонент `GamePage`. В запросе нужно передавать данные о пользователе: `jwt`-токен и массив проголосовавших пользователей 👇🏻

```javascript
const handleVote = async () => {
	const jwt = getJWT();
};
```

`handleVote` будет асинхронной функцией, так как в ней происходит запрос к API. 

`jwt`-токен ты получаешь с помощью функции `getJWT`, а новый массив проголосовавших пользователей создашь самостоятельно. 

Проверь актуальный массив пользователей в переменной `game`: 

- если его длина отлична от нуля, создай новый массив только из значений `id` каждого пользователя, в этом поможет метод `map` 👇🏻

    ```javascript
    game.users.map((user) => user.id)
    ```

- если за игру никто ранее не голосовал (`game.users.length` равен нулю), создай пустой массив с помощью литералов `[]`

Сохрани новый массив идентификаторов `id` в переменную `usersIdArray` и добавь в него `id` текущего пользователя `usersIdArray.push(currentUser.id)` 👇🏻

```javascript
const handleVote = async () => {
	const jwt = getJWT();
  let usersIdArray = game.users.length
	  ? game.users.map((user) => user.id)
    : [];
  usersIdArray.push(currentUser.id);
};
```

**Шаг 4. `PUT`-запрос**

Теперь у тебя есть всё, чтобы сделать `PUT`-запрос для изменения API. 

В переменную `response` ты будешь сохранять ответ сервера после выполнения PUT-запроса. А сейчас вызови функцию `vote` с аргументами:

- ``${endpoints.games}/${game.id}`` в качестве `url`-адреса запроса к API (тут обращаешься к описанию конкретной игры на сервере)
- `jwt`-токен зарегистрированного пользователя
- `usersIdArray` — массив `id` пользователей, проголосовавших за игру

```javascript
const handleVote = async () => {
	const jwt = getJWT();
  let usersIdArray = game.users.length
	  ? game.users.map((user) => user.id)
    : [];
  usersIdArray.push(currentUser.id);
  const response = await vote(
	  `${endpoints.games}/${game.id}`,
    jwt,
    usersIdArray
  );
};
```

Только в случае, если ответ от сервера успешный и API обновился, можно обновить состояние в приложении и изменить интерфейс.

Для этого проверь ответ от сервера `isResponseOk(response)`. И в положительном результате измени переменные состояния `isVoted` и `game`:

- вызов функции `setIsVoted(true)` установит значение `true` в переменной `isVoted`
- вызвав функцию `setGame()`, необходимо вернуть новый объект с аналогичным описанием игры, но изменённым значением ключа `users`. Тут используй оператор `spread` — `…` три точки перед переменной:
    
    а) строка `...game` — скопирует все поля `ключ: значение` из актуального объекта `game` в новый объект
    
    б) указав в конце ключ `users`, ты перезапишешь его значение на новое  
    
    в) аналогичным образом создай массив, в который распакуй существующих пользователей `...game.users` и добавь к ним текущего пользователя `currentUser` — это и будет новым значением для ключа `users` в обновленном описании игры — переменной `game` 👇🏻

    ```javascript
    // инициализируем новый объект с помощью фигурных скобок {}
    {
    	...game,
      users: [...game.users, currentUser],
    }
    ```

```javascript
const handleVote = async () => {
	const jwt = getJWT();
  let usersIdArray = game.users.length
	  ? game.users.map((user) => user.id)
    : [];
  usersIdArray.push(currentUser.id);
  const response = await vote(
	  `${endpoints.games}/${game.id}`,
    jwt,
    usersIdArray
  );
  if (isResponseOk(response)) {
	  setIsVoted(true);
    setGame(() => {
	    return {
	      ...game,
        users: [...game.users, currentUser],
      };
    });
  }
};
```

Данные сохраняются на стороне бэкенда и на клиенте.
