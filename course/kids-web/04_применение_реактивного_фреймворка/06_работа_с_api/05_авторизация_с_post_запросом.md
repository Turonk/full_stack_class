# Авторизация с POST-запросом

![](https://pictures.s3.yandex.net:443/resources/Worn-Ass-Semi-Gloss_56_1709049589.jpg)

При **авторизации** ты отправляешь свои данные на сервер, а в ответ получаешь право совершать какие-то действия на сайте. В случае с Pindie получается, что ты отправляешь на сервер адрес электронной почты и пароль, и если данные верны, то у тебя появляется возможность ставить лайки играм. Это называют **логином в приложение** (от англ. log in — «авторизоваться» или «войти в систему»), и ты постоянно сталкиваешься с этим — например, когда входишь в социальную сеть или при входе в этот курс о разработке. Выход из приложения называют **логаутом** (от англ. log out — «выйти из системы»).

Авторизация в Pindie будет работать так: при вводе электронной почты и пароля в форму будет отправляться запрос к серверу. Если с данными всё хорошо, отобразится сообщение `Вы авторизовались!` и форма закроется, а кнопка `Войти` в шапке сайта сменится на кнопку `Выйти`. Если данные будут неверными, высветится сообщение об ошибке.

### Шаг 1. Создаём функцию `authorize`

В прошлом уроке мы работали в файле `app/api/api-utils.js` — открой его. 

В нём нужно создать функцию `authorize`, а в ней написать запрос, отправляющий данные на сервер. Это должна быть асинхронная функция, поэтому добавь слово `async` при её определении (подробно об этом рассказывали в прошлых уроках). Параметры функции — адрес, на который функция должна отправлять данные, и сам объект с данными. Не забудь добавить `try`/`catch`, чтобы в случае ошибки возвращать её как результат работы функции.

```javascript
export const authorize = async (url, data) => {
	try {
    /* Код функции авторизации */
  } catch (error) {
		/* Указываем, что в случае ошибки надо возвращать ошибку */
    return error;
  }
};
```

### Шаг 2. Пишем `POST`-запрос

Теперь приступим к самому запросу (подробно о том, как работают запросы к серверу, читай в уроке второго модуля «Как писать запросы к серверу»). 

Диалог. Собака: Вот какие у нас запросы к этому запросу 😁

Диалог. Собака: 

- Чтобы отправить данные на сервер, надо использовать `POST`-запрос.
- Нужно указать, что тип контента, который мы отправляем, — `"application/json"`
- В теле запроса будут данные, которые функция `JSON.stringify()` приведёт к строке.
- Если код ответа сервера не будет равен `200` (это означает, что с запросом что-то не так), то нужно выдать ошибку. Это можно сделать так: `throw new Error("Ошибка авторизации")`. В таком случае функция перейдёт в блок `catch`, откуда мы вернём ошибку авторизации.

Адрес для отправки запроса: `${BASE_URL}/auth/local`, где `${BASE_URL}` — основной адрес для запросов к Pindie API.

```javascript
export const authorize = async (url, data) => {
  try {
		/* fetch-запрос к серверу */
    const response = await fetch(url, {
			/* указываем метод POST */
      method: "POST",
			/* 
				В headers добавляем информацию о передаваемом 
				в теле запроса типе данных
			*/
      headers: { "Content-Type": "application/json" },
			/* 
				В тело запроса добавляем приведённый к строке 
				объект с данными пользователя
			*/
      body: JSON.stringify(data),
    });
		/* 
			Проверяем, что с ответом сервера всё ок, и, если нет, кидаем ошибку 
		*/
    if (response.status !== 200) {
      throw new Error("Ошибка авторизации");
    }
		/* Сохраняем в константу result полученные данные */
    const result = await response.json();
		/* Возвращаем данные */
    return result;
  } catch (error) {
		/* Если выше произошла ошибка, то возвращаем данные об ошибке */
    return error;
  }
};
```

### Шаг 7. Добавляем переменные состояния

Теперь добавь переменные состояния, в которые будешь записывать данные формы, данные, полученные с сервера после запроса, и сообщение об успешной авторизации или ошибке. Пусть они называются `authData`, `userData` и `message`

Воспользуйся хуком `useState`, чтобы создать эти переменные. Вот изначальные состояния для каждой из них:

- у `authData` — объект `{ identifier: "", password: "" }`
- у `userData` — объект `null`
- у `message` — объект `{ status: null, text: null }`
В `status` мы будем писать, прошёл запрос или нет (`success` — если запрос прошёл, `error` — в случае ошибки), а в `text` — какое сообщение должно показываться пользователю.

```javascript
const [authData, setAuthData] = useState({ identifier: "", password: "" });
const [userData, setUserData] = useState(null);
const [message, setMessage] = useState({ status: null, text: null });
```

### Шаг 8. Создаём функцию `handleInput`

Пропиши функцию, которая будет собирать данные из полей формы и записывать их в стейт `authData`

Можно написать такую функцию, которая будет подходить для обработки сразу двух полей ввода. У полей ввода есть значения `name` — они будут доступны в событиях при наборе текста (о браузерных событиях рассказывали в уроке второго модуля «Переменная `event`»).

В React для обработки события ввода текста используется атрибут `onInput`. Вот как это выглядит 👇🏻

```javascript
<input
  onInput={handleInput}
  className={Styles["form__field-input"]}
  name="identifier"
  type="email"
  placeholder="hello@world.com"
/>
```

Функция `handleInput` будет обрабатывать это событие. Для начала выведи в консоль объект `event`, значение `name` и значение `value` 👇🏻

```javascript
const handleInput = (e) => {
  console.log(e)
  console.log(`${e.target.name}, ${e.target.value}`)
};
```

Ниже показываем, что получится, если ввести в поле `Email` цифру 1, а в поле `Пароль` — цифру 2. В консоли при событии набора текста появляются данные о поле, в которое вводится текст, и его значение. Например, `identifier, 1` значит, что `name` поля равен `identifier`, а значение (`value`) — `1`

{video:https://code.s3.yandex.net/kids-web/vids/Запись_экрана_2024-01-30_в_15.31.55.mp4|controls:true|autoplay:0|pip:false|controlsList:nodownload}

По значению `e.target.name` можно находить нужное нам поле в объекте `authData`. Вот как он выглядит изначально: `{ identifier: "", password: "" }`. Значит, можно записывать новое значение, указывая соответствующий ключ. 

Можно сделать обработчик изменения каждого поля по отдельности, но это неудобно. Поэтому сделаем так, чтобы один обработчик мог подойти каждому полю ввода.

Пусть при изменении поля объект `authData` копируется, у него меняется нужное значение и эта копия становится новым значением `authData` 👇🏻

```javascript
const handleInput = (e) => {
	const newAuthData = authData;
	newAuthData[e.target.name] = e.target.value;
	setAuthData(newAuthData);
}
```

С помощью спред-синтаксиса `…` мы можем сделать примерно то же самое изящнее и короче: при обновлении стейта повторится имеющийся объект, а затем изменится значение в нужном нам поле. Подробнее о спред-синтаксисе можешь почитать в [Доке](https://doka.guide/js/spread/){target="_blank"}.  

Вот как в итоге будет выглядеть работающая функция `handleInput` 👇🏻

```javascript
const handleInput = (e) => {
	/* 
		В объекте authData по ключу e.target.name находится 
		изменяемое значение и перезаписывается
		новым текстом из поля ввода (e.target.value). 
		Спред ... перед authData нужен, чтобы сохранить
		данные, не изменившиеся при вводе текста в одном из полей
	*/
  setAuthData({ ...authData, [e.target.name]: e.target.value });
};
```

Ты практически у цели! 

### Шаг 9. Добавляем обработчик отправки формы

Мы уже рассказывали про работу с формами в уроке второго модуля «Формы». Но в React всё устроено немного иначе. Функция-обработчик события отправки формы в React записывается в атрибут `onSubmit` 👇🏻

```javascript
<form onSubmit={handleSubmit} className={Styles["form"]}>
	{/* Содержимое формы */}
</form>
```

Сама функция-обработчик должна:

- предотвращать стандартное поведение формы
- вызывать функцию `authorize`
- проверять, что пришёл правильный ответ от сервера (для этого используй функцию `isResponseOk`, которую мы добавили в уроке «`Fetch` на сервере и клиенте»)
- записывать полученные данные в переменную состояния `userData`

Также здесь можно вернуться к переданной через `props` функции `setAuth` — она будет менять состояние, в зависимости от которого меняется текст кнопки в шапке сайта. Тут же надо в зависимости от ответа сервера устанавливать либо сообщение об авторизации, либо текст ошибки 👇🏻

```javascript
const handleSubmit = async (e) => {
	/* Предотвращаем стандартное поведение формы */
  e.preventDefault();
	/* Вызываем функцию authorize с данными из формы */
  const userData = await authorize(endpoints.auth, authData);
	/* Проверяем ответ сервера с помощью isResponseOk */
  if (isResponseOk(userData)) {
		/* Записываем в стейт данные пользователя с сервера */
    setUserData(userData);
		/*  */
    props.setAuth(true);
		/* Записываем сообщение об авторизации */
    setMessage({ status: "success", text: "Вы авторизовались!" });
  } else {
		/* Записываем сообщение об ошибке */
    setMessage({ status: "error", text: "Неверные почта или пароль" });
  }
};
```

### Шаг 10. Добавляем сообщение об успехе или ошибке

{message.status && (

### Шаг 12. Скрываем всплывающее окно

Добавь эффект, который будет скрывать всплывающее окно, если пользователь авторизовался.

Для этого понадобятся хорошо знакомые тебе хук `useEffect` и функция `setTimeout` 👇🏻

```javascript
useEffect(() => {
  let timer; 
  if (userData) {
    timer = setTimeout(() => {
			/* В props close лежит функция закрытия попапа */
      props.close();
    }, 1000);
  }
  return () => clearTimeout(timer);
}, [userData]);
```
