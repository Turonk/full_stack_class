Часть 1. Визуальный интерфейс

В твоём коде должна быть папка `app/components`, в которой будут храниться компоненты, из которых, собственно, и строится Pindie. То есть визуальный интерфейс нужно разбить на следующие компоненты:

- `AuthForm` — компонент с формой авторизации - `Banner` - `Card` — компонент карточки игры - `CardListSection` — компонент, в котором отображается либо слайдер, либо список карточек игр - `Footer` — подвал сайта - `GameNotFound` — компонент, который возникает, если пользователь пытается попасть на страницу несуществующей игры - `Header` — компонент шапки сайта - `Overlay` — компонент, который используется вместе с попапом формы авторизации для затемнения фона - `Popup` — компонент попапа - `Preloader` — компонент, который используется во время ожидания загрузки данных - `Promo` — компонент для получения промокода

В папке `app` должны присутствовать папки для соответствующих страниц:

- `games/[id]` — страница конкретной игры - `new` — страница новых игр - `popular` — страница популярных игр - Страницы игр по жанрам:

1) `pixel-games`

2) `runners`

3) `shooters`

4) `tds`

Часть 2. Маршрутизация

Обязательно проверь, что:

- Активный пункт меню подсвечивается и через меню можно переходить на страницы разделов. - На самих страницах разделов отображаются списки с карточками определённой категории. - Роутинг настроен так, что клики по карточкам ведут на детальные страницы карточек, где выводится информация о конкретной игре и в неё можно играть.

Часть 3. Авторизация

- Компонент `<AuthForm/>` позволяет пользователю авторизоваться по логину и паролю. - Форма выводит сообщение об авторизации или возникшей ошибке в интерфейс. - После авторизации `JWT`-токен пользователя сохраняется в `localStorage` браузера. - После авторизации меняется состояние и текст кнопки в шапке сайта. - После авторизации форма скрывается через таймаут в одну секунду.

Часть 4. Голосование

- Детальная страница игры, получая данные об авторизованном пользователе, проверяет наличие голоса за эту игру. - Если пользователь голосовал, кнопка голосования меняет текст внутри себя, а также принимает атрибут `disabled` и становится недоступна для клика. - Если пользователь не голосовал, при клике на кнопку голосования отправляется `PUT`-запрос на эндпоинт игры. В ключ `users` записывается новый голос. - Если `PUT`-запрос отправлен, информация о голосе авторизованного пользователя записывается в состояние игры, обновляя ключ `users`

Часть 5. Отдельный компонент `App.jsx`

Изначально мы создавали компонент `App.jsx` в уроке про **React Context** (код компонента можно подсмотреть там же, но помни, что он видоизменялся с использованием **Zustand**).

Как это было, смотри в уроках «Встроенное решение — React Context», «Внешние стейт-машины. Zustand». Компонент `App` — обёртка для всего приложения, в нём будем проверять авторизацию пользователя.

Часть 6. Получение данных на страницах

Для того чтобы получить список игр в компонентах страниц `Home`, `New`, `Pixel`, `Popular`, `Runner`, `Shooter`, `Tds`, необходимо использовать хук `useGetDataByCategory`, который мы создавали на уроке «Глобальное состояние. Идея».

Часть 7. Использование стора Zustand

Для хранения данных авторизованного пользователя нужно использовать стор, созданный с помощью библиотеки Zustand. Как это сделать, мы показали в уроке «Внешние стейт-машины. Zustand».

Проверь, что компоненты, использующие данные об авторизованном пользователе, получают их с помощью Zustand.

Дополнительные задания по желанию

Если с обязательными требованиями всё и ты теперь думаешь, как можно улучшить Pindie, то вот набросали для тебя несколько идей:

- Добавь возможность регистрировать нового пользователя. Для этого тебе нужно будет сделать новый компонент с формой регистрации, аналогичный тому, что мы использовали для авторизации пользователя. Для регистрации можешь использовать эндпоинт: `/auth/local/register`, на него нужно отправить `POST`-запрос в формате JSON c телом `{username: имя, email: почта, password: пароль}` - Сделай страницу профиля пользователя, где будут отображаться его данные. Сами данные можно брать из эндпоинта `/me`, доступ неавторизованному пользователю на страницу должен быть закрыт. - Сделай кнопку в шапке сайта для перехода на страницу пользователя. - Сделай кнопку выхода из профиля на странице профиля пользователя. Если выход был осуществлен по кнопке на странице профиля, то необходимо вместо неё открыть главную страницу.
