## Стадии жизненного цикла

React-приложение — это настоящий театр, где каждый компонент, подобно актёру, выходит на сцену, исполняет свою роль и уходит за кулисы.

Компоненты проходят через три основные стадии: монтирование, обновление и размонтирование.

**Монтирование** — это момент, когда компонент выходит на сцену. На этой стадии он готовится к тому, чтобы быть внедрённым в DOM и отображаться пользователю. Здесь происходит его инициализация, установка параметров и рендеринг.

**Обновление** наступает, когда компонент получает новые параметры, которые нужно отобразить. На этой стадии происходит перерисовка компонента, которая включает в себя проверку, действительно ли компонент должен обновиться. В случае положительного ответа начинается повторный рендеринг компонента с новыми данными.

**Размонтирование** — это завершение выступления компонента. На этой стадии он подготавливается к своему удалению из DOM. Здесь освобождаются ресурсы и React-приложение перестаёт следить за изменениями.

### Жизнь и гибель классового компонента

Создадим классовый компонент кнопки 👇🏻

```javascript
import React from 'react';

export default class Button extends React.Component {
	// Конструктор компонента
	constructor(props) {
		super(props);
	}

	// Метод рендеринга
	render () {
		return (
			<button>{this.props.text}</button>
		);
	}
}
```

В коде выше мы создаём класс `Button`, который расширяет базовый класс `Component` из библиотеки React. В этом нам помогает ключевое слово `extends`, которое так и переводится — «расширяться». Оно позволяет использовать стандартную функциональность, предоставляемую базовым классом.

Далее мы создаём конструктор компонента. Метод `constructor` вызывается автоматически при создании экземпляра класса. Другими словами, импортируя и используя компонент на странице, мы создаём кнопку по шаблону `Button` и заполняем её параметрами. Ключевое слово `super` передаёт компоненту `props`

Метод `render` основной и обязательный в классовом компоненте. Он отвечает за его рендеринг на экране. Внутри этого метода мы возвращаем JSX-разметку, которая определяет внешний вид нашей кнопки.

Мы разобрали пример с классовым компонентом, но до этого всегда писали функциональные. 

Единственное отличие заключается в способе записи: классовый компонент использует ключевые слова `class` и `extends`, а также методы `constructor` и `render`

Кстати, методов гораздо больше, у каждой стадии жизненного цикла свои.

### Методы монтирования

При монтировании запускаются методы, связанные с созданием и отображением компонента. С методами `constructor` и `render` мы уже познакомили тебя выше, но у нас есть ещё парочка:

- `componentWillMount` — выполняется перед тем, как компонент впервые будет отрисован. Здесь можно выполнить настройку компонента.
- `componentDidMount` — выполняется после первого рендеринга, здесь обновляется DOM, срабатывают обработчики событий.

Вместе методы монтирования будут выполняться в следующем порядке 👇🏻

```javascript
constructor(props) {
	super(props);
	console.log("Шаг 1. Компонент создан, но ещё не виден");
}
componentWillMount() {
	console.log("Шаг 2. Компонент готовится к появлению");
}
render () {
	console.log("Шаг 3. Компонент рендерится");
	return (<button>{this.props.text}</button>);
}
componentDidMount() {
	console.log("Шаг 4. Компонент появился на экране");
}
```

В песочнице выше происходит следующее:

1. Устанавливаются начальные параметры кнопки в конструкторе.
2. Вызывается метод подготовки к рендерингу, после чего происходит сам рендеринг.
3. После появления кнопки на экране вызывается метод, отвечающий за завершение монтирования. В это время в консоль выводятся шаги всего процесса, позволяя нам отслеживать каждый этап выполнения кода.

В работе с методами важен порядок!

Аски пытался получить текст из заголовка `<h1>` ещё до монтирования. Неудивительно, что в консоль выводится `null`, так как компонент не успел пройти этап рендеринга и пока не существует в дереве DOM. 

Если попробовать ещё раз, но уже после рендеринга в методе `componentDidMount`, увидим в консоли успешный вывод нашего заголовка.

Этот пример подчёркивает, что некоторые действия, такие как работа с элементами DOM, следует выполнять только после успешного рендеринга компонента. Такой подход позволяет избежать ошибок при взаимодействии с элементами страницы.

### Методы обновления

После монтирования компонент может обновляться из-за изменений его параметров или состояния. В этом случае в игру вступают методы обновления:

- `shouldComponentUpdate` — выполняется перед обновлением компонента. Этот метод проверяет, должен ли обновляться компонент. Если да, возвращает значение `true`, а если новых параметров нет и обновление не требуется, возвращает значение `false` (по умолчанию метод возвращает `true`, даже если мы его не используем).

- `componentWillUpdate` — выполняется прямо перед повторным рендерингом при изменении `props` и если метод `shouldComponentUpdate` подтвердил, что компонент нужно обновить, вернув значение `true`
- `componentDidUpdate` — выполняется после успешного рендеринга при изменении компонента. Обновляет DOM в соответствии с новыми изменениями.

```javascript
shouldComponentUpdate() {
	console.log("Шаг 5. Указываем, нужно ли обновлять компонент");
	return true;
}
componentWillUpdate() {
	console.log("Шаг 6. Компонент готовится к обновлению");
}
componentDidUpdate() {
	console.log("Шаг 7. Компонент обновлён");
}
```

### Методы размонтирования

При размонтировании запускается всего один метод `componentWillUnmount`. Он выполняется перед тем, как компонент будет удалён из DOM.

```javascript
componentWillUnmount() {
	console.log("Шаг 8. Компонент готовится к удалению")
}
```

Нужен этот метод для поддержания чистоты веб-приложения. Пользователь может взаимодействовать с разными компонентами, и иногда не все они должны оставаться активными на протяжении всей работы. 

Вызывая этот метод, мы можем произвести необходимую очистку и освободить ресурсы браузера для работы с другими компонентами.

Работа с жизненным циклом делает компоненты интерактивными и придаёт всему сайту динамичности. 

Важно понимать, что не всегда нужно работать со всеми стадиями — это зависит от компонента. Но важен порядок!
