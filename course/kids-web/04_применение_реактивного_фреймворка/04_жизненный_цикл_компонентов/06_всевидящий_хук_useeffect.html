Всевидящий хук useEffect

![](https://pictures.s3.yandex.net:443/resources/Worn-Ass-Semi-Gloss_42_1707834348.jpg)

Эффекты компонента

Все события жизненного цикла компонента называются **эффектами.** Эффекты возникают, когда что-то происходит внутри компонента. Например, меняется его состояние, обновляются входящие параметры и многое другое.

Работа с эффектами требует внимательности и постоянного контроля, чтобы не допустить появления ошибок. Для надёжного управления эффектами в React используется мощный хук — `useEffect`. Он занимает второе место по популярности после `useState` и предоставляет гибкие возможности работы с жизненным циклом компонентов.

Для использования `useEffect` необходимо его импортировать 👇🏻

'use client';
import {useEffect} from 'react';

{quiz-task} background: | #f1f1ef content: | 📌 Ещё раз обратим внимание, что запись `'use client'` указывает на использование нового хука именно в клиентском компоненте. В React большинство хуков предназначены для работы с клиентскими компонентами, поскольку сама библиотека используется для создания интерфейсов, с которыми взаимодействует пользователь в браузере. Поэтому для правильной работы хука важно иметь доступ к дереву DOM, который есть только у клиентских компонентов. {/quiz-task}

Знакомство с `useEffect`

Хук `useEffect` — это многофункциональный инструмент, который позволяет отслеживать любые изменения в компоненте и обрабатывать эффекты в нужный момент.

Изменения внутри компонента могут происходить на разных стадиях жизненного цикла, и `useEffect` готов к использованию в каждой из них:

- при первом отображении компонента на экране, - при обновлении компонента, - при удалении компонента из DOM.

Хук полезен для выполнения разнообразных задач — от получения данных с сервера, добавления или удаления элементов дерева DOM до установки таймеров и интервалов.

Синтаксис хука `useEffect` выглядит следующим образом 👇🏻

useEffect(() => {
	// Пишем код, который хотим выполнить
}, [/* Указываем, на какие изменения реагировать */])

Сначала мы вызываем хук, используя конструкцию **`useEffect(...)`**. Затем передаём в него два обязательных аргумента: функцию, которая должна выполниться, и массив переменных, за изменениями которых нужно следить.

**Стрелочная функция** в роли первого аргумента содержит код обработки эффекта, который будет выполнен в нужный момент.

Определить тот самый момент*,* когда хук должен запуститься, помогает второй аргумент — **массив зависимостей**. Можно представить его работу как настройку будильника. Если передать в него одну или несколько переменных, хук будет ждать изменений этих переменных и запустится, как только они произойдут.

В коде мы дополнительно используем хук `useState`, чтобы создать два состояния — для хранения сообщения корзины и товара, который в эту корзину будет добавлен.

При клике на кнопку срабатывает функция `handleClick`, которая принимает в качестве аргумента желаемый товар. Внутри этой функции мы обращаемся к `setItem`, чтобы поместить название товара в переменную состояния `item`

В массиве зависимостей хука `useEffect` мы указываем эту переменную, поэтому хук моментально замечает изменения и обрабатывает эффект смены состояния, запуская стадию обновления компонента.

Внутри хука срабатывает функция `setMessage`, которая устанавливает нужный текст внутри корзины. А так как компонент повторно рендерится, кнопка приобретает новые стиль и текст внутри благодаря условному рендерингу.

Настройка зависимостей

Массив зависимостей позволяет настроить хук для обработки эффектов на разных стадиях жизненного цикла.

Пришло время познакомиться с тонкостями работы этого параметра. Мы рассмотрим все три возможных варианта: хук записан совсем без этого массива, с пустым массивом `[]` и с заполненным.

Отсутствие массива

Если вообще не указывать зависимости, хук `useEffect` будет запускаться при каждом рендеринге компонента. Рендеринг происходит не только на стадии монтирования, но и на стадии обновления. Это может привести к дублированию операций и другим нежелательным эффектам. Лучше всегда указывать массив зависимостей, даже если он пуст. Такой подход избавит от непредсказуемого поведения компонента на всех стадиях жизненного цикла.

Пустой массив

Если оставить массив зависимостей пустым, хук `useEffect` будет работать так, словно мы установили будильник на ранний подъём. Он будет запускаться только один раз, когда компонент просыпается, а именно при его первом отображении. Пустой массив зависимостей позволяет использовать хук `useEffect` на стадии монтирования, подобно методу `componentDidMount` в классовом компоненте.

![](https://pictures.s3.yandex.net:443/resources/Frame_1497_1707834630.png)

В этом случае `useEffect` работает как индикатор того, что компонент появился на экране и можно начинать работу с DOM. Нам открывается возможность использования браузерных методов, таких как `querySelector` или `getElementByI`, манипуляций с элементами дерева DOM (начиная от поиска элементов и заканчивая установкой обработчиков событий, таймеров или интервалов).

Множество зависимостей

Хук `useEffect` может следить сразу за несколькими параметрами, которые указаны в массиве зависимостей.

Представь, что у нас есть компонент с часами, который отображает текущее время и приветствует пользователя по имени. Новый хук позволяет обновлять компонент при эффекте изменения времени или имени пользователя.

Прежде чем углубимся в этот пример, познакомим тебя с новыми функциями, которые используем в нём.

В примере выше хук `useEffect` запускается при появлении компонента и при каждом изменении состояния времени или параметров. Получается, что хук работает на стадии монтирования и обновления, подобно методам `componentDidMount` и `componentWillUpdate` в классовом компоненте.

Внутри хука `useState` мы используем необычный тип данных — `Date`. Он хранит в себе информацию о текущих дате и времени.

Функция `setTime` нужна для изменения состояния времени, так как оно меняется каждую секунду.

Интервал внутри хука `useEffect` меняет состояние времени `time`, используя функцию `setTime`. Вторым параметром интервала указана частота повторения этого действия в миллисекундах, поэтому время обновляется каждую секунду.

Обрати внимание на массив зависимостей, в котором указано несколько переменных — **`[time, props]`**, от изменений которых зависит выполнение хука.

Таким образом, каждую секунду вызывается функция `setTime`, которая устанавливает новое время в переменную `time`. В свою очередь, хук `useEffect` следит за этой переменной и перерисовывает компонент, отображая актуальное время.

{quiz-task} background: | #f1f1ef content: | 📌 Обрати внимание на консоль! Внутри хука мы выводим сообщение `Обновляю время`, которое появляется в консоли каждую секунду. {/quiz-task}

Можно заметить, что мы используем функцию `clearInterval` в необычной конструкции `return(() ⇒ …)` для остановки обновления времени. Это ещё одна важная функция хука `useEffect`

Деструктивная сила

Хук `useEffect` способен не только выполнять эффекты на стадиях монтирования и обновления компонента, но и контролировать стадию его размонтирования.

Вернёмся к синтаксису `useEffect`👇🏻

useEffect(() => {
	// Пишем код, который хотим выполнить
	return () => {
		// Пишем код, который хотим выполнить перед удалением
	}
}, [/* Указываем, на какие изменения реагировать */])

Теперь у нас есть вторая функция, возвращаемая из основной функции хука. Она выполняется перед тем, как компонент будет размонтирован, подобно методу `componentWillUnmount` в классовом компоненте. Возвращаемая функция, или функция очистки, позволяет выполнить необходимые действия перед удалением компонента.

Здесь мы используем функцию **`clearInterval(interval)`** внутри возвращаемой функции. Этот трюк позволяет избежать возможных проблем, связанных с длительными задачами, которые могут продолжаться после того, как компонент был удалён из DOM.

Веб-разработчики называют **`clearInterval(interval)`** **функцией очистки.** Она удаляет созданный временной интервал перед тем, как компонент будет полностью размонтирован. Без этой функции при каждом обновлении компонента у нас появлялось бы всё больше и больше интервалов. Возвращаемая функция предотвращает этот негативный эффект, освобождая ресурсы и обеспечивая чистоту кода.

Лови расшифровку!

- Хук `useEffect` с пустым массивом зависимостей работает подобно **стадии монтирования.** Обработка эффекта внутри хука выполняется только при первом отображении компонента. - Если указать массив зависимостей, хук `useEffect` начинает следить за изменениями указанных переменных. Код внутри хука срабатывает при монтировании компонента и при каждом обновлении указанных переменных, подобно **стадии обновления.** - Возвращаемая из хука функция выполняется перед размонтированием компонента. Это даёт возможность совершать дополнительные действия, такие как очистка ресурсов или удаление слушателей событий, как на **стадии размонтирования**. - Массив зависимостей стоит указывать всегда, даже если он будет пуст. Это поможет предотвратить хаотичное обновление и перерисовку компонента.

Работа над Pindie

Теперь ты можешь эффективно управлять жизненным циклом функциональных компонентов в React, используя хук `useEffect`. Давай вместе пошагово оживим кнопку получения промокода в компоненте `Promo`

После урока про использование хука `useState` компонент `Promo` преобразился. Теперь при клике на кнопку `Получить код` внутри неё отображается `<span>` с промокодом.

Используя хук `useEffect` обработай эффект, при котором появившийся промокод исчезает через пять секунд, а кнопка возвращает своё прежнее состояние.

Шаг 1: Импортируй хук `useEffect`

"use client";
import { useState, useEffect } from "react";

На этом шаге добавь хук `useEffect` в компонент `Promo`

Шаг 2: Инициализируй хук

useEffect(() => {
	// Здесь будет таймер для кнопки
}, [codeIsVisible]);

В качестве массива зависимостей укажи состояние промокода `codeIsVisible`, чтобы запускать таймер каждый раз, когда его состояние переключается в значение `true`

Шаг 3: Подготовь таймер

useEffect(() => {
	let timeout;
	if (codeIsVisible) {
		// Здесь будет таймер для кнопки
	}
}, [codeIsVisible]);

Создай локальную переменную `timeout`. Переменная будет принимать в себя таймер кнопки, а так как она находится на верхнем уровне функции, значит, будет доступна в возвращаемой функции в будущем.

Также сделай простую проверку переменной состояния `codeIsVisible`. Это важная проверка, так как скрывать промокод нужно только тогда, когда он отображён внутри кнопки, а значит, значение его состояния — `true`

Шаг 4: Создай таймер

useEffect(() => {
	let timeout;
	if (codeIsVisible) {
		timeout = setTimeout(() => {
			// Здесь будет код смены состояния
		}, 5000);
	}
}, [codeIsVisible]);

Присвой переменной `timeout` таймер, используя функцию `setTimeout`. Она позволяет выполнить какое-нибудь действие с задержкой. Первым аргументом она принимает функцию, которую нужно выполнить (конструкция **`() ⇒ {…}`**). Второй аргумент после запятой — время в миллисекундах, которое нужно выждать перед выполнением функции.

Более подробное описание этой функции и примеры можно найти в [Доке](https://doka.guide/js/settimeout/){target="_blank"}.

Установи второму параметру значение 5000 миллисекунд, что соответствует пяти секундам.

Шаг 5: Настрой таймер

useEffect(() => {
	let timeout;
	if (codeIsVisible) {
		timeout = setTimeout(() => {
			setCodeIsVisible(false);
		}, 5000);
	}
}, [codeIsVisible]);

Обратись к функции изменения состояния `setCodeIsVisible` внутри функции таймера. Она принимает в себя новое состояние в значении `false`, которое будет установлено через пять секунд после клика на кнопку.

Шаг 6: Очисти таймер

useEffect(() => {
	let timeout;
	if (codeIsVisible) {
		timeout = setTimeout(() => {
			setCodeIsVisible(false);
		}, 5000);	
	}
	return () => {
		clearTimeout(timeout);
	};
}, [codeIsVisible]);

Добавь возвращаемую функцию, которая будет удалять наш таймер после размонтирования компонента. Функция `clearTimeout` внутри функции очистки позволяет удалить таймер и принимает в себя единственный аргумент — сам таймер. Так как ты создаёшь для таймера локальную переменную `timeout`, можешь смело использовать её в этой функции.

Как это работает

При монтировании компонента `Promo` на странице сайта хук `useState` устанавливает состояние промокода в значение `false`. Это значит, что при загрузке страницы внутри кнопки будет отображаться не промокод, а текст `Получить код`

При клике на кнопку срабатывают сразу два хука:

1. `useState` переключает состояние промокода и вызывает стадию обновления.

2. `useEffect`, который внимательно следил за переменной `codeIsVisible`, запускает таймер. Он вернёт прежнее состояние в значение `false` через пять секунд после повторного рендеринга кнопки.

Чтобы не применять таймер к другим страницам, где нет компонента `Promo`, хук `useEffect` использует функцию очистки, которая удалит таймер перед размонтированием компонента.
