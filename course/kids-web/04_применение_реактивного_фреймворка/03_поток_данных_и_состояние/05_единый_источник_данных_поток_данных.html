Текущее состояние проекта Pindie

У нас есть главная страница — компонент `Home`, который лежит в файле `page.js` в папке `app`

В своей jsx-разметке компонент `Home` вызывает два списка — два одинаковых компонента `CardsList`, каждому из которых передаёт атрибут `id` со значениями `popular` и `new`

Внутри функции-компонента `CardsList` мы имеем два массива:

- массив `popularGames` (содержит данные для карточек популярных игр) - массив `newGames` (содержит данные для карточек новых игр)

Далее с помощью условного оператора мы определяем, какой именно массив с данными нам выбрать, чтобы отобразить список карточек 👇🏻

const targetArray =
    props.id === "popular" ? popularGames : props.id === "new" && newGames;

Это определение происходит как раз при помощи атрибута `id`, значение для которого было передано из верхнего уровня — из компонента `Home`, который вызывает компонент `CardsList`.

![](https://pictures.s3.yandex.net:443/resources/Frame_1471_1707225447.png)

В текущем состоянии проекта мы смешиваем данные со способом их отображения: храним два массива `popularGames` и `newGames` в самом компоненте `CardsList`

Это ведёт к следующим проблемам:

1. **Необходимость дублировать данные** Если мы захотим сделать ещё один список карточек с другим визуальным стилем, но который должен отображать тот же самый набор данных, нам необходимо будет скопировать массивы `popularGames` и `newGames` в этот новый компонент. Кроме того, данных в будущем будет больше, появятся новые типы карточек, и тогда компонент станет напоминать базу данных. 2. **Необходимость писать дополнительную логику** Сейчас в компоненте `CardsList` у нас есть условный оператор для определения массива, который мы берём для отображения. Но представь, что в приложении появились не просто новые и популярные игры, а, например, новые шутеры или еще хуже — новые популярные шутеры. В этом случае условный оператор будет очень сложным для чтения, понимания и поддержки.

Для этого нужно вынести массивы `popularGames` и `newGames` в другое место нашего приложения. Сейчас всё покажем.

Переезд данных

Для начала перенесём массивы на уровень выше — из компонента `CardsList` в компонент главной страницы `Home`, который лежит в файле `page.js` в папке `app` .

Так как `CardsList` больше не хранит в себе массивы с данными для карточек, их нужно передать в этот компонент, сделать это можно через атрибут, пусть он будет называться `data`. Внутри компонента `CardsList` доступ к нему можно получить через обращение к `props.data`

Обрати внимание: так как мы вынесли массивы `popularGames` и `newGames` на уровень выше, в компоненте `CardsList` теперь можно избавиться от условного оператора 👇🏻

const targetArray =
    props.id === "popular" ? popularGames : props.id === "new" && newGames;

Это стало возможным благодаря тому, что компонент `CardsList` больше не хранит и не определяет, что именно ему нужно отобразить, — иными словами, он стал глупым.

Только тот был в поиске мозгов, а нашему компоненту глупость, наоборот, очень даже кстати. Такой компонент рисует те данные, которые в него были переданы, и не выполняет более никаких задач. Это делает его более простым в использовании и поддержке.

Функция-фильтр

В данный момент у нас есть только главная страница `Home`, но в ней два раза вызывается компонент `CardsList` c разными массивами данных, поэтому нам необходимо написать функцию, которая из большого массива `data` будет вычленять только те данные, которые нужно передать в соответствующий `CardsList`

Пусть эта функция будет называться `getGamesByCategory`

Чтобы написать такую функцию, нужно освоить методы `find` и `filter` для работы с массивами в JavaScript. Немного отвлечёмся от Pindie и на простых примерах разберёмся, как работают эти методы.

Метод `find`

Метод `find` (который мы подробно разбирали в прошлом модуле) принимает в качестве аргумента функцию проверки условия и вызывает эту функцию для каждого элемента массива, пока не найдёт тот, для которого эта функция вернёт значение `true`

Этот элемент массива возвращается в качестве результата метода `find`

Изучи его на практике и потренируйся в песочницах — в каждой из них есть код с комментариями, результаты работы метода `find` также логируются в консоль.

Метод `filter`

Метод `filter` (его мы тоже подробно изучали в прошлом модуле) принимает в качестве аргумента функцию проверки условия и вызывает эту функцию для каждого элемента массива. В качестве результата метод `filter` возвращает новый массив, состоящий из элементов, для которых функция проверки условия вернула `true`

`getGamesByCategory`

Теперь настало время написать ту самую функцию `getGamesByCategory`, которая из массива `data` будет доставать объекты с данными игр, подходящими под ту или иную категорию.

Например, у нас есть категория новых игр — `getGamesByCategory` должна возвращать массив, содержащий в себе только те объекты из массива `data`, у которых в поле `category` есть категория с полем `name: "new"`

Уже сейчас мы можем написать заготовку функции `getGamesByCategory`, в качестве аргумента она будет принимать строку `category` — имя категории.

const getGamesByCategory = (category) => {
	...
};

Для этого нужно воспользоваться методом `find`

У каждого объекта есть поле `category` — массив с категориями, к которым относится игра. Если в этом массиве будет категория, у которой поле `name` равняется нужному нам названию категории, то такой объект подходит.

Если метод `find` вернёт не `undefined`, значит, принадлежит 👇🏻

Правильный вопрос!

Для этого используем метод `filter`. Для каждого элемента массива `data` проверяем его принадлежность к нужной категории, как мы это делали выше: если принадлежит, `filter` добавит его в новый массив.

Обрати внимание, что в качестве результата функции проверки условия для `filter` возвращается результат работы метода `find`

Да! Раньше в наших примерах функция проверки условия явно проверяла что-то при помощи `===, <, >`, а сейчас функция проверки возвращает результат `find` (либо `undefined`, либо объект такого вида `{id: …, name: …}`).

В данном же случае метод `filter` воспринимает что-то отличное от `undefined` как `true`, а сам `undefined` — как `false`

В любом случае `getGamesByCategory` готова к вставке в проект. Добавим в папку `data` файл `data-utils.js`, откуда и будем экспортировать функцию-фильтр.

В качестве значений переменных `popularGames` и `newGames` будем использовать результат работы функции 👇🏻

const popularGames = getGamesByCategory("popular");
const newGames = getGamesByCategory("new");
