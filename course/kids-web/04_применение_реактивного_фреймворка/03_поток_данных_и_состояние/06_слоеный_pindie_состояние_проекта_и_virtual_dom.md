# Слоёный Pindie — состояние проекта и Virtual Dom

Скорее тебе пригодится чёрная водолазка, как у стильных архитекторов, ведь то, как приложение организовано, называют **архитектурой приложения**.

![](https://pictures.s3.yandex.net:443/resources/Worn-Ass-Semi-Gloss_31_1707295542.jpg)

Давай посмотрим, на какие части можно поделить Pindie.

![](https://pictures.s3.yandex.net:443/resources/Frame_1476_1707295579.png)

Первые два слоя — про данные и их преобразование. Подробно мы обсуждали их в прошлом уроке.

Затем — слои, которые мы уже изучали в уроке про React, Babel и React DOM на прошлой неделе:

1. Используя React, пишем разметку в JSX.
2. Babel переводит JSX-разметку в понятный браузеру JavaScript.
3. React DOM отрисовывает получившуюся HTML-разметку.

Наконец, HTML-разметка встраивается в DOM (подробно о нём говорили во втором модуле).

Такая архитектура приложения выглядит массивно, но зато компонентный подход и JSX позволяют  писать код быстрее. Но это не всё, что даёт React. 

На самом деле React ещё и делает сайт эффективнее.

Если работать с DOM напрямую, то обновление элементов может занимать достаточно много времени. Иногда мы можем менять DOM не самым простым для браузера способом. 

Например, у нас есть такая разметка 👇🏻

```javascript
<section class="section">
	<p class="hello">Привет!</p>
</section>
```

Мы хотим добавить вместо `<p>` с классом `hello` другой элемент `<p>` с помощью JavaScript.

Можно удалить этот элемент и вставить на его место новый. На чистом JS это будет выглядеть так 👇🏻

```javascript
// Находим контейнер, где хранится элемент
const section = document.querySelector(".section");
// Находим старый элемент
const oldElement = document.querySelector(".hello");
// Создаём новый элемент
const newElement = document.createElement("p");
// Задаём новому элементу нужное содержание и класс
newElement.textContent = "Новый текст!";
newElement.classList.add("hello");
// Удаляем старый элемент
oldElement.remove();
// Добавляем новый элемент в контейнер
section.append(newElement);
```

Но вообще-то эффективнее использовать такой способ 👇🏻

```javascript
// Находим элемент
const oldElement = document.querySelector(".hello");
// Меняем содержание
oldElement.textContent = "Новый текст!"
```

Да, можно каждый раз искать наиболее быстрый способ изменить DOM. Но чем больше операций с DOM нужно выполнить, тем больше времени будет занимать поиск лучшего решения. Да и операции с DOM в твоих работах становятся всё сложнее и их становится всё больше. Представь, что тебе надо учитывать эффективность обновления DOM каждый раз, когда ты скрываешь элементы в зависимости от условий или передаёшь компонентам `props`

React решает проблему обновления DOM, добавляя ещё один слой в архитектуру нашего приложения — копию реального DOM. Этот слой называют **Virtual DOM**.

![](https://pictures.s3.yandex.net:443/resources/Frame_1474_1_1707295696.png)

Изменения, которые должны произойти с сайтом, сначала вносятся в Virtual DOM. Virtual DOM не отрисовывается на сайте, а используется для вычислений: React сравнивает Virtual DOM с DOM сайта и находит элементы, которые должны измениться. Затем React рассчитывает наиболее эффективный и быстрый способ обновления DOM и использует его. В итоге тебе не приходится думать о том, как лучше всего взаимодействовать с DOM.

![](https://pictures.s3.yandex.net:443/resources/Frame_1477_1_1707295725.png)

Если представить, что DOM — дом, то Virtual DOM — чертёж этого дома. 

В случае, если нам нужно добавить стену в уже построенный дом, мы можем на чертеже определить самый лучший вариант, как это сделать, и только потом приняться за работу в настоящем доме. 

Так же и с DOM-деревом при использовании React: сначала собирается чертёж, описывающий, что и как нужно сделать, а затем происходит обновление. 

Соответственно, если у нас будет такой компонент...

```javascript
export const HelloReact = (props) => {
	return (
		<section className="section">
			{props.type === "hello" ? <p className="hello">Привет!</p> : <p className="hey">Хей!</p>}
		</section>
	)
}
```

…React при изменении `props.type` сделает следующее:

- внесёт обновления в Virtual DOM
- сравнит Virtual DOM с настоящим DOM
- найдёт достаточно быстрый способ обновить DOM
- внесёт изменения в DOM
