# Pulse FM / авторский хаб 2.0

Замыкающий проект спринта 2, уроки 7–13. Ученик переводит **свой** сайт из спринта 1 на Flask. Тексты стенда PulseDeck не копировать: карточки, имена и обложки остаются авторскими.

Спринт 1 оставил готовый HTML и CSS на диске. К уроку 13 тот же сайт открывается только по `http://127.0.0.1:5000`, данные карточек живут в Python, новая карточка добавляется формой.

## Что входит и что не входит

Входит:

- несколько HTML-страниц из общих шаблонов;
- CSS, картинки и при наличии аудио из `static/`;
- список словарей `ITEMS` в `app.py`;
- одна форма `POST`, которая дополняет этот список;
- свой ответ `404`.

Не входит в зачёт спринта 2: база данных, логин, `fetch`, JSON API, корзина, перенос чужого сайта. Список в памяти процесса пропадает при перезапуске сервера. Это называется вслух на уроке 11 и на защите.

## Маршруты

| Метод и путь | Кто отвечает | Что видит браузер |
| --- | --- | --- |
| `GET /` | `home` | Герой своего сайта и 3 первые карточки из `ITEMS` |
| `GET /catalog` | `catalog` | Все карточки, один цикл Jinja |
| `GET /item/<item_id>` | `item_page` | Одна карточка. Нет такого `id` — ответ `404` |
| `GET /about` | `about` | Кто автор и как называется проект |
| `GET /suggest` | `suggest` | Пустая форма |
| `POST /suggest` | `suggest` | Проверка полей, `ITEMS.append`, `flash`, redirect на `/catalog` |
| любой другой путь | обработчик `404` | Своя страница «такого адреса нет» и ссылка на `/` |

Имена функций можно оставить этими. Менять пути без причины не нужно: на защите преподаватель открывает одни и те же адреса.

## Данные

Один список в `app.py`. Минимум 6 карточек к защите — свои, не стендовые.

```python
ITEMS = [
    {
        "id": "flamewall",
        "title": "Flamewall",
        "subtitle": "Camellia",
        "meta": "6:50",
        "img": "flame.jpg",
        "blurb": "Почему эта карточка в моём эфире.",
    },
]
```

| Поле | Правило |
| --- | --- |
| `id` | Латиница, цифры и дефис. Уникален. Попадает в URL `/item/<item_id>` |
| `title` | Название карточки |
| `subtitle` | Автор, игра, источник — одно поле под заголовком |
| `meta` | Длительность, год или другая короткая подпись. Можно пустую строку |
| `img` | Только имя файла внутри `static/img/`, не путь `src/...` и не чужой URL |
| `blurb` | Одна-две фразы на странице карточки |

На главной в шаблоне берутся `ITEMS[:3]`. В каталоге — весь список. Так топ и полный список не расходятся.

```text

  base.html

  404.html

  css/style.css
  img/

```

`requirements.txt` содержит строку `flask`. Команды запуска в `README.md` ученика:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m flask --app app run --debug
```

## Форма `/suggest`

Поля: `title`, `subtitle`, `blurb`. Обложка на спринте 2 выбирается из уже лежащих файлов: `<select name="img">` с 2–4 именами из `static/img/`. Загрузку файла с диска не делаем.

Пустое `title` не добавляет карточку. Сервер делает `flash` с короткой причиной и `redirect` обратно на `/suggest`. Успех: новая запись в `ITEMS`, `flash` «карточка в эфире», `redirect` на `/catalog`. Обновление каталога не должно отправлять форму второй раз.

`id` для новой карточки собирает сервер из названия: нижний регистр, пробелы в дефисы, без пробелов в URL. Если такое `id` уже есть, к концу дописывается `-2`. Это показывает учитель на уроке 11, ученик переносит рабочий вариант.

`app.secret_key` нужен только для `flash`. Строка учебная, вслух: «это не пароль от банка и не секрет продакшена».

## Критерий «проект готов» до защиты

- [ ] Сервер запускается командами из README, адрес `http://127.0.0.1:5000/`
- [ ] На главной свой герой и 3 карточки из Python
- [ ] `/catalog` показывает все карточки одним циклом
- [ ] `/item/<id>` открывает существующую карточку
- [ ] `/about` — свой текст, не текст стенда
- [ ] Стили и картинки грузятся через `url_for('static', ...)`
- [ ] Форма добавляет карточку, после F5 на каталоге форма не отправляется снова
- [ ] Пустое название не попадает в список
- [ ] Неизвестный адрес и неизвестный `id` отдают свой `404.html`
- [ ] В `app.py` нет чужих названий со стенда

## Защита на уроке 13

До 6 минут на ученика. Гость в зале может продиктовать одну карточку в форму.

1. Открыть `/` и назвать, файл это или ответ сервера.
2. Показать `ITEMS` в `app.py` и ту же карточку на `/catalog`.
3. Перейти на `/item/<id>` по ссылке из каталога.
4. Добавить карточку из зала через `/suggest` и найти её в каталоге.
5. Открыть заведомо пустой путь и показать свой 404.

Оценка по рубрике, не по красоте относительно соседа.

| | Не зачёт | Зачёт | Сильно |
| --- | --- | --- | --- |
| Запрос | Сайт открыт как `file://` | Все страницы с `127.0.0.1` | Ученик сам называет метод, путь и обработчик |
| Данные | Карточки по-прежнему скопированы в HTML | Список в Python, цикл в каталоге | Может добавить поле и показать его в шаблоне |
| Форма | Кнопка ничего не меняет или ломает сервер | Валидная карточка появляется, пустая — нет | Объясняет, зачем redirect после POST |
| Ошибка | Чужой путь — белая страница Flask | Свой 404 и на пустой `id` | Ссылка с 404 возвращает на главную |
| Авторство | Тексты стенда | Свои карточки и обложки | Рассказывает, что перенёс со своего сайта спринта 1 |

Кто не успел форму, защищает маршрут и цикл. Форма добивается после урока и присылается скрином. Без работающего сервера питч не начинается: сначала поднять `flask run`, потом говорить.
