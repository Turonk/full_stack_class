## Цель урока

Ученик собирает панель плеера (кнопка, название, прогресс-бар) на flex и прибивает её к низу экрана через `position: sticky`. Плеер виден при любой прокрутке и **не перекрывает** контент. Ученик объясняет своими словами, чем `sticky` отличается от `fixed`.

**Один концепт дня:** плеер — это HUD сайта: всегда на экране, но живёт в потоке.

## 2. Завязка + предсказание · 10 мин

### Сцена

**Сказать:**

> MusicHub почти живой: тема есть, карточки есть. Но посмотрите на стенд: чтобы нажать Play, нужно **докрутить страницу до самого конца** — плеер лежит в подвале, как сломанная игрушка на антресоли. Класс прав: «плеер как в подвале».

> А как устроены настоящие плееры? В Spotify панель управления прибита к низу: крутишь каталог — она на месте. В играх то же самое называется **HUD** — панель здоровья и патронов внизу экрана. Она всегда с тобой, куда бы ты ни пошёл по уровню.

**Спросить:** В игре панель здоровья исчезает, когда ты скроллишь карту?
**Ждём:** нет, она всегда на экране.

### Предсказание (главное, до кода)

**Сказать:**

> В CSS есть три способа «вырвать» элемент из обычного потока:

- `fixed` — прибит к **окну** браузера навсегда;
- `sticky` — живёт в потоке, но **прилипает** к краю, когда докручиваешь до точки;
- `absolute` — вырван из потока и привязан к ближайшему родителю с `relative`.

**Спросить:** Что подходит плееру внизу каталога? Голосуем: fixed — правая рука, sticky — левая.
**Ждём:** спор. Обсудить: `fixed` тоже «всегда виден» — чем плох?

**Сказать:**

> Оба варианта держат панель на экране. Но `fixed` вырывает элемент из потока полностью — он переставляет занимать место, и последняя карточка каталога прячется **под** панелью. `sticky` честнее: элемент остаётся в потоке, просто прилипает. Наш выбор — **sticky**. А про запас снизу поговорим в блоке 4 — там ещё будет сюрприз.

## 3. Показываю · Блок 1: `position: sticky` · 7 мин

> Стенд открыт, Live Server включён. Каждая правка — сначала предсказание класса, потом Enter.

**Сказать:**

> Смотрим код на стенде:

```css
.player {
  position: sticky;
  bottom: 0;
  background: var(--bg-elev);
  border-top: 1px solid #2A3350;
  padding: 12px 20px;
}
```

> `position: sticky` — это элемент, который ведёт себя нормально, **пока** прокрутка не дошла до точки прилипания. `bottom: 0` — «не отпускай меня ниже нижнего края экрана». Дословно: «плыву с потоком, но у кромки — держусь».

**Кадр:** кручу каталог на стенде — плеер едет вместе со страницей, доходит до низа экрана и **прилипает**. Дальнейшая прокрутка — панель на месте.

**Спросить:** Чем это отличается от `fixed`?
**Ждём:** fixed прибит к окну сразу и всегда; sticky — в потоке, прилипает при достижении края.

**Инженерная минутка — почему sticky, а не fixed:**

> `fixed` — панель поверх всего, она **перекрывает** контент: последнюю карточку не дочитать, кнопка под плеером не нажимается. Плюс на телефонах fixed-панели любят «прыгать», когда появляется адресная строка. `sticky` живёт в потоке — страница знает про его место. Spotify, YouTube Music — все плееры мира сделаны так или похоже.

> Важная тонкость: sticky работает только **внутри своего родителя**. Если родитель короткий — прилипание «отпустит», когда родитель уедет вверх. Поэтому плеер — прямой ребёнок `body` или высокого контейнера.

## 4. Блок 2: Flex-панель — три зоны · 7 мин

**Сказать:**

> Панель плеера — классика из трёх зон: **слева** кнопки, **в центре** название трека, **справа** прогресс или громкость. Знакомый расклад?

```css
.player {
  display: flex;
  align-items: center;   /* всё по центру высоты */
  gap: 16px;             /* честный воздух между зонами */
  flex-wrap: wrap;       /* на узком экране зоны перенесутся */
}

.player .title {
  flex: 1;      /* название забирает ВСЁ свободное место */
  min-width: 0; /* и не рвёт строку длинным текстом */
}
```

> Новое свойство — `flex: 1`. До сих пор flex делил место **поровну** или по содержимому. `flex: 1` говорит зоне: «расти, забирай всё, что свободно». Кнопки остаются компактными, название растягивается, прогресс прижимается вправо.

**Аналогия:**

> Это как дележ парты: двое сели по краям (кнопки и громкость), а посередине — учебник, он занимает всё оставшееся место. `flex: 1` — «учебник».

**Спросить:** Что случится без `min-width: 0`, если название трека — «Симфония №40 соль минор, очень длинное»?
**Ждём:** предположения. Показать на стенде: длинное название **выталкивает** прогресс-бар за экран. `min-width: 0` — страховка от раздувания.

**Кадр:** добавляю `flex-wrap: wrap`, сужаю окно DevTools до 360px — зоны переносятся на вторую строку, ничего не лопается.

## 5. Блок 3: Прогресс-бар из двух div · 5 мин

**Сказать:**

> Полоска «сколько прошло» — это не магия и не JavaScript. Два прямоугольника друг в друге:

```html
<div class="progress">
  <div class="progress-fill"></div>
</div>
```

```css
.progress {
  flex: 2;               /* полоса — вторая «растущая» зона */
  height: 6px;
  background: #2A3350;   /* фон — «не прослушано» */
  border-radius: 3px;
}
.progress-fill {
  width: 40%;            /* залито — «прослушано» */
  height: 100%;
  background: var(--accent);
  border-radius: 3px;
}
```

> Внутри — коробка из Спринта 1: родитель задаёт размер, ребёнок заполняет долю. `width: 40%` — значит, трек «проигран» на две пятых. В Спринте 3 подключим JavaScript — и полоса поедет по-настоящему. Сегодня она честная, но застывшая: кадр из игры, а не сама игра.

**Спросить:** Что произойдёт, если у `.progress-fill` забыть `height: 100%`?
**Ждём:** полоска исчезнет — у div без текста нет своей высоты.

## 6. Блок 4: Запас снизу — почему плеер «съел» карточку · 4 мин

**Сказать:**

> Обещанный сюрприз. Смотрю на стенд: докрутил каталог до конца — а последняя карточка **наполовину под плеером**. Класс: «плеер её съел!»

> Причина: sticky-панель занимает место в потоке **там, где написана**, а прилипая, она визуально наезжает на низ контента. Лечится одной строкой — запасом:

```css
body {
  padding-bottom: 88px;  /* 88 ≈ высота плеера + воздух */
}
```

> Правило дня: **прибил панель — дай контенту запас**. Это как в рюкзаке: положил ноутбук — оставь место, чтобы молния его не передавила.

**Спросить:** Откуда взялось число 88?
**Ждём:** примерно высота плеера. Да — смотрим в DevTools, измеряем, округляем с запасом. Магических чисел нет, есть измеренные.

5. **Эксперимент «телефон»:** DevTools → 360px. Предсказываем, что будет без `flex-wrap` → включаем wrap → сравниваем.

**Реплики-якоря по ходу:**

**Checkpoint-вопрос перед переменой (порог 7/10):**

## FAQ — вопросы, которые могут задать

- **Почему не `fixed`, он же проще?** Fixed перекрывает контент и «прыгает» на телефонах при появлении адресной строки. Sticky честнее: элемент остаётся в потоке.
- **Можно ли сделать плеер сверху?** Да, `top: 0` вместо `bottom: 0` — прилипнет к верху. Так делают липкие шапки и меню.
- **Что такое `z-index`?** Порядок слоёв: кто выше, тот и перекрывает. Сегодня не нужен — sticky-плеер и так поверх контента своего потока. Вернёмся, если карточки начнут «наезжать» на панель.
- **Зачем `min-width: 0`, если есть `flex: 1`?** У flex-детей минимальная ширина по умолчанию — размер контента. Длинное название отказывается сжиматься и рвёт панель. `min-width: 0` разрешает сжаться.
- **Будет ли плеер играть?** В Спринте 3 (A15–A17) подключим JavaScript — кнопка оживёт, прогресс поедет. Сегодня учимся строить панель, а не мотор.

## Шпаргалка · термины одной фразой

| Термин | Одной фразой |
| --- | --- |
| `position: sticky` | плывёт с потоком, у края прилипает |
| `position: fixed` | прибит к окну, перекрывает контент |
| `bottom: 0` | точка прилипания — нижний край экрана |
| `flex: 1` | зона забирает всё свободное место |
| `min-width: 0` | страховка: длинный текст не рвёт панель |
| `flex-wrap: wrap` | не влезло — перенеси на следующую строку |
| запас снизу | `padding-bottom` ≈ высота панели: контент не перекрыт |
| HUD | панель управления, которая всегда на экране |
