## Результат урока

К концу урока ученик объясняет и показывает одну цепочку:

`браузер → HTTP GET → маршрут Flask → функция-обработчик → HTTP-ответ → рендеринг`

На практике:

1. `http://127.0.0.1:5000/` возвращает ответ обработчика `home`.
2. `http://127.0.0.1:5000/radio` возвращает ответ обработчика `radio`.
3. Ученик самостоятельно добавляет `/about`: имя и описание своей станции.
4. Изменение `return` видно в браузере после обновления страницы.

Pulse FM во Flask сегодня не переносим. Проверяем механизм запроса, а не миграцию готового сайта.

## Открытие · слайды 01–02 · 2 мин

**Сказать:**

> До этого занятия браузер открывал ваш Pulse FM как локальный файл: находил `index.html` на диске и отображал готовый HTML. В адресной строке при этом был путь к файлу, а запрос к программе не уходил.

> Сегодня меняем модель доставки страницы. Браузер отправит HTTP-запрос, Python-программа на Flask сформирует ответ, и браузер отобразит уже его. Наша задача — проследить этот путь без пропусков: кто инициирует запрос, как Flask находит нужную функцию и что именно возвращается браузеру.

**Спросить:** Какая модель описывает ваш Pulse FM сейчас: локальный файл или серверный ответ?  
**Ждём:** локальный файл. Браузер читает готовый HTML с диска, адрес `file://`.

## Блок 1 · Две модели доставки страницы · слайд 03 · 3 мин

**Сказать:**

> Слева на иллюстрации — готовая страница, закреплённая на стене. Справа — обслуживание по запросу. Для нас важна не картинка, а разница в механизме.

> В первой модели содержимое уже существует как файл. Браузер получает его с диска в неизменном виде. Во второй модели готового HTML-файла для конкретного ответа может не быть: программа создаёт содержимое, когда приходит запрос.

> Именно поэтому Discord, Spotify и другие сетевые приложения не сводятся к папке с HTML на компьютере пользователя. Их интерфейс работает в браузере, но данные и решения приходят от серверной программы.

**Спросить:** Если содержимое должно зависеть от запроса, какая модель нужна?  
**Ждём:** серверная. Программа формирует ответ в момент запроса.

## Блок 2 · Frontend и backend · слайд 04 · 3 мин

**Сказать:**

> Разделим систему на две части. Frontend — клиентская часть, которая выполняется в браузере. Она показывает интерфейс, применяет HTML и CSS и отображает полученный результат. Ваш Pulse FM сейчас — frontend без собственного backend.

> Backend — серверная часть. Сегодня это Python и Flask на том же компьютере. Backend принимает запрос, выбирает обработчик, выполняет код и формирует ответ.

> Граница между frontend и backend — HTTP. В одну сторону уходит запрос, в другую возвращается ответ. Когда мы говорим «Flask отдал страницу», технически это значит: Flask сформировал HTTP-ответ, а браузер выполнил рендеринг его содержимого.

**Спросить:** Кто отображает тег `<h1>` на экране: Flask или браузер?  
**Ждём:** браузер. Flask возвращает строку с разметкой, браузер её интерпретирует.

## Блок 3 · URL и HTTP · слайды 05–06 · 4 мин

**Сказать:**

> Разберём адрес: `http://127.0.0.1:5000/radio`. `http` — протокол. `127.0.0.1` — loopback-адрес, то есть этот же компьютер. `5000` — порт, на котором процесс Flask принимает соединения. `/radio` — путь; по нему Flask выбирает обработчик.

> Поэтому `127.0.0.1` на другом ноутбуке укажет уже на тот ноутбук, а не на ваш. Сегодня сервер доступен только локально, мы ничего не публикуем в интернет.

> Сам запрос в упрощённом виде выглядит так: `GET /radio HTTP/1.1`. Метод `GET` означает «получить ресурс». Ниже браузер указывает хост: `Host: 127.0.0.1:5000`.

> Ответ содержит статус и тело. Статус `200 OK` — запрос успешно обработан. В теле сегодня находится HTML. Если путь не зарегистрирован, Flask вернёт `404 Not Found`. Это не падение программы, а корректный ответ: такого ресурса нет.

**Спросить:** В адресе назовите протокол, хост, порт и путь.  
**Ждём:** `http`, `127.0.0.1`, `5000`, `/radio`.

## Блок 4 · Жизненный цикл запроса · слайд 07 · 3 мин

Пройди цепочку по слайду слева направо.

**Сказать:**

> Шаг первый: браузер формирует `GET /radio`. Шаг второй: запрос принимает dev-сервер на порту 5000. Шаг третий: Flask сопоставляет путь `/radio` с зарегистрированным маршрутом. Шаг четвёртый: вызывается функция-обработчик, и её `return` становится телом ответа. Шаг пятый: браузер получает ответ и рендерит HTML.

> Обратите внимание на ответственность каждого участника. Браузер не выбирает Python-функцию. Flask не рисует страницу на экране. Функция не печатает интерфейс напрямую — она возвращает данные для ответа.

**Спросить:** На каком шаге создаётся HTML для `/radio`?  
**Ждём:** на четвёртом, в функции-обработчике. На пятом браузер его отображает.

## Блок 5 · Маршрут и обработчик во Flask · слайд 08 · 5 мин

**Файл:** `demo/app.py`  
Перед I do маршрут `/radio` закомментирован. На экране сначала только `/`.

```python
from flask import Flask

app = Flask(__name__)


@app.route("/")
def home():
    return "<h1>PulseLab жив</h1><p>Это ответ сервера, не файл с рабочего стола.</p>"
```

**Сказать:**

> `from flask import Flask` импортирует класс фреймворка. `app = Flask(__name__)` создаёт объект приложения; `__name__` помогает Flask определить текущий модуль и связанную с ним папку проекта.

> Конструкция `@app.route("/")` регистрирует правило маршрута: путь `/` связан с функцией ниже. Как создавать собственные декораторы, сегодня не разбираем. Нам важна операция: зарегистрировать соответствие «URL → обработчик».

> Функция `home` — обработчик корневого пути. Её `return` не выводит текст в терминал и не рисует страницу. Возвращаемая строка становится телом HTTP-ответа со статусом `200`.

> Запуск: `flask --app app run --debug`. Параметр `--app app` указывает модуль приложения. Режим `--debug` перезапускает сервер после изменения кода, но уже открытую вкладку всё равно нужно обновить: новый ответ появится только после нового запроса.

**Спросить:** Что связывает путь `/` именно с функцией `home`?  
**Ждём:** регистрация маршрута `@app.route("/")` над функцией.

**Кадр:** терминал с `Running on http://127.0.0.1:5000`, затем браузер на `/`. Измени одно слово в `return`, сохрани файл и обнови вкладку. В исходном коде страницы видна та же строка, которую вернула функция.

## Шпаргалка терминов

- **Клиент** — программа, которая инициирует запрос. В уроке это браузер.
- **Сервер** — программа, которая принимает запросы и возвращает ответы. В уроке Flask-приложение работает на локальном dev-сервере.
- **Frontend** — клиентская часть в браузере: интерфейс, HTML/CSS, рендеринг.
- **Backend** — серверная часть: приём запроса, логика, формирование ответа.
- **HTTP-запрос** — метод, путь и служебная информация. Сегодня: `GET /radio`.
- **Маршрут** — зарегистрированное правило «путь → обработчик».
- **Функция-обработчик** — Python-функция, возвращающая результат для ответа.
- **Тело ответа** — содержимое HTTP-ответа. Сегодня это строка HTML.
- **Loopback** — адрес `127.0.0.1`, обращение компьютера к самому себе.
- **Порт** — номер, по которому процесс принимает соединения. У dev-сервера Flask здесь `5000`.
