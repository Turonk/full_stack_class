# Урок 7 · Checks

Вопросы повторяют слайды 02, 05–09, 12 и 15. Термины не заменять бытовыми аналогиями: ожидаем «клиент», «loopback», «маршрут», «обработчик», «тело ответа», «рендеринг».

## Retrieval · слайд 02

**Q:** По какой модели сейчас работает Pulse FM: локальный файл или серверный ответ? Как это видно по адресной строке?  
**Ожидание:** локальный файл. Адрес `file://`, браузер читает готовый `index.html` с диска.  
**Mist:** «раз страница открылась, значит, есть сервер» → вернуть к слайду 02 и сравнить модели A и B. Сервер нужен только там, где программа получает запрос и формирует ответ.

## URL и HTTP · слайды 05–06

**Q:** В `http://127.0.0.1:5000/radio` назовите протокол, хост, порт и путь.  
**Ожидание:** `http`; `127.0.0.1` — loopback, этот же компьютер; `5000` — порт процесса Flask; `/radio` — путь.  
**Mist:** «5000 — папка» / «127.0.0.1 — сайт» → разобрать адрес по частям на слайде 05.

**Q:** Что означает `GET`, что содержит ответ при успешной обработке и когда возникает `404`?  
**Ожидание:** `GET` — получить ресурс. Успешный ответ: статус `200` и тело, сегодня HTML. `404` — для пути нет зарегистрированного маршрута.  
**Mist:** «404 — сервер сломался» → показать, что процесс продолжает отвечать на `/`. Ошибка относится к конкретному пути, а не ко всему приложению.

## Тело ответа · слайд 09

**Q:** Что покажет браузер при `return "PulseLab"` и при `return "<h1>PulseLab</h1>"`?  
**Ожидание:** сначала обычный текст, затем заголовок. В обоих случаях функция возвращает строку; HTML интерпретирует браузер.  
**Mist:** «Flask нарисовал заголовок» → открыть исходный код ответа и показать строку из `return`. Рендеринг выполняет frontend в браузере.

## Контрольная точка · слайды 11–12

Ученик устно прослеживает запрос `GET /radio` без пропусков:

1. Клиент — браузер.
2. Запрос уходит на `127.0.0.1:5000`, путь `/radio`.
3. Flask находит зарегистрированный маршрут.
4. Вызывается обработчик `radio()`.
5. Его `return` становится телом HTTP-ответа.
6. Браузер рендерит полученный HTML.

**Критерий прохождения:** не перепутаны маршрут и обработчик; не сказано, что Python рисует страницу.  
**Mist majority:** вернуться к слайду 07 и выполнить ту же трассировку на стенде. К лабораторной работе не переходить, пока большинство не повторит цепочку.

## Взаимопроверка

**Действие:** сосед открывает `http://127.0.0.1:5000/` и `http://127.0.0.1:5000/about`.  
**Ожидание:** для каждого адреса названы путь, обработчик и содержимое тела ответа. На `/about` — имя ученика и описание его станции.  
**Mist:** открыта страница `file://` → вернуть к адресной строке. Для результата урока нужен ответ локального сервера, а не файл Pulse FM.

## Итог · слайд 15

**Q1:** Чем открытие `file://` отличается от запроса `http://`?  
**Ожидание:** в первом случае браузер читает готовый файл; во втором отправляет запрос, и программа формирует ответ.

**Q2:** Как Flask находит обработчик по пути `/about`?  
**Ожидание:** по маршруту, зарегистрированному через `@app.route("/about")`.

**Q3:** Что произойдёт, если удалить регистрацию маршрута, но оставить функцию?  
**Ожидание:** функция останется в коде, но Flask не будет вызывать её для этого пути; запрос получит `404`.

**Mist:** «приложение перестанет запускаться» → продемонстрировать на стенде: `/` отвечает, незарегистрированный путь возвращает `404`.
