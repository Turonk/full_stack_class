## Цель урока

Ученик различает две модели доставки страницы: браузер читает готовый локальный файл по `file://` либо отправляет HTTP-запрос и получает ответ, сформированный программой. К концу занятия он запускает Flask локально, объясняет жизненный цикл запроса и самостоятельно регистрирует маршрут `/about` с функцией-обработчиком.

Ключевая цепочка для всех материалов урока:

`браузер → HTTP GET → маршрут Flask → функция-обработчик → HTTP-ответ → рендеринг`

## Границы темы

В урок входят только:

- клиент и сервер, frontend и backend;
- URL: протокол, loopback-адрес, порт, путь;
- HTTP-запрос `GET`, статус `200`, статус `404`, тело ответа;
- регистрация маршрута через `@app.route`;
- функция-обработчик и `return` как источник тела ответа.

Не входят: Jinja и наследование шаблонов, `url_for`, каталог `static`, POST и формы, сессии, JSON API, базы данных, cookies, детальный разбор всех HTTP-заголовков, WSGI и production-развёртывание. На слайде 06 показаны только стартовая строка запроса, `Host`, статус, `Content-Type` и тело — этого достаточно для модели урока.

Как писать собственные декораторы, не разбираем. Для ученика декоратор здесь — синтаксис регистрации правила маршрута в приложении Flask.

## Техническая модель для преподавателя

При открытии `http://127.0.0.1:5000/radio` браузер создаёт HTTP-запрос `GET /radio`. Соединение принимает встроенный dev-сервер Flask на loopback-адресе и порту 5000. Flask сопоставляет путь с зарегистрированными правилами URL и вызывает связанную функцию-обработчик. Строка, возвращённая функцией, преобразуется в HTTP-ответ: при обычном выполнении статус `200`, тип содержимого `text/html`, возвращённая строка — тело ответа. Браузер парсит HTML и выполняет рендеринг.

Если правило для пути не зарегистрировано, обработчик не вызывается и Flask возвращает `404 Not Found`. Наличие функции в `app.py` само по себе маршрут не создаёт.

Термин «сервер» в уроке не привязываем к отдельному компьютеру. Сервер — программа или процесс, принимающий запросы. На занятии клиент и сервер работают на одном ноутбуке и разделены по ролям, а не по устройствам.

## Подготовка стенда накануне

Из папки `demo` в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m flask --app app run --debug
```

Папку `.venv` ученикам не раздаём и в git не добавляем. До урока проверить:

- `/` возвращает «PulseLab жив»;
- `/radio` возвращает Night Circuit;
- незарегистрированный путь, например `/tracks`, возвращает `404`;
- изменение строки в `return` после обновления страницы видно в браузере.

Перед I do закомментировать обработчик `radio` вместе с `@app.route`. В We do класс формулирует путь, имя функции и тело ответа, учитель вводит код. Файл в репозитории остаётся рабочим.

### Запуск без активации окружения

Активация через `Activate.ps1` не обязательна. Интерпретатор из `.venv` напрямую гарантирует, что Flask импортируется из нужного окружения, и не зависит от ExecutionPolicy:

```powershell
.\.venv\Scripts\python.exe -m flask --app app run --debug
```

### Если окружение на ноутбуках не готово

Отвести на установку до 15 минут. Лабораторную часть сократить: ученик меняет тело ответа в готовом обработчике `home`, а самостоятельную регистрацию `/about` переносит в домашнюю работу. Жизненный цикл запроса и контрольную точку не сокращать.

## FAQ

- **Flask — это сервер?** Строго: Flask — веб-фреймворк и объект приложения. HTTP-соединения в режиме разработки принимает встроенный dev-сервер. Ученикам достаточно: «Flask-приложение работает как локальный сервер», преподаватель должен понимать различие.
- **Flask заменяет Python?** Нет. Это библиотека и фреймворк на Python; функции, строки и `return` работают как обычно.
- **Почему страница существует без нового `index.html`?** HTML находится в теле HTTP-ответа. Его сформировал обработчик в момент запроса.
- **Почему исходный код страницы совпадает со строкой из `return`?** Для строкового ответа Flask помещает эту строку в тело без шаблонизатора.
- **Почему `<h1>` отображается заголовком?** Ответ имеет тип HTML, браузер парсит разметку и выполняет рендеринг. Flask заголовок не рисует.
- **Почему сосед не открывает мой `127.0.0.1`?** Loopback всегда указывает на устройство, с которого выполняется запрос. На ноутбуке соседа это его собственный компьютер.
- **Что делает `--debug`?** Включает отладочный режим и перезапуск при изменении кода. Уже открытая вкладка не обновляется сама: браузер должен отправить новый запрос.
- **Что будет, если оставить функцию, но удалить `@app.route`?** Приложение продолжит работу, но путь не будет связан с функцией. Запрос к нему вернёт `404`.
- **Можно ли вернуть весь Pulse FM одной строкой?** Технически обработчик может вернуть большой HTML, но это не решает задачи урока и смешивает механизм запроса с миграцией сайта. Шаблоны и статические файлы — A27–A28.

## Диагностика по слоям

Порядок совпадает со слайдом 14. Сначала проверить процесс и адрес, только потом код маршрута.

| Слой | Симптом | Проверка и действие |
| --- | --- | --- |
| Среда | `ModuleNotFoundError: flask` | Flask установлен не в то окружение. Запускать через `.\.venv\Scripts\python.exe -m flask` из папки проекта |
| Среда | `pip` выполнился, импорт не работает | Сверить интерпретатор установки и запуска. Норма урока — один `.venv` на проект |
| Процесс | Соединение отклонено | Сервер не запущен или терминал закрыт. Перезапустить команду и не закрывать окно |
| Процесс | Приложение запускалось двойным щелчком по `app.py` | Остановить такой запуск. Нужна команда Flask в терминале |
| Сеть | `Address already in use` | Порт 5000 занят другим процессом. Найти и остановить предыдущий сервер |
| Сеть | Открылся знакомый Pulse FM вместо ответа Flask | В адресной строке `file://`. Открыть `http://127.0.0.1:5000/...` |
| Приложение | Код изменён, браузер показывает старый текст | Файл не сохранён, сервер не перезапустился или вкладка не обновлена |
| Приложение | `/about` возвращает `404` | Нет регистрации маршрута либо путь в `@app.route` не совпадает с URL. Сверить `/about` символ в символ |

## Отстаёт / опережает

- **Отстаёт:** сохранить работающий `/`, затем добавить `/about` по образцу со слайда 08. Тело ответа — имя и одно короткое предложение.
- **Опережает:** добавить маршрут `/tracks` с названием одного трека и устно проследить для него весь жизненный цикл запроса. В Jinja, CSS и перенос сайта не уходить.
