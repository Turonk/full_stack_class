# A11 Checks · Контрольные точки

## Retrieval
**Q:** Зачем нужен `base.html`? Что принимает функция `@app.route("/item/<item_id>")`?  
**Ожидание:** чтобы не дублировать каркас сайта; принимает строковый идентификатор карточки из URL.

## Checkpoint mid (обязательный)
**Q1:** Почему у каждого инпута в форме должен быть атрибут `name`?  
**Ожидание:** по значению `name` сервер извлекает значение из словаря `request.form`. Без него поле теряется.  
**Q2:** Зачем после успешной обработки POST-запроса делать `redirect`, а не сразу возвращать шаблон?  
**Ожидание:** чтобы браузер перешел в режим чистого GET-запроса, и обновление страницы по F5 не отправляло данные формы повторно (паттерн Post/Redirect/Get).

## Контроль практики (You do)
**Критерий:**
1. Страница `/suggest` открывает форму с полями для заголовка, подзаголовка, описания и выбора картинки.
2. При попытке отправить пустой заголовок форма не добавляет карточку, а выводит flash-сообщение об ошибке.
3. При корректном заполнении сервер перенаправляет в `/catalog`, где новая карточка сразу отображается в общем ряду.
4. Обновление страницы каталога (F5) не вызывает диалоговое окно подтверждения повторной отправки.

## Exit ticket
1. Термин дня: метод POST, `request.form`, Post/Redirect/Get, `flash`.
2. Что произойдет с добавленными через форму карточками, если остановить сервер в терминале? (Ожидание: они пропадут, так как хранятся в оперативной памяти процесса).
