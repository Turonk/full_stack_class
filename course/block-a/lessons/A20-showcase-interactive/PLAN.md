# Урок 20 · Showcase Interactive Hub

Паспорт защиты. Проект: [Interactive Hub](../../projects/04-interactive-hub/PROJECT.md). После [fetch API](../A19-fetch-api/PLAN.md).

- Группа ≤10 · 120 минут
- Это не новый концепт. Это публичная проверка цепочки «сервер → JS → DOM → localStorage → API».

## Результат

Каждый ученик запустил сервер и за ≤6 минут показал: сервер, JS-игру, каталог через `fetch`, `localStorage`. Сосед по рубрике отмечает зачёт или дыру.

## Тайминг

| Мин | Фаза | Действие |
| --- | --- | --- |
| 0–10 | Правила | На слайде порядок из 6 шагов и рубрика. Серверы поднимаются до вызова |
| 10–70 | Питчи | ≤6 мин × ученик |
| 70–90 | Ревью | Пара проходит чек-лист по экрану соседа |
| 90–110 | Правка | Только провал зачёта |
| 110–120 | Закрытие | Мост: завтра новый проект MerchShop на том же сервере |

## Порядок одного питча

1. Адресная строка `/` — ответ сервера.
2. Показать `ITEMS` в `app.py` и ту же карточку в `/api/items` (JSON).
3. Открыть `/catalog` — каталог через `fetch`, не `{% for %}`.
4. Перейти на `/game` — сыграть раунд, показать счёт.
5. Обновить страницу — `localStorage` показал рекорд.
6. Открыть `/fake` — свой 404.

Кто не успел `fetch`, защищает шаги 1–3, 5–6. Шаг 4 закрывает дома скрином.

## Что говорит ведущий, если питч буксует

- Сайт открыт с диска — остановить, запустить `flask run`.
- Карточки зашиты в HTML — попросить показать `fetch`. Нет `fetch`: зачёт по API не ставить.
- Игра не запускается — проверить `game.js`, `defer`.

## Не делать на этом уроке

Не вводить корзину, session, MerchShop. Не переносить в новый дизайн. Не сравнивать красоту.
