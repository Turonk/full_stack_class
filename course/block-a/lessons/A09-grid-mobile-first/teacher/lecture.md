## 2. Завязка + предсказание · 10 мин

### Сцена

**Сказать:**

> Смотрите на стенд: карточки треков идут **столбиком**, одна под другой. На телефоне — нормально, там узко. А теперь разверну окно на весь проектор… Три столбика текста посреди огромного пустого экрана. Класс прав: «карточек мало, а экран большой — выглядит бедно».

> Настоящий каталог умеет **перестраиваться**: телефон — одна колонка, планшет — две, десктоп — три. Один и тот же HTML, никакого дублирования — меняется только CSS.

### Предсказание (главное, до кода)

**Спросить:** У нас уже есть flex — мы собирали им шапку и плеер. Соберёт ли flex сетку 3×2, шесть карточек ровными рядами? Голосуем: да — правая рука, нет — левая.
**Ждём:** спор.

**Сказать:**

> Flex умеет многое: `flex-wrap` перенесёт карточки на следующую строку. Но ряды получатся **неровными**: последняя карточка в ряду шире или уже соседних, выравнивание по колонкам «поедет». Flex — это про **одну линию**: ряд или колонку. А сетка — это **две оси сразу**: и ряды, и колонки. Для двух осей есть свой инструмент — **Grid**.

> Аналогия: flex — это очередь в столовой, все встают друг за другом. Grid — это шахматная доска: у каждой клетки есть и строка, и столбец.

## 3. Показываю · Блок 1: Grid — две оси сразу · 7 мин

> Стенд открыт, Live Server включён. Каждая правка — сначала предсказание класса, потом Enter.

**Сказать:**

> Минимальный Grid — три строки:

```css
.tracks {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}
```

> Разбираем по косточкам:

- `display: grid` — как и flex, включается на **родителе**. Дети автоматически становятся клетками сетки.
- `grid-template-columns` — «сколько колонок и какой ширины». `repeat(3, 1fr)` — «три колонки, каждая по одной доле». `1fr` — **fraction**, доля свободного места. Три доли делят ширину поровну.
- `gap: 16px` — воздух **и между колонками, и между рядами**. Одно свойство вместо margin на каждой карточке.

**Кадр:** включаю grid на стенде — шесть карточек встают 3×2, ровно, с одинаковым воздухом.

**Спросить:** Что будет, если написать `repeat(2, 1fr)`, а карточек шесть?
**Ждём:** два столбца, три ряда. Проверить на стенде.

**Спросить:** А если `1fr 2fr`?
**Ждём:** предположения. Правильно: левая колонка вдвое **уже** правой — доли делятся 1:2. Проверить.

## 4. Блок 2: Mobile-first — телефон это база · 7 мин

**Сказать:**

> Три колонки на проекторе — красиво. А теперь главный вопрос: что увидит человек с телефоном 360px? Три колонки по 100 пикселей? Текст встанет вертикально, как в узком столбце газеты. Кошмар.

> Есть два подхода. **Desktop-first:** сначала делаем красиво на большом экране, потом медиазапросами «ухудшаем» для телефона. **Mobile-first:** база — телефон, а медиазапросы **добавляют** улучшения для широких экранов. Мы живём во втором.

```css
/* база — телефон: одна колонка */
.tracks {
  display: grid;
  grid-template-columns: 1fr;
  gap: 16px;
}

/* планшет и шире — две колонки, потом три */
@media (min-width: 720px) {
  .tracks { grid-template-columns: repeat(2, 1fr); }
}

@media (min-width: 1200px) {
  .tracks { grid-template-columns: repeat(3, 1fr); }
}
```

> Читаем вслух: `@media (min-width: 720px)` — «когда экран **шире** 720 пикселей, примени». База написана **до** медиазапросов — и это принципиально: помнишь каскад из A07? При равной силе побеждает правило **ниже**. Медиазапросы стоят внизу — они перебивают базу на широких экранах. Если перепутать порядок, на телефоне будет «пусто» или каша.

**Спросить:** Почему `min-width`, а не `max-width`?
**Ждём:** mobile-first — «при расширении добавляем»; `max-width` — это desktop-first, «при сужении ломаем».

**Инженерная минутка — почему индустрия выбрала mobile-first:**

> Больше половины трафика интернета — телефоны. Если сайт сначала сделали для десктопа, на телефоне его приходится «утрамбовывать» — а это костыли и баги. Если база — телефон, десктопная версия получается **надстройкой**: добавить колонки проще, чем убрать лишнее. Spotify, YouTube, Discord — все адаптивные и все mobile-first.

> **Брейкпоинты** — 720px и 1200px — не магические числа из учебника, а договорённость: «здесь колонке становится тесно». В разных проектах числа свои. Смысл один: медиазапрос ставят там, где дизайн **начинает ломаться**, а не «где в статье написали».

## 5. Блок 3: Трюк — `auto-fit` и `minmax` · 5 мин

**Сказать:**

> А теперь фокус, от которого взрослые разработчики улыбаются. Всё то же самое — **без единого медиазапроса**:

```css
.tracks {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 16px;
}
```

> Читаем по слогам: «строй столько колонок шириной **не меньше 220px**, сколько влезает (`auto-fit`); каждая колонка — от 220px до доли свободного места (`1fr`)». Экран узкий — влезает одна колонка. Шире — две. Ещё шире — три. Сетка перестраивается **сама**, как резиновая.

**Кадр:** меняю на стенде явные медиазапросы на auto-fit — тяну ползунок ширины DevTools, колонки перескакивают сами.

**Сказать:**

> Когда брать что? **Явные брейкпоинты** — когда макет меняется скачком («на планшете появится боковая колонка»). **auto-fit** — когда карточки одинаковые и нужно просто «сколько влезет». Сегодня в Your MusicHub — явные брейкпоинты (так совпадает с эталоном спринта), auto-fit — в челлендж.

## 6. Блок 4: Точечно `absolute` — бейдж на обложке · 4 мин

**Сказать:**

> Одна маленькая деталь, и мы закрываем тему position на весь спринт. Хотим бейдж «NEW» в углу обложки трека — поверх картинки, в левом верхнем углу.

```html
<div class="cover">
  <img src="…" alt="Обложка трека">
  <span class="badge">NEW</span>
</div>
```

```css
.cover { position: relative; }        /* «я — якорь» */
.badge {
  position: absolute;                 /* «привяжи меня к якорю» */
  top: 8px;
  left: 8px;
  background: var(--accent);
  padding: 2px 8px;
  border-radius: 999px;
}
```

> Правило пары: **absolute ищет ближайшего родителя с relative** и привязывается к нему. Без relative у родителя бейдж уедет привязываться к странице целиком — и встанет не там. Аналогия: absolute — это магнит, relative — железная полка. Нет полки — магнит прилипнет к холодильнику в другой комнате.

**Спросить:** Что будет, если у `.cover` убрать `position: relative`?
**Ждём:** предположения → показать на стенде: бейдж уехал в угол страницы.

> Запомните эту пару — она ещё встретится в Спринте 4 (значок корзины). Больше моделей position в этом блоке не будет: sticky был в A08, relative+absolute — здесь. Всё.

## 7. Делаем вместе · 20 мин

> Класс диктует — я печатаю на стенде. Порядок строго такой, каждый шаг сначала предсказываем.

1. **Каталог:** в `main` — `section.tracks` с **шестью** карточками (дублируем три из A07, названия меняем — класс диктует свои треки).
2. **База:** `display: grid; grid-template-columns: 1fr; gap: 16px;`. Открываем DevTools → 360px: одна колонка, скролла вбок нет.

4. **1200px:** предсказываем → три колонки. Тянем ползунок ширины — класс хором называет, где произойдёт перелом.
5. **Бейдж:** на одну карточку вешаем «NEW» через relative/absolute. Убираем relative — ловим баг вслух, возвращаем.

**Реплики-якоря по ходу:**

- «Grid — две оси. Flex — одна линия.»
- «База — телефон. Медиазапросы ДОБАВЛЯЮТ, а не ломают.»
- «Медиазапросы — внизу файла. Каскад!»
- «Горизонтальный скролл — всегда баг.»

**Checkpoint-вопрос перед переменой (порог 7/10):**

1. Чем grid отличается от flex? — **Grid — две оси (ряды и колонки), flex — одна линия.**
2. Почему медиазапросы пишут **после** базовых стилей? — **Каскад: при равной силе побеждает нижнее правило; mobile-first добавляет улучшения поверх базы.**

## 8. Делаешь сам · 35 мин

> Ученик собирает каталог в своём MusicHub (файлы после A07–A08). Критерий «готово» — на слайде и здесь.

### Задача (шаги)

1. Проверь, что в `head` есть `<meta name="viewport" content="width=device-width, initial-scale=1">`. **Без него телефон «притворится» десктопом** и вся работа насмарку — это не шутка, это самый частый баг дня.
2. Оберни карточки треков в `section.tracks` (минимум **шесть** карточек — названия свои).
3. База: `.tracks { display: grid; grid-template-columns: 1fr; gap: 16px; }`.
4. Медиазапрос `min-width: 720px` → 2 колонки; `min-width: 1200px` → 3 колонки. Медиазапросы — **внизу файла**.
5. Бейдж «NEW» (или «ХИТ») на обложке одной карточки: relative на `.cover`, absolute на `.badge`.
6. Проверка в DevTools (Ctrl+Shift+M): 360px — одна колонка, 720px — две, 1200px — три. Горизонтального скролла нет нигде.

### Критерий «готово»

- [ ] viewport meta на месте
- [ ] каталог перестраивается 1 → 2 → 3 колонки
- [ ] медиазапросы после базовых стилей, `min-width`
- [ ] на 360px нет горизонтального скролла
- [ ] бейдж сидит в углу обложки, не уехал
- [ ] картинки в карточках не шире колонки (`img { max-width: 100%; }`)

### Минимум для отстающих

Шаги 1–4: viewport + база одна колонка + один медиазапрос 720px. Бейдж и 1200px — в домашку.

### Челлендж для быстрых

- Заменить явные брейкпоинты на `repeat(auto-fit, minmax(220px, 1fr))` — и увидеть, что медиазапросы больше не нужны.

- «Хит недели» отдельной секцией: на десктопе — картинка слева, текст справа (`grid-template-columns: 1fr 1.2fr` внутри `@media`), на телефоне — колонкой (это как раз домашка — сдать досрочно).

## FAQ — вопросы, которые могут задать

- **Когда flex, когда grid?** Одна линия (шапка, плеер, кнопки в ряд) — flex. Две оси (каталог, макет страницы) — grid. Они друзья, не соперники: внутри grid-карточки спокойно живёт flex.
- **Что такое `fr`?** Fraction — доля свободного места. `1fr 2fr` — делёж в пропорции 1:2.
- **Почему у меня `auto-fit` схлопывает колонки?** Без `minmax` браузеру не от чего считать. `minmax(220px, 1fr)` — «не уже 220px, а дальше — по обстоятельствам».
- **Брейкпоинты 720/1200 — обязательные?** Нет. Это наши договорённости на курс. Ставь брейкпоинт там, где твой дизайн начинает ломаться.
- **Нужен ли `position: relative` без absolute?** Редко. Основная роль relative — быть якорем для absolute-детей (и слегка сдвигать элемент, что мы не используем).
- **Что такое `grid-auto-rows`?** Высота строк по умолчанию. Сегодня не нужна — строки растут по контенту.

## Шпаргалка · термины одной фразой

| Термин | Одной фразой |
| --- | --- |
| `display: grid` | родитель раскладывает детей по двум осям |
| `grid-template-columns` | сколько колонок и какой ширины |
| `1fr` | одна доля свободного места |
| `repeat(3, 1fr)` | три равные колонки |
| `gap` | воздух между колонками и рядами сразу |
| mobile-first | база — телефон, медиазапросы добавляют |
| `@media (min-width: 720px)` | «когда экран шире 720 — примени» |
| брейкпоинт | ширина, где дизайн начинает ломаться |
| `auto-fit + minmax` | резиновая сетка без медиазапросов |
| `relative + absolute` | полка и магнит: бейдж в углу обложки |
| viewport meta | «телефон, не притворяйся десктопом» |
