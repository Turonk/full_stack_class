# A05 · Лекция вслух · Витрина треков и отклик

Читай почти дословно. Стенд — PulseDeck (`demo/`). Сумма блоков ядра: ~15 минут. Шаги набора — в блоках ниже: файл, место, код.

---

## Результат урока

К концу урока ученик собирает витрину из трёх разных треков и проверяет три вещи:

1. карточка поднимается от мыши;
2. при Tab поднимается вся карточка, потому что фокус попал на ссылку внутри;
3. на ширине 360px страница не уезжает вбок.

Переход занимает около 0,2 с и записан только для `transform` и `box-shadow`.

**Ждём:** подняться / тень / заметный отклик.

## Блок 1 · Полка и перенос · 4 мин

**Подготовка на глазах класса.** Открыт `demo/styles.css`. У `.shelf` временно убери `flex-wrap` и `gap`. У `.tile` временно убери `transition` и правило `.tile:hover, .tile:focus-within`. Файл в репозитории остаётся эталоном — ты возвращаешь куски по одному.

**Файл:** `demo/styles.css`  
**Место:** правило `.shelf` (после `display: flex`)

```css
.shelf {
  display: flex;
  flex-wrap: wrap;
  gap: 16px;
}
```

**Сказать:**

> Три карточки в ряд красивы на широком экране. На телефоне 360px они не обязаны умещаться в одну строку. Если в ряд не влезли — страница уедет вбок. Это ломает просмотр.

> `flex-wrap: wrap` — не влезло, перенеси на следующую строку. `gap` — расстояние между карточками. У `.tile` уже стоит `flex: 1 1 180px`: карточка может сжиматься и расти, но не меньше примерно 180px.

**Спросить:** Что хуже на демо — карточка перенеслась на новую строку или весь экран уехал вбок?  
**Ждём:** скролл вбок хуже; перенос строки — норма.

**Кадр:** DevTools → ширина 360px. Карточки перенеслись, страница не едет вбок.

## Блок 2 · Мышь и клавиатура · 5 мин

**Файл:** `demo/styles.css`  
**Место:** сначала свойство внутри `.tile`, затем отдельное правило ниже

```css
.tile {
  /* …остальное уже есть… */
  transition: transform 0.2s ease, box-shadow 0.2s ease;
}

.tile:hover,
.tile:focus-within {
  transform: translateY(-4px);
  box-shadow: 0 0 0 1px #2ee6a6, 0 16px 32px rgba(46, 230, 166, 0.2);
}
```

**Сказать:**

> Карточка — это `article`. С клавиатуры Tab на неё сам не встанет. Фокус получает ссылка Play внутри. Поэтому подъём карточки пишем на `:hover` и на `:focus-within`: «фокус где-то внутри этого элемента».

> Кольцо вокруг ссылки рисует браузер через `:focus-visible` — когда фокус пришёл с клавиатуры, а не после клика мышью. Схема такая: мышь → `:hover` на карточке; Tab → фокус на ссылке + `:focus-within` поднимает карточку.

**Спросить:** Почему одного `:hover` мало?  
**Ждём:** кто ходит Tab’ом / без мыши / не видно, где фокус.

**Кадр:** навели — карточка поднялась. Tab по Play — карточка поднялась, у ссылки видно кольцо.

## Блок 3 · transition: только нужные свойства · 4 мин

**Сказать:**

> Смотрим два варианта. Первый кажется короче:

```css
/* временно — для сравнения */
.tile { transition: all 0.2s; }

/* оставляем так */
.tile { transition: transform 0.2s ease, box-shadow 0.2s ease; }
```

**Файл:** `demo/styles.css` · **Место:** свойство `transition` у `.tile`  
Сначала поставь `all`, наведи курсор. Потом верни список из двух свойств.

> `transition: all` — браузер готов анимировать любое меняющееся свойство, в том числе тяжёлые вроде `width` или `margin`. Страница может дёргаться, а вы не поймёте почему. Перечисляйте только то, что реально меняется.

> `transform` и `box-shadow` браузеру анимировать дёшево. 0,15–0,25 с — комфортный отклик: мгновенно выглядит дёргано, полсекунды — слишком медленно. `ease` — плавный разгон и торможение.

**Спросить:** Какие два свойства нам нужны, чтобы карточка «подпрыгнула»?  
**Ждём:** transform и box-shadow.

**Кадр:** `all` → наведение; точечный список → то же наведение. На глаз почти одинаково; привычка писать список спасает на больших страницах.

## Факт из мира IT · 3–4 мин · ~50-я минута занятия

Проектор: [caniuse.com/css-focus-visible](https://caniuse.com/css-focus-visible). Логин не нужен.

**Сказать:**

> `:focus-visible` появился в Chrome в 2020 году. В Safari — только в версии 15.4, в марте 2022. Пока поддержки не было, на сайтах часто писали `outline: none`, чтобы рамка не вспыхивала после клика мышью. Вместе с ней пропадал и фокус с клавиатуры.

> Этот псевдокласс как раз отделяет два случая: клик мышью и Tab. В стандарте доступности WCAG есть пункт 2.4.7 Focus Visible: человек должен видеть, где он находится на странице.

**Кадр:** сразу после факта — Tab по ссылкам Play на стенде. Кольцо видно, карточка поднимается.

## Шпаргалка

| Термин | Одной фразой |
| --- | --- |
| `:hover` | курсор над элементом |
| `:focus-within` | фокус внутри элемента — поднимаем всю карточку |
| `:focus-visible` | кольцо у ссылки, когда фокус с клавиатуры |
| `transition` | плавная смена свойств ~0,2 с |
| `transition: all` | лучше перечислить свойства явно |
| `flex-wrap: wrap` | не влезло — перенос на новую строку |
| 360px | типичная ширина телефона для проверки |

## Чек-понимания

1. Почему одного `:hover` мало? Кто теряет без отклика с клавиатуры?
2. Чем `:focus-within` на карточке отличается от `:focus-visible` на ссылке?
3. Сколько примерно секунд занимает комфортный transition? Какие два свойства мы анимируем?
4. Почему `transition: all` — плохая привычка?
5. Что хуже на 360px: карточка перенеслась на новую строку или страница уехала вбок?
