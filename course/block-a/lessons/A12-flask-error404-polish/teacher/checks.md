# A12 Checks · Контрольные точки

## Retrieval
**Q:** Почему после успешного POST нужно делать `redirect`?  
**Ожидание:** чтобы защитить от повторной отправки данных при обновлении страницы по F5 (паттерн Post/Redirect/Get).

## Checkpoint mid (обязательный)
**Q1:** Что произойдет, если в `@app.errorhandler(404)` написать `return render_template("404.html")` без `, 404`?  
**Ожидание:** браузер покажет шаблон ошибки, но вернет код статуса `200 OK`, что является ошибкой протокола.  
**Q2:** Что делает функция `abort(404)`?  
**Ожидание:** прерывает текущую функцию и передает управление в обработчик ошибки 404.

## Контроль практики (You do)
**Чек-лист проекта к защите:**
- [ ] Сервер стартует без ошибок по `127.0.0.1:5000`
- [ ] Главная и каталог рендерят карточки из списка `ITEMS`
- [ ] Клик по карточке открывает её по ссылке `/item/<id>`
- [ ] Форма `/suggest` добавляет новую карточку в каталог
- [ ] Несуществующий адрес (например `/fake-path`) открывает фирменный `404.html`
- [ ] Несуществующий `id` (например `/item/fake-id`) также открывает фирменный `404.html`
- [ ] Статус ответа на странице ошибки строго равен 404 (проверяется в DevTools Network)

## Exit ticket
1. Термин дня: `@app.errorhandler(404)`, `abort(404)`, кортеж статуса.
2. Готовность к питчу: все 5 пунктов чек-листа отмечены как пройденные.
