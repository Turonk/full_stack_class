## 2. Завязка + предсказание · 10 мин

### Сцена

**Сказать:**

> Смотрите на стенд: бейдж «В эфире» у хита недели. Он стоит, **как приклеенный**. А у настоящих радио что происходит с индикатором эфира? Он **пульсирует** — как сердцебиение станции: «мы живы, мы в эфире, прямо сейчас играет музыка».

> Музыкальный сайт без движения — это склад. С движением — сцена.

**Спросить:** А что будет, если анимировать **всё подряд**? Бейдж мигает, карточки прыгают, фон переливается, кнопки вращаются?
**Ждём:** «рябит», «глаза устают», «невозможно читать», «бесит».

**Сказать:**

> Верно. Это называется «новогодняя ёлка»: столько огней, что не видишь подарков. Отсюда **правило курса: одна анимация на экран**. Движение — это акцент. Акцент бывает один, иначе это уже не акцент, а шум.

### Предсказание (главное, до кода)

**Спросить:** Есть люди, которых от движения на экране буквально **укачивает** — кружится голова, тошнит. Как сделать так, чтобы им тоже было хорошо, и при этом не лишать всех остальных пульса?
**Ждём:** обычно молчание или «кнопка выключить».

**Сказать:**

> Кнопка — полумера: её надо найти и нажать. У операционных систем уже есть настройка «**уменьшить движение**». И CSS умеет её **услышать**. Сегодня научимся уважать эту настройку — это профессиональный стандарт, а не «фича для вежливых».

## 3. Показываю · Блок 1: transition vs @keyframes · 7 мин

> Стенд открыт, Live Server включён. Каждая правка — сначала предсказание класса, потом Enter.

**Сказать:**

> В Спринте 1 вы уже оживляли карточки — помните A05? Навели курсор — карточка поднялась. Это был `transition`. Вспомним, что он умеет, и найдём его потолок:

```css
.card {
  transition: transform 0.2s ease, box-shadow 0.2s ease;
}
.card:hover,
.card:focus-visible {
  transform: translateY(-4px);
  box-shadow: 0 12px 24px rgba(0, 0, 0, 0.35);
}
```

> `transition` — это переход **между двумя состояниями**: был обычный, стал наведенный. Три вопроса: какое свойство, как долго, с каким ускорением. Всё. Он не умеет: двигаться **сам по себе**, без наведения; повторяться по кругу; менять свойство несколько раз за один проход.

> А пульс бейджа — это именно «сам по себе и по кругу». Для такого есть **`@keyframes`** — сценарий движения по шагам:

| | transition | @keyframes |
| --- | --- | --- |
| Кто запускает | событие (hover, focus) | сам, по команде `animation` |
| Сколько состояний | два: было → стало | сколько угодно: 0% → 70% → 100% |
| Повтор | один раз на событие | можно зациклить (`infinite`) |
| Пример у нас | карточка подпрыгивает | бейдж пульсирует |

**Аналогия:**

> `transition` — лифт: нажал этаж, доехал, стоп. `@keyframes` — стиральная машина: программа по шагам, крутится, пока не выключишь.

## 4. Блок 2: Пишем пульс · 8 мин

**Сказать:**

> Сценарий пульса: круг света расходится от бейджа и растворяется — как круги на воде от брошенного камня. Три ключевые точки:

```css
@keyframes pulse {
  0%   { box-shadow: 0 0 0 0 rgba(124, 92, 255, 0.6); }  /* точка у бейджа */
  70%  { box-shadow: 0 0 0 12px rgba(124, 92, 255, 0); } /* круг разошёлся, растворился */
  100% { box-shadow: 0 0 0 0 rgba(124, 92, 255, 0); }    /* пауза перед следующим */
}

.live-badge {
  animation: pulse 2s infinite;
}
```

> Читаем по строкам:

- `@keyframes pulse` — название сценария. `pulse` — имя, которым его позовут.
- `0%`, `70%`, `100%` — моменты времени внутри одного прохода. Не секунды, а **проценты** цикла.
- `rgba(124, 92, 255, 0.6)` — наш акцент с прозрачностью: 0.6 — полукруг света, 0 — растворился.
- `animation: pulse 2s infinite` — «играй сценарий pulse, один проход 2 секунды, повторяй бесконечно».

**Кадр:** включаю на стенде — бейдж задышал. Зал смотрит три секунды молча. Потом выключаю — «мёртвый склад». Включаю — «живой эфир».

**Спросить:** Что будет при `animation: pulse 0.3s infinite`?
**Ждём:** предположения → показать: истеричное мигание, как стробоскоп. Вывод: **2–3 секунды — спокойное дыхание**; меньше секунды — раздражение.

**Сказать:**

> Ещё два варианта пульса, если box-shadow надоест: `transform: scale(1.05)` — бейдж слегка «дышит» размером; `filter: brightness(1.2)` — вспыхивает светлее (так сделано в эталоне спринта). Свойства выбираем дешёвые для браузера: `transform`, `opacity`, `filter` — их он анимирует легко. `width`, `top`, `margin` — тяжело, страница начинает тормозить. Помните A05: не `transition: all`, а точечный список.

## 5. Блок 3: prefers-reduced-motion — уважение · 6 мин

**Сказать:**

> Обещанная защита. У Windows, macOS, iOS и Android есть настройка «уменьшить движение» — её включают люди с вестибулярными нарушениями: их от параллакса и пульсации реально укачивает. CSS слышит её через медиазапрос:

```css
@media (prefers-reduced-motion: reduce) {
  .live-badge { animation: none; }
}
```

> Читаем вслух: «если пользователь попросил систему уменьшить движение — **не анимируй**». Бейдж остаётся видимым, просто стоит спокойно. Контент не потерялся — потерялся только спецэффект.

**Инженерная минутка — почему это стандарт, а не доброта:**

> Большие сайты и приложения обязаны это учитывать: есть государственные стандарты доступности (WCAG), и «анимация без выключателя» — прямой путь их нарушить. Плюс практичный аргумент: укачанный пользователь закроет сайт быстрее, чем восхитится им. Забота о доступности — это забота о **всех**: лифт с поручнем нужен не только бабушкам.

**Спросить:** Что делать с hover-transition из A05 внутри этого медиазапроса?
**Ждём:** предположения. Правильно: тоже успокоить — `transition: none`. В эталоне спринта так и сделано:

```css
@media (prefers-reduced-motion: reduce) {
  .live-badge, .btn, .card { animation: none; transition: none; }
}
```

**Кадр:** включаю «уменьшить движение» в настройках системы (или показываю, как это сделать в DevTools: Rendering → Emulate CSS media feature) — пульс замирает. Выключаю — дышит снова. Класс видит: защита **настоящая**, а не для галочки.

## 6. Блок 4: Чек-лист «вау без укачивания» · 3 мин

**Сказать:**

> Собираем правила дня в один чек-лист — он же ваш пропуск на showcase:

1. **Одна анимация на экран.** Пульс бейджа — да. Ещё и переливающийся фон — нет.
2. **Спокойный темп:** 2–3 секунды на цикл. Быстрее — стробоскоп.
3. **Дешёвые свойства:** `transform`, `opacity`, `filter`, `box-shadow`. Не `width`/`top`/`margin`.
4. **Точечный transition:** перечисляем свойства, не `all`.
5. **Защита:** `prefers-reduced-motion` отключает всё движение.
6. **Смысл:** анимация что-то **сообщает** («мы в эфире», «карточка кликабельна»), а не просто мельтешит.

**Спросить:** Какой пункт нарушает «мигающий неоновый заголовок»?
**Ждём:** почти все, особенно 6 — смысла нет.

## 7. Делаем вместе · 20 мин

> Класс диктует — я печатаю на стенде. Порядок строго такой, каждый шаг сначала предсказываем.

1. **Бейдж:** в HTML хита недели — `span.live-badge` с текстом «В ЭФИРЕ». Вспоминаем A09: он absolute в углу обложки.
2. **Сценарий:** пишем `@keyframes pulse` — класс выбирает цвет круга (акцент или искра `#FFC857`) и радиус расхождения (8px? 12px?).
3. **Запуск:** `animation: pulse 2s infinite`. Класс голосует за скорость: 1s / 2s / 4s — пробуем все три, выбираем «дыхание».
4. **Защита:** медиазапрос reduced-motion. Включаем эмуляцию в DevTools — пульс замирает. Зал видит, что защита работает.
5. **Ревизия A05:** проверяем, что hover карточек на месте, `transition` точечный, `:focus-visible` показывает кольцо при Tab.

**Реплики-якоря по ходу:**

- «Одна анимация на экран.»
- «transition — лифт, keyframes — стиральная машина.»
- «Движение сообщает, а не мельтешит.»
- «Защита reduced-motion — не опция, а стандарт.»

**Checkpoint-вопрос перед переменой (порог 7/10):**

1. Чем `transition` отличается от `@keyframes`? — **Transition — два состояния по событию; keyframes — сценарий по шагам, сам и зацикленно.**
2. Что делает `prefers-reduced-motion: reduce`? — **Пользователь попросил систему убрать движение — мы отключаем анимации, контент остаётся.**

Если меньше 7 верно — ещё один круг: на стенде «лифт vs стиральная машина» — класс распределяет примеры (hover карточки, пульс, мигание загрузки, подъём кнопки) по двум колонкам.

### Минимум для отстающих

### Челлендж для быстрых

- Вторая защита: `animation-play-state: paused` на `:hover` бейджа — пульс замирает, когда на него навели.
- Мягкое появление карточек при загрузке: `@keyframes fadeIn` (opacity 0→1, 0.4s) — **с той же защитой** reduced-motion. Помнить правило: одна анимация на экран — fadeIn одноразовый, ряби не создаёт.
- Эквалайзер из трёх полосок (`div.eq-bar`) рядом с играющим треком: `scaleY` по keyframes с разной задержкой `animation-delay`.

## FAQ — вопросы, которые могут задать

- **Можно две анимации, если они спокойные?** На showcase — одна зацикленная. Одноразовые (fadeIn при загрузке, hover-подъём) не считаются рябью: они произошли и закончились.
- **Чем `animation` отличается от `transition` ещё раз?** Transition ждёт события и идёт один раз между двумя состояниями. Animation играет сценарий сама, по шагам, можно зациклить.
- **Почему проценты, а не секунды в keyframes?** Проценты — внутри одного цикла любой длины. Сценарий один, скорость меняется в `animation: … 2s`.
- **Как проверить reduced-motion, если в системе не включено?** DevTools → Ctrl+Shift+P → «Rendering» → Emulate CSS media feature prefers-reduced-motion.
- **Что такое `animation-delay`?** Пауза перед стартом. Нужна для «волны»: три полоски эквалайзера стартуют в 0s, 0.2s, 0.4s.
- **Будет ли анимация в JavaScript-играх Спринта 3?** Да, но другая: там движение считает код (игровой цикл). CSS-анимация — для интерфейса, JS — для игры.

## Шпаргалка · термины одной фразой

| Термин | Одной фразой |
| --- | --- |
| `transition` | лифт: два состояния по событию, один раз |
| `@keyframes` | сценарий движения по шагам (0% → 70% → 100%) |
| `animation` | «играй сценарий»: имя, длительность, повторы |
| `infinite` | крути, пока не выключат |
| дешёвые свойства | `transform`, `opacity`, `filter`, `box-shadow` |
| `prefers-reduced-motion` | пользователь попросил не качать — отключаем движение |
| одна анимация на экран | движение — акцент, а не фон |
| пульс | круг света расходится и растворяется — «мы в эфире» |
