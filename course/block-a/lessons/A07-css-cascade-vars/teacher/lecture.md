
## 3. Показываю · Блок 1: Каскад — очередь за властью · 7 мин

> Стенд открыт, Live Server включён. Каждая правка — сначала предсказание класса, потом Enter.

**Сказать:**

> Слово «каскад» вы слышали: вода падает со ступеньки на ступеньку. В CSS правила тоже «падают» на элемент сверху вниз, и на каждой ступеньке выясняется, кто главнее. Ступенек три — сверху вниз:

1. **Откуда правило?** Браузерные стили по умолчанию — самые слабые. Ваши стили сильнее. Мы сегодня живём только в своих.
2. **Насколько правило точное?** Об этом — следующий блок, специфичность.
3. **Кто написал позже?** При равных условиях побеждает **последний**. Как в Python:

```python
color = "purple"
color = "pink"   # последнее присваивание побеждает
print(color)     # pink
```

> В CSS то же: два одинаковых по силе правила — выиграло нижнее. Никакой магии, просто очередь.

**Кадр на стенде:** показываю два правила `.card { background: … }` — класс предсказал верно, карточка фиолетовая. Меняю порядок строк местами — карточка тёмная. Порядок решает.

**Спросить:** Значит, если правило ниже — оно всегда победит?
**Ждём:** «да» — **ловушка**. Ответ: нет, сначала смотрим силу (специфичность), и только при равной силе — порядок.

## 4. Блок 2: Специфичность — чей голос громче · 7 мин

**Сказать:**

> Ступенька выше порядка — **специфичность**: насколько точно правило прицелилось в элемент. Три уровня, от слабого к сильному:

| Селектор | Ранг | Сила | Кого описывает |
| --- | --- | --- | --- |
| `button` | 0-0-1 | слабая | **все** кнопки вообще |
| `.btn-primary` | 0-1-0 | средняя | группу «главные кнопки» |
| `#play-btn` | 1-0-0 | сильная | один уникальный элемент |
| `style="…"` прямо в HTML | — | почти непобедимая | **не используем** — это Спринт 1, «ад одного файла» |

> Аналогия из школьного чата: сообщение «всем сделать дз» — слабое, оно обо всех. «Футболистам — форма на завтра» — точнее. «Иванов, ты дежурный» — самое точное, и если Иванов получит два непротиворечащих указания, он выполнит адресное. Ранг читается как счёт: сначала сравниваем id, потом классы, потом теги.

```css
button { color: #9AA3B8; }        /* все кнопки — приглушённые */
.btn-primary { color: #7C5CFF; }  /* главная кнопка — акцент. Победит для неё */
#play-btn { color: #2EE6A6; }     /* одна конкретная — зелёная. Победит для play */
```

**Спросить:** Кнопка `<button class="btn-primary" id="play-btn">`. Какого она цвета?
**Ждём:** зелёная — id сильнее класса, класс сильнее тега.

**Ловушка №2 (составной селектор):** показываю на стенде:

```css
.title { color: #FF6B6B; }        /* ранг 0-1-0 */
.card .title { color: #F4F1EA; }  /* ранг 0-2-0 — два класса! */
```

**Спросить:** Заголовок внутри `.card` — красный или светлый?
**Ждём:** спор. Правильный ответ — **светлый**: два класса в селекторе дают ранг выше, чем один. Не «ниже по файлу», а «точнее прицел».

**Сказать:**

> Теперь главный запрет дня. Есть способ перекричать всех сразу — `!important`:

```css
.card { background: #FF6B6B !important; }  /* ТАК НЕ ДЕЛАЕМ */
```

> Это не «сила», это крик. Правило с `!important` ломает очередь: его уже нельзя нормально перебить, и через месяц вы обвешаете весь файл восклицательными знаками, как новогоднюю ёлку. Правило курса: **`!important` — не начинать им день**. Если что-то не перебивается — значит, проблема в структуре селекторов, а не в громкости. В Python аналогия: `global` на каждый чих — работает, но код становится нечитаемым.

**Инженерная минутка — почему это важно в проде:**

> В больших проектах CSS пишут десятки людей. Если каждый кричит `!important`, файл превращается в базар: никто не понимает, что победит. Специфичность — это договорённость команды: правила читаются предсказуемо, как код с понятными именами. Discord, Spotify, GitHub — все живут на классах и почти не используют id в стилях. Мы делаем так же: **класс — рабочая лошадка, id — для JavaScript и якорей ссылок**.

## 5. Блок 3: Переменные `:root` — тема в одном месте · 8 мин

**Сказать:**

> Вернёмся к заказчику и двадцати кнопкам. Вот обещанное волшебство — переменные CSS. Смотри на стенд:

```css
:root {
  --bg: #0B0F1A;       /* фон-холст */
  --bg-elev: #141A2A;  /* «приподнятая» поверхность — карточки, плеер */
  --text: #F4F1EA;     /* основной текст */
  --muted: #9AA3B8;    /* приглушённый */
  --accent: #7C5CFF;   /* акцент — кнопки, ссылки */
}

body {
  background: var(--bg);
  color: var(--text);
}

.btn { background: var(--accent); }
a    { color: var(--accent); }
```

> Разбираем синтаксис по косточкам:

- `:root` — это «корень страницы», правило для самого главного элемента. Переменные, объявленные там, видны **всем** остальным правилам.
- Имя переменной начинается с **двух дефисов**: `--accent`. Дефисы обязательны, иначе CSS не поймёт, что это переменная, а не свойство.
- Достают переменную через `var(--accent)`. `var` — «возьми значение».

**Кадр:** на стенде меняю одну строку `--accent: #7C5CFF` на `--accent: #FF6B6B` — и **весь сайт** перекрашивается: кнопки, ссылки, обводки. Одна строка. Двадцать кнопок. Заказчик доволен.

**Спросить:** На что это похоже в Python?
**Ждём:** переменная / константа; `ACCENT = ...` и везде `ACCENT`.

**Сказать:**

> Один в один. Вы уже писали так в Python, просто не подозревали, что в CSS то же самое называется `:root`. А в играх это файл настроек скина: поменял одну строку конфига — весь персонаж в другой броне.

> Правило дня, которое переходит во все следующие уроки: **цвет в MusicHub пишется ровно один раз — в `:root`.** Дальше по файлу — только `var(…)`. Увижу `#7C5CFF` в правиле кнопки — вернём и перепишем.

**Ловушка (показать специально):** печатаю `var(--acent)` — опечатка, один `c` потеряли. Браузер **не ругается красным текстом**, он просто молча игнорирует: элемент получает значение по умолчанию.

**Сказать:**

> Вот коварство CSS: синтаксическая ошибка не падает с треском, как в Python. Она тихо делает «как получится». Поэтому переменные проверяем глазами и через DevTools — там видно, подставилось значение или нет.

## 6. Блок 4: Наследование — стили текут вниз · 4 мин

**Сказать:**

> Ещё один механизм, который вы уже использовали, не замечая. Почему в Pulse FM вы ставили `font-family` один раз на `body` — а шрифт менялся у всех абзацев и заголовков?

> Это **наследование**: часть свойств течёт от родителя к детям. Цвет текста и шрифт — наследуются. Фон и рамка — **нет**.

```css
body { color: var(--text); }  /* текст детей тоже светлый */
body { background: var(--bg); } /* а фон у детей НЕ появится */
```

**Спросить:** Поставил `background` на `body`. Появится ли фон у карточки внутри?
**Ждём:** нет — фон не наследуется; карточка прозрачная, сквозь неё видно фон body.

**Сказать:**

> Тонкость, которая спасает от паники: карточка «без фона» на самом деле прозрачная — вы просто видите фон родителя. Поэтому `.card` мы красим отдельно, в `--bg-elev`. Запомните пару: **текст течёт вниз, фон — нет**.

## FAQ — вопросы, которые могут задать

- **А можно переменную поменять для одной карточки?** Да: объявить `--accent` заново внутри `.card` — и дети этой карточки увидят новое значение. Это мощный приём, но сегодня не нужен.
- **Почему `:root`, а не `body`?** `:root` — самый верх дерева, переменные видны отовсюду. На практике для переменных разницы почти нет, но `:root` — принятая договорённость.
- **Пересчитывает ли браузер страницу при смене переменной?** Да, все `var()` зависят от неё — кадр пересоберётся. Поэтому тема меняется мгновенно, без перезагрузки.
- **Что если у переменной нет значения?** `var(--нет-такой)` без запасного варианта → свойство считается незаданным (наследование или initial). Есть страховка: `var(--accent, #7c5cff)` — второй аргумент — запасное значение.
- **Зачем знать порядок каскада, если есть переменные?** Переменные решают «где хранить», каскад — «кто победит». Это две разные проблемы.

## Шпаргалка · термины одной фразой

| Термин | Одной фразой |
| --- | --- |
| каскад | очередь правил: сила → точность → порядок |
| специфичность | тег < класс < id: кто точнее прицелился |
| `!important` | крик вместо очереди; не начинать им день |
| `:root` | корень страницы, дом переменных |
| `--переменная` | именованное значение, пишется с двумя дефисами |
| `var(--x)` | «возьми значение переменной» |
| наследование | цвет и шрифт текут вниз, фон и рамка — нет |
| тема | все цвета в одном месте, акцент меняется одной строкой |
