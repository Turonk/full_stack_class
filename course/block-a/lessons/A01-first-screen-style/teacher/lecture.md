## Блок 1 · Сайт — не картинка · 4 мин

**Сказать:**

> Сцена: кто-то думает, что сайт — одна большая картинка из Photoshop. Иногда так и делают лендинги-обманки. Но нормальный интерфейс — это **текст плюс правила**, как этот текст рисовать.

> HTML — список предметов на сцене: «тут заголовок», «тут кнопка», «тут абзац».  
> CSS — костюмы и свет: цвет, размер, отступы.  
> Браузер — движок. Он читает оба файла и рисует кадр. Похоже на игру: есть модели персонажей и есть скин.

**Спросить:** Если убрать все правила стиля, что останется на экране?  
**Ждём:** голый текст / белый фон / «некрасиво, но смысл читается».

**Сказать:**

> Именно. Смысл живёт в HTML. Красота — в CSS. Если смешать всё в кучу атрибутов `style=""` на каждом теге, через месяц никто не найдёт, где поменять цвет кнопки. В Python вы уже встречали ад одного файла на 500 строк. Здесь тот же закон: **разделяй ответственность**.

## Блок 2 · Два файла с первой минуты · 4 мин

**Сказать:**

> Сцена: в папке лежат `index.html` и `styles.css`. На экране всё ещё белый лист. Класс шепчет: «файл же есть!»

> Правило курса с дня один: минимум два файла — и **явная стрелка** между ними.

```
pulse-fm/
  index.html
  styles.css
```

> `index.html` — сцена. `styles.css` — свет. Браузер второй файл **не угадает**. Стрелка — тег `link` в `head`:

```html
<link rel="stylesheet" href="styles.css">
```

> `rel="stylesheet"` — «это таблица стилей».  
> `href="styles.css"` — «лежит рядом, вот имя».  
> Переименуешь файл и забудешь `href` — стили «исчезли», хотя файл на диске цел. Для браузера неподключённый файл = не существует.

**Спросить:** Это на что похоже в Python?  
**Ждём:** забытый `import` / модуль лежит, но не подключён.

**Сказать:**

> Да. `import` не сработал — имени в программе нет. `link` не написали — CSS для страницы нет. Файл можно хоть на рабочий стол положить — без связи он мёртвый груз. Кадр: добавили `link` — экран потемнел. Убрали — снова белый лист.

## Блок 3 · Как браузер рисует кадр · 4 мин

**Сказать:** (можно пальцем по схеме на слайде)

> Браузер просит файлы → разбирает HTML в дерево тегов → накладывает правила CSS → красит пиксели. Это не один раз «нарисовал и забыл». Почти как игровой цикл: что-то изменилось — кадр пересобрали.

> Поэтому Live Server удобен: сохранил файл — страница моргнула. Вы сразу видите следствие, не гадаете.

**Спросить:** Стили лежат в `styles.css`, в HTML **нет** `link`. Экран тёмный или белый?  
**Ждём:** спор 20 секунд → **белый / дефолт браузера**.

**Сказать:**

> Ловушка поймана. «Файл же есть на диске!» — не аргумент. Браузер читает только то, на что есть стрелка. Это наш checkpoint сегодня: предскажи → удали link → проверь → верни. Баннер есть в HTML, кнопки «Слушать» в коде — а без связи браузер рисует пустой эфир.

## Блок 4 · Каркас HTML без страха · 4 мин

**Сказать:**

> Сцена: нужен эфир. Не двадцать тегов — маленький набор.

> `h1` — главный смысл экрана. Один на страницу по возможности.  
> `p` — поддержка, слоган.  
> `button` или ссылка-кнопка — действие «Слушать».  
> Всё это живёт внутри `body`. В `head` — служебное: title вкладки и наш `link`.

> Тег — это скобки смысла: открыли, положили текст, закрыли. Браузер не понимает «нарисуй красиво». Он понимает «это заголовок».

**Спросить:** Почему заголовок не делают просто крупным абзацем?  
**Ждём:** смысл / доступность / структура; если слабо — подскажи: «для людей и для программ, которые читают страницу».

**Сказать:**

> Кадр: появился `h1` — глаз знает, куда сесть. Появилась кнопка — экран зовёт жать «Слушать».

## Блок 5 · CSS: одно правило — одно изменение · 3 мин

**Сказать:**

> В CSS мы говорим: «для таких-то элементов — такие-то свойства».

```css
body {
  background: #0b0f1a;
  color: #f4f1ea;
}
```

> Тёмный холст — не потому что «круто», а потому что обложки и неон на светлом фоне орют. Discord и плееры живут в той же логике.

> Цвет кнопки лучше один раз описать в CSS, а не копировать на три кнопки руками. Завтра смените акцент — правите одно место. Кадр: одно правило — весь баннер другой.
